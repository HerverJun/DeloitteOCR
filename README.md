## 运行便携包

解压完整包，双击 `启动工作台.cmd`，创建项目并导入照片。选择识别方式，完成后校对文字或表格，再点击「导出结果」。包内自带 CPython、四个独立运行环境、模型、CUDA 用户态 DLL、MSVC 运行库和浏览器静态资源。目标机只需要 Windows、Edge/Chrome 和兼容的 NVIDIA 驱动；不需要安装 Python、Node.js、CUDA Toolkit 或开发工具。

现有程序的项目默认值为 `%LOCALAPPDATA%\OfflineOCR\Workspace`，与应用目录分离；本机使用前必须按[存储规范](docs/项目文件存储规范.md)将应用数据、缓存和临时目录配置到 F 盘，并使用 `--data "F:\OCR\output\local-run\workspace"` 显式指定项目目录。仅指定 `--data` 不会改变校验记录、GPU 锁和凭据的默认位置。关闭浏览器不结束后台；从系统托盘重新打开或退出。异常退出后，未完成任务等待手动「继续」，已完成项不会重复。操作说明见[使用手册](docs/DeloitteOCR使用手册.md)。

首次启动、升级或迁移安装目录后，会完整校验离线文件、GPU 与原生依赖。启动窗口会提示“所需时间较长，请耐心等待”，并持续显示当前阶段和文件进度；通过后自动继续启动。日常启动复用成功记录，只核对版本清单、必要入口和磁盘空间，不再扫描模型或逐个启动引擎探针。GPU 与模型在实际识别时加载，加载失败会显示在任务中，可修复后重试。

如需重新排查离线文件，退出托盘中的工作台后双击 `完整校验并启动.cmd`；也可运行 `launcher\OfflineOCRLauncher.exe --verify-startup`。`ocr.cmd verify` 始终执行完整文件校验。成功记录保存在 `%LOCALAPPDATA%\OfflineOCR\Verification`，与项目目录分离，切换项目可以复用；没有定期重扫，记录丢失、损坏或校验规则更新时会重新检查。日常启动不检测清单未改变时的所有文件内容变化，需要时使用上述完整校验入口。

批次固定所选模型、引擎包版本和处理参数；默认逐图片导出，勾选「汇总为一个工作簿」才合并 Excel。可在「引擎管理」导入完整离线包、查看暂存、启用或回退；这些操作仍完整校验引擎包并进行实际识别自检。在「项目占用与清理」按完整项目名称确认删除。使用启动器参数 `--review-only` 可只校对、导出与普通图像处理；基础应用校验可以复用完整校验记录，仅校对校验记录不能用于启用识别。

也可以在包目录打开终端：

```powershell
.\ocr.cmd doctor
.\ocr.cmd verify
.\ocr.cmd recognize --engine all --image "F:\OCR\output\inputs\测试图片.png" --output "F:\OCR\output\recognition\本次运行"
```

引擎参数为 `ppocr`、`paddlevl`、`glm`、`hunyuan` 或 `all`。`all` 顺序启动独立进程，每个引擎结束即释放进程资源。输出目录必须为空，防止旧结果被误当作本次成功证据。

输出包括原始模型 JSON、统一 JSON、TXT、Markdown、对应坐标的 `input.png` 和可用时的 XLSX。原图不会被修改。模型缺失的置信度或坐标为 `null`。PP-OCRv6 不具备表格结构识别能力，表格照片仍返回文字块，不能据此冒充 Excel 结构还原。
