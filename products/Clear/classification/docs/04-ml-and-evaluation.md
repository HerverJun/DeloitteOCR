# 算法与验证方案

## 默认学习流程

读取锁定清单，应用确定性预处理，提取冻结编码器特征，仅训练带 L2 正则的多类线性层。首版以 PyTorch 训练线性头，减少 scikit-learn 到 PyTorch 权重转换这一步。评估、导出与正式推理均使用同一预处理契约。

冻结模型不仅意味着关闭梯度，还需要 encoder.eval()；ResNet 的 BatchNorm 不得更新统计量。编码器和分类头的训练状态分别设置。首次优先采用 DINOv2 最后一层 CLS 特征与 ResNet18 全局平均池化特征，显式执行 L2 归一化，epsilon=1e-12。特征提取方式和归一化都写入元数据，并在 ONNX 图中保留。

## 最小实验矩阵

| 编号 | 编码器候选 | 输入 | 训练方式 | 决定的问题 |
| --- | --- | --- | --- | --- |
| B0 | timm ResNet18 预训练权重 | 224×224 | 冻结与线性头 | 建立速度与效果基线 |
| B1 | DINOv2 ViT-S/14 无 registers | 224×224 | 冻结与线性头 | 通用视觉特征是否改善业务分类 |
| B2 | 同一 DINOv2 权重 | 336×336 | 冻结与线性头 | 细节保留的收益是否值得额外耗时 |

候选 timm 名称为 `resnet18.a1_in1k` 和 `vit_small_patch14_dinov2.lvd142m`。当前机器的 timm 1.0.22 注册表能识别两者，但**仍需在最终锁定版本加载权重并测试**。注册表中的 DINOv2 默认输入为 518×518，本项目的 224/336 是拟定实验尺寸，需显式设置 img_size 并验证位置编码调整与导出，不能只修改外部 resize。DINOv2 使用模型支持的输入尺寸与位置编码处理，不把原仓库输入裁剪行为未经验证地等同于 timm 行为。

先固定种子 42、简单分类头与少量正则参数，在 train/val 上选择一次。不得把多个随机种子中最好的测试集结果作为报告值。组数足够时补充三次预先声明的训练种子稳定性检查；它们不是三个独立测试集。

## 数据与人工预算

文档试点沿用原报告的示例预算：发票、收款码截图、合同各 50 张，其他 100 张，共 250 张；最多三轮纠错，每轮 40 张，总人工确认量约 370 张。这是工作量估计，不保证达到任何精度。

首轮默认按分组后的近似 60/20/20 划分 train/val/test，即 150/50/50 左右；分组完整性优先于精确比例。每个目标类约 10 张测试样本，只适合发现明显问题，不能证明 1% 等低错误率。原报告将约 20% 预算留作独立测试；本方案进一步从剩余数据中留出验证集，用于模型选择和阈值设置。

类别、模板、来源、同一文档不同截图、连拍、近重复应在划分前定义组。若一类只有一个独立来源组，不强行分散到三个集合；收集更多组或将本轮标为探索性。组数很少时，可以在非测试部分采用 GroupKFold 辅助观察稳定性，但不能据此虚构独立验证样本。

测试集锁定，调参、主动学习与阈值优化只使用 train/val 和 pool。每轮纠错不读取测试错误来挑选训练样本；三轮迭代结束后做一次正式测试。若因分析测试错误而修改方案，需要新建保留集，并将旧测试归入开发数据。

## 预处理契约

1. 根据文件内容解码，限制最大解码像素；应用 EXIF orientation。
2. 统一转 RGB。透明图先按白色背景合成；灰度扩展三通道，CMYK 的转换实现及 Pillow 版本记入环境。
3. 文档配置保持完整画面与宽高比，按目标长边缩放，居中白色补边。尺寸计算使用 `floor(value + 0.5)`，至少 1 像素；奇数补边时右侧或下侧多 1 像素。
4. 插值固定 bicubic；记录具体实现和版本。像素转 float32、除以 255，按指定 mean/std 归一化，转换 NCHW。
5. train/val/test/ONNX 封装使用相同确定性路径。首版特征缓存不启用随机裁剪、翻转或随机颜色增强。

自然图像项目可先使用同一完整图像补边配置，再与权重推荐裁剪方式单独比较；“通用”不等于文档增强适合所有场景。长图经过整图缩放丢失关键内容时，先标记该失败类型，再比较切块或 OCR。不要只提高模型容量。

## 特征缓存

缓存键包括原始图片内容哈希、权重 SHA256、模型适配器版本、输入大小、预处理契约哈希、特征提取方式、特征归一化和 dtype。特征数组可使用 NPY memmap 分片，索引记录 item_id、内容哈希、偏移和完成状态；临时分片校验后原子重命名，恢复时重算未提交分片。

标签和分类头不进入编码器特征键；改标签可复用相同特征，但产生新训练和评估版本。只有归一化、精度与全部编码器配置相同时可复用。生产 ONNX 默认不输出特征；批量任务额外写特征缓存是可选功能，需另测 IO 与存储开销。

15 万张、384 维 float32 的纯数组为 230400000 字节，约 230.4 MB 或 219.7 MiB；不含索引、缩略图和原图。原图大小必须抽样估算，不能用这个数作为平台全部存储需求。

## 评分与接受策略

softmax 分数不是天然校准的正确率。第一阶段在验证集上形成阈值与覆盖率曲线，按业务误报、漏报和人工成本选择每类阈值；样本不足时明确标为探索阈值。可选温度校准同样只使用验证数据，并记录参数与来源版本。

其他类保留明确负例；未知类别检测不属于本方案保证。每类阈值判断只对预测类进行，接受率等于 accepted/成功推理数。另报端到端处理覆盖率=成功推理数/输入项数，避免把坏图排除后掩盖任务质量。

人工复核每轮示例为 20 张低分或边界样本、10 张特征空间新颖样本、10 张按来源分层随机样本。先排除重复组，保存抽样策略、随机种子与入选概率（能够计算时）。主动选出的难例不用于估计总体错误率；总体抽查需独立设计，并在非均匀抽样时使用正确权重。

## 必报指标

| 指标 | 定义或用途 |
| --- | --- |
| 类别 precision recall F1 | 同时列出 TP FP FN 与分母，零分母记 null 并说明 |
| Macro F1 balanced accuracy | 不让大类掩盖少数类表现 |
| 混淆矩阵 | 真实类为行、预测类为列，固定标签顺序 |
| 接受后每类 precision | 仅统计已接受的对应预测，揭示实际输出质量 |
| 自动处理 recall | 已接受且正确的目标类数 / 该真实类总数 |
| coverage review_rate | 接受与待复核占成功推理数比例 |
| 处理失败率 | failed 输入项数 / 全部输入项数 |
| 每类样本与独立组数 | 说明小样本与相关性限制 |
| 吞吐与资源 | 全链路图/秒、总耗时、峰值 RAM/显存、设备和磁盘条件 |
| 人工成本 | 每轮确认数、分钟数、修正数与收益 |

二分类 FPR=FP/(FP+TN)，不能与 1−precision 混用。1% 业务占比、95% recall、1% FPR 的假设下，10 万张会得到 950 真阳性与 990 假阳性，precision 约 49%。这说明验收应使用真实来源和类别占比。

置信区间在近似独立样本时可给出 Wilson 区间；有来源相关性时按组 bootstrap 或明确区间仅供描述。10 张测试图中零错误不能支持“99% 精度”。例如独立试验零错误的 95% 误差上界粗略为 3/n；证明低错误率需要更多独立样本。

## ONNX 一致性验收

先 FP32，H/W 固定、batch 动态。保存导出器、opset、PyTorch、ONNX 和 ORT 版本；opset 在 P0 实测选择，不凭经验写成已通过。

固定图像集覆盖 RGB、灰度、透明 PNG、EXIF 旋转、极宽极高、中文路径、重复图及末批。比较共用预处理后的 PyTorch 与 ORT logits，并测 batch 1、16、32 和非整除末批。第一轮诊断门槛可设 `atol=1e-4, rtol=1e-3`；该值是拟定起点，需根据数值分布说明最终容差。

发布要求：输出形状正确、有限数、类别一致、接受状态一致、预处理指纹一致。阈值附近差异必须逐条检查，不能仅以平均误差小判定通过。相同图片在不同 batch 与顺序下结果一致；FP16 或 TensorRT 是新的发布验证，不能继承 FP32 结论。

## 批量验收

先做 100 张功能集，再做至少 1000 张代表性吞吐测试，最终做 15 万输入项完整性与恢复测试。合成图片可用于故障和规模验证，业务质量必须用真实样本。

在提交结果前、提交后、写导出时分别终止工作进程；恢复后输入项都有明确终态，无多余或缺失结果。覆盖坏图、缺失文件、重名文件、相同内容不同路径、源文件被修改、GPU OOM、磁盘空间不足、取消、暂停和重试。

15 万张一小时需要 41.7 图/秒，20 分钟需要 125 图/秒，只是目标换算。分开报告扫描哈希、解码、GPU、结果写入与可选复制耗时，冷启动和热缓存分开记录，不据开发机结果推断 A4000/A6000 性能。
