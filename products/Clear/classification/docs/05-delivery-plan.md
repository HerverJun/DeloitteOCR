# 开发任务与开工清单

## 实施原则

先证明真实样本可分、导出可用、任务可靠，再建设界面。准备包已经完成设计工作，下面任务是尚待实施的工作项；勾选状态只能依据实际产物和验证结果更新。

## 里程碑

| 阶段 | 工作 | 交付与退出条件 | 估计开发人日 |
| --- | --- | --- | --- |
| P0 技术验证 | 隔离环境、样本规范、3 组基线、ONNX 导出、设备测试 | 锁文件、权重与许可记录、实际评估、可独立运行的推理包 | 3–5 |
| P1 数据与核心 | 领域实体、数据版本、共用预处理、缓存、CLI 训练评估导出 | 一个真实项目在 CLI 完成可复现闭环，契约测试通过 | 5–8 |
| P2 批量任务 | SQLite 账本、进程、租约、恢复、坏图、导出、归档 | 15 万项任务与故障注入验证，无漏项重复生效结果 | 4–7 |
| P3 Web 工作台 | 项目、数据集、实验、模型库、任务和复核页 | 浏览器完成全流程，后台真实任务驱动 | 5–8 |
| P4 交付验证 | 三轮纠错流程、目标机验证、内网访问、备份与说明 | 业务验收记录、安装包或部署说明、恢复演练 | 3–5 |

总计约 20–33 开发人日，假设 1 名熟悉 Python 与 Web 的开发者、数据能及时提供、无需采购设备。标注、等待业务反馈、权重审批与明显算法返工未计入。这是排期估算，需在 P0 后重新评估，不是交付承诺。

## 测试策略

单元测试集中在容易破坏正确性的逻辑：预处理、类别映射、分组划分、阈值、缓存键和状态转换。集成测试验证从样本到 ONNX 的真实输出、数据库事务与恢复。端到端测试覆盖 Web 闭环与大批量数据，不用大量只检查函数存在的测试充数。

CI 的 CPU 快速检查与专用 GPU 验收分开。没有 GPU 的 CI 可以验证接口和结构，不能宣称 GPU 部署通过。训练与推理锁文件分开，最小推理环境必须在不安装 PyTorch 的环境中验证依赖完整性。
