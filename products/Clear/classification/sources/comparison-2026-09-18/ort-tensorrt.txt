viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Caches can help reduce session creation time from minutes to seconds </h3> <p>Following numbers are measured from initializing session with TRT EP for SD UNet model.</p> <ul> <li>No cache (default)  – 384 seconds <ul> <li>The first run (warmup) can be very long because building engine involves exhaustive inside an ONNX model</li> <li>No builder will be instantiated, nor engine will be built</li> <li>Quickly load engine with less processes needed</li> </ul> </li> </ul> <p><img .\</code></li> <li>Will be generated with inputs/outputs identical to original model</li> <li>Run the embed engine model as the original model !</li> </ul> </li> </ul> <p>The folder structure of the         <span class="p">),</span>
    <span class="p">]</span>

    <span class="n">graph</span> <span class="o">=</span> <span class="n">helper</span><span class="p">.</span><span class="n">make_graph</span><span class="p">(</span>
        <span class="n">nodes</span><span class="p">,</span>
        <span class="s">"trt_plugin_custom_op"</span><span class="p">,</span>
        <span class="p">[</span>  <span class="c1"># input
</span>            <span class="n">helper</span><span class="p">.</span><span class="n">make_tensor_value_info</span><span class="p">(</span><span class="s">"input1"</span><span class="p">,</span> <span class="n">TensorProto</span><span class="p">.</span><span class="n">FLOAT</span><span class="p">,</span> <span class="p">[</span><span class="mi">12</span><span class="p">,</span> <span class="mi">256</span><span class="p">,</span> <span class="mi">256</span><span class="p">]),</span>
            <span class="n">helper</span><span class="p">.</span><span class="n">make_tensor_value_info</span><span class="p">(</span><span class="s">"input2"</span><span class="p">,</span> <span class="n">TensorProto</span><span class="p">.</span><span class="n">FLOAT</span><span class="p">,</span> <span class="p">[</span><span class="mi">12</span><span class="p">,</span> <span class="mi">256</span><span class="p">,</span> <span class="mi">256</span><span class="p">]),</span>
            <span class="n">helper</span><span class="p">.</span><span class="n">make_tensor_value_info</span><span class="p">(</span><span class="s">"input3"</span><span class="p">,</span> <span class="n">TensorProto</span><span class="p">.</span><span class="n">FLOAT</span><span class="p">,</span> <span class="p">[</span><span class="mi">12</span><span class="p">,</span> <span class="mi">256</span><span class="p">,</span> <span class="mi">256</span><span class="p">]),</span>
        <span class="p">],</span>
        <span class="p">[</span>  <span class="c1"># output
</span>            <span class="n">helper</span><span class="p">.</span><span class="n">make_tensor_value_info</span><span class="p">(</span><span class="s">"output"</span><span class="p">,</span> <span class="n">TensorProto</span><span class="p">.</span><span class="n">FLOAT</span><span class="p">,</span> <span class="p">[</span><span class="mi">12</span><span class="p">,</span> <span class="mi">256</span><span class="p">,</span> <span class="mi">256</span><span class="p">]),</span>
        <span class="p">],</span>
    <span class="p">)</span>

    <span class="n">model</span> <span class="o">=</span> <span class="n">helper</span><span class="p">.</span><span class="n">make_model</span><span class="p">(</span><span class="n">graph</span><span class="p">)</span>
    <span class="n">onnx</span><span class="p">.</span><span class="n">save</span><span class="p">(</span><span class="n">model</span><span class="p">,</span> <span class="n">model_name</span><span class="p">)</span>
</code></pre></div> </div> </details> <p>Note: If users want to use TRT plugins that are not in the TRT plugin library in official release, please see the ORT TRT provider option <code class="language-plaintext highlighter-rouge">trt_extra_plugin_lib_paths</code> for more details.</p> <h3 id="timing-cache"> <a href="#timing-cache" class="anchor-heading" aria-labelledby="timing-cache"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Timing cache </h3> <p>Enabling <code class="language-plaintext highlighter-rouge">trt_timing_cache_enable</code> will enable ORT TRT to use TensorRT timing cache to accelerate engine build time on a device with the same compute capability. This will work across models as it simply stores kernel latencies for specific configurations and cubins (TRT 9.0+). Those files are usually very small (only a few KB or MB) which makes them very easy to ship with an application to accelerate the build time on the user end.</p> <p><em>Note:</em> A timing cache can be used across one <a href="https://developer.nvidia.com/cuda-gpus">GPU compute capability</a> similar to an engine. Nonetheless the preferred way is to use one per GPU model, but practice shows that sharing across one compute capability works well in most cases.</p> <p>The following examples shows build time reduction with timing cache:</p> <div class="table-wrapper"><table> <thead> <tr> <th>Model</th> <th>no Cache</th> <th>with Cache</th> </tr> </thead> <tbody> <tr> <td>efficientnet-lite4-11</td> <td>34.6 s</td> <td>7.7 s</td> </tr> <tr> <td>yolov4</td> <td>108.62 s</td> <td>9.4 s</td> </tr> </tbody> </table></div> <p>Click below for Python example:</p> <details> <div class="language-python highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="kn">import</span> <span class="nn">onnxruntime</span> <span class="k">as</span> <span class="n">ort</span>

<span class="n">ort</span><span class="p">.</span><span class="n">set_default_logger_severity</span><span class="p">(</span><span class="mi">0</span><span class="p">)</span> <span class="c1"># Turn on verbose mode for ORT TRT
</span><span class="n">sess_options</span> <span class="o">=</span> <span class="n">ort</span><span class="p">.</span><span class="n">SessionOptions</span><span class="p">()</span>

<span class="n">trt_ep_options</span> <span class="o">=</span> <span class="p">{</span>
    <span class="s">"trt_timing_cache_enable"</span><span class="p">:</span> <span class="bp">True</span><span class="p">,</span>
<span class="p">}</span>

<span class="n">sess</span> <span class="o">=</span> <span class="n">ort</span><span class="p">.</span><span class="n">InferenceSession</span><span class="p">(</span>
    <span class="s">"my_model.onnx"</span><span class="p">,</span>
    <span class="n">providers</span><span class="o">=</span><span class="p">[</span>
        <span class="p">(</span><span class="s">"TensorrtExecutionProvider"</span><span class="p">,</span> <span class="n">trt_ep_options</span><span class="p">),</span>
        <span class="s">"CUDAExecutionProvider"</span><span class="p">,</span>
    <span class="p">],</span>
<span class="p">)</span>

<span class="c1"># Once inference session initialization is done (assume no dynamic shape input, otherwise you must wait until inference run is done)
# you can find timing cache is saved in the 'trt_engine_cache_path' directory, e.g., TensorrtExecutionProvider_cache_cc75.timing, please note
# that the name contains information of compute capability.
</span>
<span class="n">sess</span><span class="p">.</span><span class="n">run</span><span class="p">(</span>
    <span class="bp">None</span><span class="p">,</span>
    <span class="p">{</span><span class="s">"input_ids"</span><span class="p">:</span> <span class="n">np</span><span class="p">.</span><span class="n">zeros</span><span class="p">((</span><span class="mi">1</span><span class="p">,</span> <span class="mi">77</span><span class="p">),</span> <span class="n">dtype</span><span class="o">=</span><span class="n">np</span><span class="p">.</span><span class="n">int32</span><span class="p">)}</span>
<span class="p">)</span>
</code></pre></div> </div> </details> <h3 id="explicit-shape-range-for-dynamic-shape-input"> <a href="#explicit-shape-range-for-dynamic-shape-input" class="anchor-heading" aria-labelledby="explicit-shape-range-for-dynamic-shape-input"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Explicit shape range for dynamic shape input </h3> <p>ORT TRT lets you explicitly specify min/max/opt shapes for each dynamic shape input through three provider options, <code class="language-plaintext highlighter-rouge">trt_profile_min_shapes</code>, <code class="language-plaintext highlighter-rouge">trt_profile_max_shapes</code> and <code class="language-plaintext highlighter-rouge">trt_profile_opt_shapes</code>. If these three provider options are not specified and model has dynamic shape input, ORT TRT will determine the min/max/opt shapes for the dynamic shape input based on incoming input tensor. The min/max/opt shapes are required for TRT optimization profile (An optimization profile describes a range of dimensions for each TRT network input and the dimensions that the auto-tuner will use for optimization. When using runtime dimensions, you must create at least one optimization profile at build time.)</p> <p>To use the engine cache built with optimization profiles specified by explicit shape ranges, user still needs to provide those three provider options as well as engine cache enable flag. ORT TRT will firstly compare the shape ranges of those three provider options with the shape ranges saved in the .profile file, and then rebuild the engine if the shape ranges don’t match.</p> <p>Click below for Python example:</p> <details> <div class="language-python highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="kn">import</span> <span class="nn">onnxruntime</span> <span class="k">as</span> <span class="n">ort</span>

<span class="n">ort</span><span class="p">.</span><span class="n">set_default_logger_severity</span><span class="p">(</span><span class="mi">0</span><span class="p">)</span> <span class="c1"># Turn on verbose mode for ORT TRT

<span class="n">trt_ep_options</span> <span class="o">=</span> <span class="p">{</span>
    <span class="s">"trt_fp16_enable"</span><span class="p">:</span> <span class="bp">True</span><span class="p">,</span>
    <span class="s">"trt_engine_cache_enable"</span><span class="p">:</span> <span class="bp">True</span><span class="p">,</span>
    <span class="s">"trt_profile_min_shapes"</span><span class="p">:</span> <span class="s">"sample:2x4x64x64,encoder_hidden_states:2x77x768"</span><span class="p">,</span>

        <span class="p">(</span><span class="mi">2</span> <span class="o">*</span> <span class="n">batch_size</span><span class="p">,</span> <span class="n">unet_dim</span><span class="p">,</span> <span class="n">latent_height</span><span class="p">,</span> <span class="n">latent_width</span><span class="p">),</span> <span class="n">dtype</span><span class="o">=</span><span class="n">np</span><span class="p">.</span><span class="n">float32</span>

However, note that ORT 1.20.1 and 1.20.2 will <strong>not</strong> run DDS ops with TRT due to a <a href="https://onnxruntime.ai/docs/execution-providers/TensorRT-ExecutionProvider.html#known-issues">known performance issue</a>.</li> </ul> <h2 id="samples"> <a href="#samples" class="anchor-heading" aria-labelledby="samples"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Samples </h2> <p>This example shows how to run the Faster R-CNN model on TensorRT execution provider.</p> <ol> <li> <p>Download the Faster R-CNN onnx model from the ONNX model zoo <a href="https://github.com/onnx/models/tree/main/validated/vision/object_detection_segmentation/faster-rcnn">here</a>.</p> </li> <li>Infer shapes in the model by running the <a href="https://github.com/microsoft/onnxruntime/blob/main/onnxruntime/python/tools/symbolic_shape_infer.py">shape inference script</a> <div class="language-bash highlighter-rouge"><div class="highlight"><pre class="highlight"><code> python symbolic_shape_infer.py <span class="nt">--input</span> /path/to/onnx/model/model.onnx <span class="nt">--output</span> /path/to/onnx/model/new_model.onnx <span class="nt">--auto_merge</span>
</code></pre></div> </div> </li> <li> <p>To test model with sample input and verify the output, run <code class="language-plaintext highlighter-rouge">onnx_test_runner</code> under ONNX Runtime build directory.</p> <blockquote> <p>Models and test_data_set_ folder need to be stored under the same path. <code class="language-plaintext highlighter-rouge">onnx_test_runner</code> will test all models under this path.</p> </blockquote> <div class="language-bash highlighter-rouge"><div class="highlight"><pre class="highlight"><code> ./onnx_test_runner <span class="nt">-e</span> tensorrt /path/to/onnx/model/
</code></pre></div> </div> </li> <li> <p>To test on model performance, run <code class="language-plaintext highlighter-rouge">onnxruntime_perf_test</code> on your shape-inferred Faster-RCNN model</p> <blockquote> <p>Download sample test data with model from <a href="https://github.com/onnx/models/tree/main/validated/vision/object_detection_segmentation/faster-rcnn">model zoo</a>, and put test_data_set folder next to your inferred model</p> </blockquote> <div class="language-bash highlighter-rouge"><div class="highlight"><pre class="highlight"><code> <span class="c"># e.g.</span>
 <span class="c"># -r: set up test repeat time</span>
 <span class="c"># -e: set up execution provider</span>
 <span class="c"># -i: set up params for execution provider options</span>
 ./onnxruntime_perf_test <span class="nt">-r</span> 1 <span class="nt">-e</span> tensorrt <span class="nt">-i</span> <span class="s2">"trt_fp16_enable|true"</span> /path/to/onnx/your_inferred_model.onnx
</code></pre></div> </div> </li> </ol> <p>Please see <a href="https://github.com/microsoft/onnxruntime/blob/main/docs/python/notebooks/onnx-inference-byoc-gpu-cpu-aks.ipynb">this Notebook</a> for an example of running a model on GPU using ONNX Runtime through Azure Machine Learning Services.</p> <h2 id="known-issues"> <a href="#known-issues" class="anchor-heading" aria-labelledby="known-issues"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Known Issues </h2> <ul> <li>TensorRT 8.6 built-in parser and TensorRT oss parser behaves differently.
