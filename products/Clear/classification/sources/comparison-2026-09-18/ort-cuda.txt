Note that ONNX Runtime Training is aligned with PyTorch CUDA versions; refer to the Optimize Training tab on <a href="https://onnxruntime.ai/getting-started">onnxruntime.ai</a> for supported versions.</p> <p>Because of <a href="https://docs.nvidia.com/deploy/cuda-compatibility/#minor-version-compatibility">Nvidia CUDA Minor Version Compatibility</a>, ONNX Runtime built with CUDA 11.8 are compatible with any CUDA 11.x version; ONNX Runtime built with CUDA 12.8 are compatible with any CUDA 12.x version; ONNX Runtime built with CUDA 13.0 are compatible with any CUDA 13.x version.</p> <p>ONNX Runtime built with cuDNN 8.x is not compatible with cuDNN 9.x, and vice versa. You can choose the package based on CUDA and cuDNN major versions that match your runtime environment (e.g., PyTorch 2.3 uses cuDNN 8.x, while PyTorch 2.4 or later uses cuDNN 9.x).</p> <p>Note: Starting with version 1.27, GPU packages published to <a href="https://pypi.org/project/onnxruntime-gpu/">PyPI (<code class="language-plaintext highlighter-rouge">onnxruntime-gpu</code>)</a> and <a href="https://www.nuget.org/packages/Microsoft.ML.OnnxRuntime.Gpu/">NuGet (<code class="language-plaintext highlighter-rouge">Microsoft.ML.OnnxRuntime.Gpu</code>)</a> are built with <strong>CUDA 13.0</strong> by default. Older GPU package versions are built with <strong>CUDA 12.8</strong> by default.</p> <p>To reduce the need for manual installations of CUDA and cuDNN, and ensure seamless integration between ONNX Runtime and PyTorch, the <code class="language-plaintext highlighter-rouge">onnxruntime-gpu</code> Python package offers API to load CUDA and cuDNN dynamic link libraries (DLLs) appropriately. viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Compatibility with PyTorch </h2> <p>The <code class="language-plaintext highlighter-rouge">onnxruntime-gpu</code> package is designed to work seamlessly with <a href="https://pytorch.org/">PyTorch</a>, provided both are built against the same major version of CUDA and cuDNN. When installing PyTorch with CUDA support, the necessary CUDA and cuDNN DLLs are included, eliminating the need for separate installations of the CUDA toolkit or cuDNN.</p> <p>To ensure ONNX Runtime utilizes the DLLs installed by PyTorch, you can preload these libraries before creating an inference session. This can be achieved by either importing PyTorch or by using the <code class="language-plaintext highlighter-rouge">onnxruntime.preload_dlls()</code> function.</p> <p><strong>Example 1: Importing PyTorch</strong></p> <div class="language-python highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="c1"># Import torch will preload necessary DLLs. It need to be done before creating session.
</span><span class="kn">import</span> <span class="nn">torch</span>
<span class="kn">import</span> <span class="nn">onnxruntime</span>

<span class="c1"># Create an inference session with CUDA execution provider
</span><span class="n">session</span> <span class="o">=</span> <span class="n">onnxruntime</span><span class="p">.</span><span class="n">InferenceSession</span><span class="p">(</span><span class="s">"model.onnx"</span><span class="p">,</span> <span class="n">providers</span><span class="o">=</span><span class="p">[</span><span class="s">"CUDAExecutionProvider"</span><span class="p">])</span>
</code></pre></div></div> <p><strong>Example 2: Using <code class="language-plaintext highlighter-rouge">preload_dlls</code> Function</strong></p> <div class="language-python highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="kn">import</span> <span class="nn">onnxruntime</span>

<span class="c1"># Preload necessary DLLs
</span><span class="n">onnxruntime</span><span class="p">.</span><span class="n">preload_dlls</span><span class="p">()</span>

<span class="c1"># Create an inference session with CUDA execution provider
</span><span class="n">session</span> <span class="o">=</span> <span class="n">onnxruntime</span><span class="p">.</span><span class="n">InferenceSession</span><span class="p">(</span><span class="s">"model.onnx"</span><span class="p">,</span> <span class="n">providers</span><span class="o">=</span><span class="p">[</span><span class="s">"CUDAExecutionProvider"</span><span class="p">])</span>
</code></pre></div></div> <h2 id="preload-dlls"> <a href="#preload-dlls" class="anchor-heading" aria-labelledby="preload-dlls"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Preload DLLs </h2> <p>Since version 1.21.0, the <code class="language-plaintext highlighter-rouge">onnxruntime-gpu</code> package provides the <code class="language-plaintext highlighter-rouge">preload_dlls</code> function to preload CUDA, cuDNN, and Microsoft Visual C++ (MSVC) runtime DLLs. This function offers flexibility in specifying which libraries to load and from which directories.</p> <p><strong>Function Signature:</strong></p> <div class="language-python highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="n">onnxruntime</span><span class="p">.</span><span class="n">preload_dlls</span><span class="p">(</span><span class="n">cuda</span><span class="o">=</span><span class="bp">True</span><span class="p">,</span> <span class="n">cudnn</span><span class="o">=</span><span class="bp">True</span><span class="p">,</span> <span class="n">msvc</span><span class="o">=</span><span class="bp">True</span><span class="p">,</span> <span class="n">directory</span><span class="o">=</span><span class="bp">None</span><span class="p">)</span>
</code></pre></div></div> <p><strong>Parameters:</strong></p> <ul> <li><code class="language-plaintext highlighter-rouge">cuda</code> (bool): Preload CUDA DLLs if set to <code class="language-plaintext highlighter-rouge">True</code>.</li> <li><code class="language-plaintext highlighter-rouge">cudnn</code> (bool): Preload cuDNN DLLs if set to <code class="language-plaintext highlighter-rouge">True</code>.</li> <li><code class="language-plaintext highlighter-rouge">msvc</code> (bool): Preload MSVC runtime DLLs if set to <code class="language-plaintext highlighter-rouge">True</code>.</li> <li><code class="language-plaintext highlighter-rouge">directory</code> (str or None): Directory to load the DLLs from. <ul> <li><code class="language-plaintext highlighter-rouge">None</code>: Search in default directories.</li> <li><code class="language-plaintext highlighter-rouge">""</code> (empty string): Search in NVIDIA site packages.</li> <li>Specific path: Load DLLs from the specified directory.</li> </ul> </li> </ul> <p><strong>Default Search Order:</strong></p> <p>When <code class="language-plaintext highlighter-rouge">directory=None</code>, the function searches for CUDA and cuDNN DLLs in the following order:</p> <ol> <li>On Windows, the <code class="language-plaintext highlighter-rouge">lib</code> directory under the PyTorch installation.</li> <li>Python site-packages directories for NVIDIA CUDA or cuDNN libraries (e.g., <code class="language-plaintext highlighter-rouge">nvidia_cuda_runtime_cu12</code>, <code class="language-plaintext highlighter-rouge">nvidia_cudnn_cu12</code>).</li> <li>Fallback to the default DLL loading behavior.</li> </ol> <p>By preloading the necessary DLLs using default search order, you can ensure that ONNX Runtime operates seamlessly with PyTorch.</p> <p><strong>Installing CUDA and cuDNN via <code class="language-plaintext highlighter-rouge">onnxruntime-gpu</code>:</strong></p> <p>You can install the necessary CUDA and cuDNN runtime DLLs alongside the <code class="language-plaintext highlighter-rouge">onnxruntime-gpu</code> package using pip:</p> <div class="language-bash highlighter-rouge"><div class="highlight"><pre class="highlight"><code>pip <span class="nb">install </span>onnxruntime-gpu[cuda,cudnn]
</code></pre></div></div> <p><strong>Preloading DLLs from NVIDIA Site Packages:</strong></p> <p>To preload CUDA and cuDNN DLLs from NVIDIA site packages and display debug information:</p> <div class="language-python highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="kn">import</span> <span class="nn">onnxruntime</span>

<span class="c1"># Preload DLLs from NVIDIA site packages
</span><span class="n">onnxruntime</span><span class="p">.</span><span class="n">preload_dlls</span><span class="p">(</span><span class="n">directory</span><span class="o">=</span><span class="s">""</span><span class="p">)</span>

<span class="c1"># Print debug information
</span><span class="n">onnxruntime</span><span class="p">.</span><span class="n">print_debug_info</span><span class="p">()</span>
</code></pre></div></div> <p><strong>Loading DLLs from Specific Directories:</strong></p> <p>To load DLLs from a specified location, set the <code class="language-plaintext highlighter-rouge">directory</code> parameter to an absolute path or a path relative to the ONNX Runtime package root.</p> <p><strong>Example: Loading CUDA from System Installation and cuDNN from NVIDIA Site Package</strong></p> <div class="language-python highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="kn">import</span> <span class="nn">os</span>
<span class="kn">import</span> <span class="nn">onnxruntime</span>

<span class="c1"># Load CUDA DLLs from system installation
</span><span class="n">cuda_path</span> <span class="o">=</span> <span class="n">os</span><span class="p">.</span><span class="n">path</span><span class="p">.</span><span class="n">join</span><span class="p">(</span><span class="n">os</span><span class="p">.</span><span class="n">environ</span><span class="p">[</span><span class="s">"CUDA_PATH"</span><span class="p">],</span> <span class="s">"bin"</span><span class="p">)</span>
<span class="n">onnxruntime</span><span class="p">.</span><span class="n">preload_dlls</span><span class="p">(</span><span class="n">cuda</span><span class="o">=</span><span class="bp">True</span><span class="p">,</span> <span class="n">cudnn</span><span class="o">=</span><span class="bp">False</span><span class="p">,</span> <span class="n">directory</span><span class="o">=</span><span class="n">cuda_path</span><span class="p">)</span>

<span class="c1"># Load cuDNN DLLs from NVIDIA site package
</span><span class="n">onnxruntime</span><span class="p">.</span><span class="n">preload_dlls</span><span class="p">(</span><span class="n">cuda</span><span class="o">=</span><span class="bp">False</span><span class="p">,</span> <span class="n">cudnn</span><span class="o">=</span><span class="bp">True</span><span class="p">,</span> <span class="n">directory</span><span class="o">=</span><span class="s">"..</span><span class="se">\\</span><span class="s">nvidia</span><span class="se">\\</span><span class="s">cudnn</span><span class="se">\\</span><span class="s">bin"</span><span class="p">)</span>

<span class="c1"># Print debug information
</span><span class="n">onnxruntime</span><span class="p">.</span><span class="n">print_debug_info</span><span class="p">()</span>
</code></pre></div></div> <h2 id="configuration-options"> <a href="#configuration-options" class="anchor-heading" aria-labelledby="configuration-options"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Configuration Options </h2> <p>The CUDA Execution Provider supports the following configuration options.</p> <h3 id="device_id"> <a href="#device_id" class="anchor-heading" aria-labelledby="device_id"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> device_id </h3> <p>The device ID.</p> <p>Default value: 0</p> <h3 id="user_compute_stream"> <a href="#user_compute_stream" class="anchor-heading" aria-labelledby="user_compute_stream"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> user_compute_stream </h3> <p>Defines the compute stream for the inference to run on.                                         <span class="s">"user_compute_stream"</span><span class="p">:</span> <span class="nb">str</span><span class="p">(</span><span class="n">torch</span><span class="p">.</span><span class="n">cuda</span><span class="p">.</span><span class="n">current_stream</span><span class="p">().</span><span class="n">cuda_stream</span><span class="p">)})]</span>

<span class="n">sess</span> <span class="o">=</span> <span class="n">ort</span><span class="p">.</span><span class="n">InferenceSession</span><span class="p">(</span><span class="s">"my_model.onnx"</span><span class="p">,</span> <span class="n">sess_options</span><span class="o">=</span><span class="n">sess_options</span><span class="p">,</span> <span class="n">providers</span><span class="o">=</span><span class="n">providers</span><span class="p">)</span>
</code></pre></div></div> <p>To take advantage of user compute stream, it is recommended to use <a href="/docs/api/python/api_summary.html">I/O Binding</a> to bind inputs and outputs to tensors in device.</p> <h3 id="do_copy_in_default_stream"> <a href="#do_copy_in_default_stream" class="anchor-heading" aria-labelledby="do_copy_in_default_stream"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> do_copy_in_default_stream </h3> <p>Whether to do copies in the default stream or use separate streams. To enable the usage of CUDA Graphs, use the provider options as shown in the samples below. ORT supports multi-graph capture capability by passing the user specified gpu_graph_id to the run options. gpu_graph_id is optional when the session uses one cuda graph. If not set, the default value is 0. If the gpu_graph_id is set to -1, cuda graph capture/replay is disabled in that run.</p> <p>Currently, there are some constraints with regards to using the CUDA Graphs feature:</p> <ul> <li> <p>Models with control-flow ops (i.e. <code class="language-plaintext highlighter-rouge">If</code>, <code class="language-plaintext highlighter-rouge">Loop</code> and <code class="language-plaintext highlighter-rouge">Scan</code> ops) are not supported.</p> </li> <li> <p>Usage of CUDA Graphs is limited to models where-in all the model ops (graph nodes) can be partitioned to the CUDA EP.</p> </li> <li> <p>The input/output types of models need to be tensors.</p> </li> <li> <p>Shapes and addresses of inputs/outputs cannot change across inference calls for the same graph annotation id. Input tensors for replay shall be copied to the address of input tensors used in graph capture.</p> </li> <li> <p>In multi-graph capture mode, the captured graphs will remain in the session’s lifetime and the captured graph deletion feature is not supported at the moment.</p> </li> <li> <p>By design, <a href="https://developer.nvidia.com/blog/cuda-10-features-revealed/">CUDA Graphs</a> is designed to read from/write to the same CUDA virtual memory addresses during the graph replaying step as it does during the graph capturing step. Due to this requirement, usage of this feature requires using IOBinding so as to bind memory which will be used as input(s)/output(s) for the CUDA Graph machinery to read from/write to (please see samples below).</p> </li> <li> <p>While updating the input(s) for subsequent inference calls, the fresh input(s) need to be copied over to the corresponding CUDA memory location(s) of the bound <code class="language-plaintext highlighter-rouge">OrtValue</code> input(s) (please see samples below to see how this can be achieved). This is due to the fact that the “graph replay” will require reading inputs from the same CUDA virtual memory addresses.</p> </li> <li> <p>Multi-threaded usage is currently not supported, i.e. <code class="language-plaintext highlighter-rouge">Run()</code> MAY NOT be invoked on the same <code class="language-plaintext highlighter-rouge">InferenceSession</code> object from multiple threads while using CUDA Graphs.</p> </li> </ul> <p>NOTE: The very first <code class="language-plaintext highlighter-rouge">Run()</code> performs a variety of tasks under the hood like making CUDA memory allocations, capturing the CUDA graph for the model, and then performing a graph replay to ensure that the graph runs.
