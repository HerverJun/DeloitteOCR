## 2. 手动成果如何进入同一任务

在工具内独立导入且没有平台 handoff 的 OCR/PDF 和已完成分类推理结果，现在可以通过原生目录查询并接回。平台下载原件、核实项目归属与内容哈希，保存来源绑定；相同字节复用可核实的资料身份。

新资料登记不会自动扩大当前任务范围。任务限定资料时，接回回执先返回 `required_assets`；未加入范围前不能读取结果。用户在“带回结果”中明确选择结果和新增资料后，范围与结果一起保存，再回到同一对话继续。接回本身不会暗中调用主控模型。

门户“带回结果”增加原生项目选择、目录分页和“核实原件并接回”。结果链接保留 `native_binding`、workspace 和原任务；预览读取当前保存版本，可打开原生项目继续操作。已固定证据继续保留保存时的事实。

接回结果可继续描述、固定证据、读取文字/表格、转为数据输入、生成发现和底稿，以及进入成果中心下载。OCR 归集原生导出 JSON/ZIP，分类归集预测 CSV 和保留原值的 JSON，模型包归集实际下载文件与训练元数据。

## 3. 等待、恢复与检索

训练、专业视觉、融合和批次接入原生任务观察器。异步完成后将实际回读结果交给 LangGraph，继续选择工具；不是只给出一个任务 ID 就结束。运行时事实补齐数据版本、模型、来源绑定、批次和正式对象身份，供下一轮接续。

标注、训练版本发布、训练、OCR 编辑/采用/视觉、分类处置/活动模型、导出等具有原操作身份和持久回执。业务成功但传输回复丢失时查询原操作；导出恢复读取原固定成果，校验文件与来源，不把后续新版本冒作原请求结果。批次处置通过业务 `request_id` 查回，避免把 Agent 操作身份与业务自建操作 ID 混用。

图片推理的失败子集重试仍通过原工具执行。训练、视觉、融合和批次不误入图片推理分支，返回对应业务工具供主控读取错误后决定；取消是否完成以实际原生状态为准。

原文检索优先当前选中资料，合并初始引用、手动返回、执行结果、已完成 handoff 与已接回原生结果。分页提供文件位置、文件内匹配位置和去重后 OCR 结果位置；达到命中上限不会跳过尚未读取的文件或同文件后续命中。继续原文用 `next_asset_offset` 和 `next_asset_match_offset`；原文结束后将 `asset_offset` 设为 `asset_page_total`，再按 `next_ocr_offset` 继续 OCR。

## 5. 能力边界与加载方式

文档检索仍是原文匹配，每次最多读取 200 个候选文件，单文件 8 MB，PDF 原文检索最多 200 页；分页可继续文件和 OCR 结果，未识别图片先通过 OCR。未接回的原生独立资料需先查询并接回。没有新增向量库。

结构表拼接要求明确顺序、完整结构、相同原值表头和列数、没有合并单元格；不猜造扫描票据字段，也不声称具备通用智能跨页表格引擎。Word/PDF 底稿导出、子 Agent、任意 shell 和账户/凭据/破坏性资料管理不属于本轮新增工具。已安装专业模型的可用性与权限继续由真实目录和原生服务决定。

现有本机开发启动器直接使用三套 worktrees 的源码，门户读取本轮 `apps/portal/dist`；平台运行时新增 pypdf 6.1.1 依赖已安装到 F 盘。正常重新启动平台及其关联 OCR/分类服务后加载本轮代码，保留原业务目录；本轮未代替用户停止当前运行实例。独立发行包需要按现有打包流程另行生成，不宣称历史包已经更新。

三仓库既有未提交修改均保留。本轮以 538 个文件的执行前快照核对变化；pyproject、OCR/分类外层工作台及门户测试未在该快照范围内，单独登记，不把全部 Git 差异归为本轮修改。项目源码、依赖、临时、日志和成果全部在 F 盘。
