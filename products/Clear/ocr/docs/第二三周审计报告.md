## 审计发现与修复

1. PyInstaller 在污染的 PATH 中拾取 Poppler ICU 和其他程序的 UCRT DLL，导致 QtCore 导入失败。构建器改为最小 PATH，拒绝打包 Windows 系统 ICU/UCRT，并附带官方 MSVC CRT；最终编译启动器已实际运行。
2. 复制目录时全局忽略 `results` 会损坏 Paddle 包内真实模块。已恢复完整依赖，并在构建说明中改为只排除根级用户输出。
3. 服务在 OS 断网测试中曾因残留 loopback 连接停留于关闭阶段。增加连接的 graceful shutdown 期限，之后继续等待队列保存和模型释放；复验正常退出。失败记录仍在构建目录，不作为通过证据。
4. Markdown/TXT 表格导出曾可能混入旧识别表。导出现在按文档顺序替换成校对单元格，支持 HTML 与 Markdown 表格，JSON 保留原始与编辑双方；新增回归测试通过。
5. 删除表格末行/末列后选区越界，现自动约束到有效范围。后台去弯曲完成时不覆盖用户新选择的图像版本；取消后的迟到输出不能发布为成功。
6. 新建项目和导入存在异步时序风险，现等待项目切换完成并阻止重叠导入。图像解码移出服务事件循环，避免大图阻塞本机请求。
7. 浏览器验收初版连续撤销测试没有等待每步独立保存，导致多撤销一步；已修正测试同步并独立读回实际文件。最终 XLSX/TXT 校对内容正确，非仅检查下载事件。

## 架构与可追溯性

SQLite 使用 WAL、FULL 同步和事务；结果完成与任务成功原子提交。原文件、处理版本、处理参数、引擎会话与原始模型输出均可追溯。前端以独立 revision 乐观并发校验防止旧窗口覆盖新编辑，切换和导出前 flush。临时失败不伪装为成功，也不自动降低模型质量。

本机服务绑定 127.0.0.1，使用每次启动生成的令牌；Host/Origin 检查与静态资源 CSP 阻止跨站调用和远程资源加载。模型仍使用第一周明确的本地路径和离线保护；原生 WFP 验证另覆盖 Python 拦截无法代表的原生网络调用。

模型 revision、Python 依赖、前端包锁、启动器构建版本和 Qt/PySide 源码/许可随包提供。源码和构建脚本可复核；证据只含合成测试图片及其结果，不包含会话令牌或完整用户数据库。
