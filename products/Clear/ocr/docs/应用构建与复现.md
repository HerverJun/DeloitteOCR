# 第二、三周应用构建与复现

## 基础与锁定

先按《构建与复现》生成第一周四引擎便携基础包。本次未变更模型 revision、Hunyuan F16 路线或 Paddle Windows 修正版。新增 service 为官方 CPython 3.12.10 embedded，使用 `config/service-requirements.txt` 和 `scripts/install_from_wheels.py` 安装本地 wheels；复制应用本地 MSVC CRT。不要将开发虚拟环境当成交付运行时。

前端 Node 22.17.0、npm 10.9.2，`frontend/package-lock.json` 精确锁定 React、Fluent UI、Vite 等依赖。在 frontend 运行 `npm ci`、`npm run test`、`npm run build`；将 dist 内容复制到 bundle/web。运行时不需要 Node 或前端开发服务器。`locks/frontend-package-lock.json` 随包保留。npm 审计结果只代表本次查询，不能代替持续更新。

启动器使用 CPython 3.12.14 构建环境、PySide6-Essentials 6.10.2、shiboken6 6.10.2、PyInstaller 6.20.0。Essentials 已包含所需 Qt Core/Gui/Widgets；无需 Addons。运行：

```powershell
python scripts/build_launcher.py --python "E:\build\launcher-env\Scripts\python.exe" --work "E:\build\launcher" --bundle "E:\build\bundle" --msvc-redist "C:\Program Files\Microsoft Visual Studio\18\Insiders\VC\Redist\MSVC\14.50.35710\x64\Microsoft.VC145.CRT"
python scripts/sync_bundle.py --bundle "E:\build\bundle"
Copy-Item frontend/dist/* "E:\build\bundle\web" -Recurse -Force
python scripts/lock_bundle.py --bundle "E:\build\bundle" --metadata-only
python scripts/audit_dependencies.py --bundle "E:\build\bundle" --output "E:\build\dependency-audit.json"
```

构建器将源码复制到构建盘后再运行 PyInstaller，避免 C/E 跨盘 spec 相对路径错误。PATH 只保留构建 Python 和 Windows 系统目录，清除 Conda/Python 环境污染，并拒绝错误打包的 `icuuc.dll`、`ucrtbase.dll`、`api-ms-win-*`。本次发现 Poppler/libheif DLL 搜索路径污染会让 QtCore 报“找不到指定程序”，此防护为实测修复。最终构建版本记录在 `config/launcher-build.json`。

复制便携包时，不能全局排除名称为 `results` 的目录：Paddle 的 Python 包本身包含该目录。只按完整路径排除应用根目录的用户输出；不要破坏依赖内部目录。

## 验证与证据

使用 bundle/runtimes/service/python.exe 的隔离模式运行 unittest（discover 源码 tests 的绝对路径），这样测试的是交付环境。真实应用验收：

```powershell
& "E:\build\bundle\runtimes\service\python.exe" -X utf8 -I scripts/audit_application.py --bundle "E:\build\bundle" --output "E:\build\app-audit"
```

必须使用新证据目录。该工具启动真实编译启动器，运行四引擎，验证取消、恢复、原图、编辑、导出和进程清理。`--quick` 仅跑四引擎单张及启动退出，供搬迁和断网复验。工具的 PID 检查只针对自己创建的进程。

浏览器验收先以 `--data "E:\OCR-week23-build\ui-project" --no-browser` 启动工作台，再运行 `node frontend/scripts/ui-audit.mjs`。可用 OCR_BUILD_ROOT 调整构建根目录。脚本从 launcher-state.json 读取动态端口，以外部 Edge headless 执行真实界面操作，浏览器禁用 GPU 不影响 OCR CUDA；每次结束关闭浏览器。

`scripts/build_offline_guard.cmd` 编译原生 WFP 工具。经管理员授权运行 `tools/offline_guard.exe BUNDLE OUTPUT --application`，临时阻断六套 Python、启动器、llama-server 及原生探针的非 loopback 连接，测试实际应用四引擎。动态规则随工具退出消失，不变更其他应用、网络适配器或防火墙配置。

## 归档

运行 `collect_app_licenses.py` 和 `collect_licenses.py` 整理许可、Qt/PySide 源码及索引；再用 `package_bundle.py` 流式生成 ZIP64 和逐文件 SHA-256 manifest，`verify_archive.py` 独立读回验证。用户项目数据留在应用包之外。源码归档从已提交 Git 树生成，交付目录另附归档哈希与验证回执，避免报告写入自身归档哈希产生循环。
