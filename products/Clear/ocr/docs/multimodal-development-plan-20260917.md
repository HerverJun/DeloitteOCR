# 通用多模态审校正式开发 · 第一阶段

依据：2026-09-17 多模态二轮审校调研及用户“开始正式通用型开发”的指令。模型补充要求：核实 Qwen3.6 小参数路线；模型选择与业务流程解耦。

## 本轮交付范围

1. 独立的本地视觉审校提供方与锁定模型配置；使用本机 llama.cpp，多模型配置可切换，运行时不联网下载。
2. 选中文字/单元格与整页审校任务；进入现有持久化 GPU 队列，支持取消、重试、重启后显式恢复。
3. 图像、采用修订、原值和模型配置快照；模型只返回现有目标的保留、建议修改或存疑。无可靠局部位置时明确使用整页证据。
4. 独立提案与采用记录；人工选择采用、保留或存疑，同批非冲突建议可连续处理；外部编辑、图像/采用结果变化导致旧建议失效。
5. 复用已有保存、撤销、来源和复核界面；未经采用的模型建议不进入原文或原始 OCR 投票，也不写为人工确认。
6. 导出带来源的 JSON / Markdown / XLSX 校验清单；普通输出与 PDF 来源清单纳入审校记录。事实转录和模型建议明确分开。
7. 后端/前端回归、隔离浏览器流程、真实本地模型功能实验及运行说明。

本轮不把通用模型等同于可靠的自动纠错器。跨页结构仲裁、自由模板 DOCX、主动取证和微调是调研中的后续扩展；本轮接口保留可扩展边界，先交付上述完整使用闭环。

## 通用性约束

- 不根据文件名、样本编号、特定表头、金额或已知答案选择策略；固定通用 prompt、输入预算和输出 schema。
- 原图/原始 OCR 不改写，现有人工修订不被后台覆盖；引用真实定位，无可靠框不生成猜测框。
- 模型输出没有合法目标、截断、漏目标、JSON 不合法或任务取消时不伪装为成功。
- API 校验与数据库事务负责目标身份、重复提交、修订过期和权限范围；不执行模型生成代码。
- 原始提示、响应、模型与量化身份、图像版本、采用和撤销链保留可复核证据。

## 验证口径

先记录现有回归基线，再验证迁移与原流程兼容；新测试重点是跨修订覆盖、撤销/重试、并发变化、前导零、表格源文本同步、取消与导出一致性。UI 使用外部 Playwright/Chromium，关闭 GPU 合成，结束后关闭浏览器。

真实模型实验单独保存失败、延迟和输出，不将合成样本或少量开发材料称为独立质量验收。新封存质量、真人复核效率和目标 A4000/另一台 Windows 离线验收，未经实际执行不得声称通过。
