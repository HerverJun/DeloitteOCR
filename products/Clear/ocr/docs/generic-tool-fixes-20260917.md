# 通用工具恢复修复 · 0.10.0rc3

本轮修复 0.10.0rc2 全局复核发现的四项通用工程问题。工具继续为未经修改的 pdfplumber 0.11.10，上游默认参数及锁文件保持不变，没有使用文件名、表头、样本标注或公开材料表现调整规则。

## 行为变化

- 页面渲染与原生文字先完成持久化，辅助表格工具随后以独立 CPU 请求运行。辅助超时或进程失败会保留基础页面及已完成文字，产生可见失败状态。
- 取消、服务停止与临时密码等待单独传播，发布前再次核对取消。退出中断的任务保留可恢复状态，不被伪装成辅助失败后继续记为成功。
- 已渲染的加密 PDF 单独重试时，沿上游异常链识别真实的密码异常；缺少密码进入等待解锁，重新输入临时密码后继续，不把密码写入任务或缓存。
- 辅助缓存绑定文档哈希、页码、图像哈希、渲染元数据、工具配置和适配代码。旧候选快照不会因为存在就被复用；暂停/恢复及已有区域 OCR 的分支也更新辅助快照。空检测可缓存，损坏缓存重算，失败不会当作成功缓存。
- 文档复核队列与结构面板区分提取失败、配置过期、已完成但未检出表格、排队/运行/中断和不适用。“重新提取 PDF 表格”通过持久任务队列只更新辅助候选，保留结果原文、人工编辑、修订、撤销历史和采用选择。历史候选保存，过期候选不能通过旧请求被接受。

基础页面 OCR 仍按既有模式处理；独立重试表格时不执行 OCR。默认仍为 Paddle + local-v2，无自动结构采用。PDF 表格工具属于辅助证据，失败提示本身不擅自改写采用内容或认定页面识别错误。

全量后端、前端、安装副本、已曝光公开工作区升级、PDF/Excel 导出和离线文件校验结果，以 `E:\OCR-generic-tool-fixes-20260917\delivery-receipt.json` 的最终回执为准。公开工作区升级只重提辅助结构，不能作为重新运行 OCR 或新的质量/泛化成绩。
