# 结构修复探索：Astra 代替人工审核的执行补充

日期：2026-09-19。授权：用户明确表示没有时间逐格人工审核，指定 GPT-Astra 承担审核，以 Astra 的审核水平作为本轮开发目标。本补充适用于后续结构修复探索；已经冻结的旧实验计划、协议、结果保持原样。

## 执行决定

- 审核模型固定为当前工具中可调用的 `gpt-6-astra`。使用独立 Codex 子任务，每份文档独立上下文，不继承开发过程、修复方案解释或既往分数。若该模型不可用，记录阻塞，不偷偷换成其他模型。
- 用户不再承担抽样、标注、逐格复核或争议裁决。这些研究工作由 Astra 与程序校验完成；无法确定的内容标为不确定并保持原结果，不把审核工作退回给用户。
- 本轮以 Astra 审核作为模型参考标准。已有独立参考标签的材料，同时报告相对标签的准确率；新材料无独立标签时，结果名称使用“Astra 审核通过率／一致率”，不能将模型自我认可写成人工真值或客观准确率。
- Luna 继续作为候选选择模型，Astra 担任独立评审。给评审的材料不包含候选提供方、模型名字、开发者选择、评分或“应该通过”的提示。
- 审核替代发生在实验材料与研究验收环节，不改变用户工作台中实际采用／撤销的产品交互，也不授权绕过内容保全、完整网格、图像版本或来源身份检查。

## 审核顺序

1. 先用固定、有独立参考标签的少量材料校准审核者。只给原图和待审结果，隐藏答案；逐格评判结构和文字，记录不确定处及可见依据。所有响应冻结后统一计分，不按分数重试。
2. 后续新增材料先让 Astra 只看原图创建模型参考标注，冻结后再运行修复方案，避免答案受方案输出引导。金额、编号、正负号、小数、重复值、空白、合并跨度、表题和脚注单列。
3. 程序核对完整性、身份、字面内容、网格及图像修订。模型从图像估计的框只能标为模型推断，不冒充 PDF 原生坐标、检测器证据或真实人工框。拆分仍须可核验的内容片段边界。
4. 若关键内容或结构有歧义，可对该文档安排一次独立 Astra 复审，不提供首次裁决。两次意见不一致或仍无依据则弃权。模型之间一致只表示一致性，不额外宣称精度。
5. 对通过程序校验的同一批补丁比较本地方案和本地＋Luna，以冻结的独立标签或 Astra 模型参考分别评分。报告纠正、改坏、保持、不确定及未触发，不能只选通过样本。

首轮观察后的执行细化：优先使用“Astra 完整参考表＋程序逐格比对”，而非仅依赖它逐格口头给出的通过／失败状态。数学排版、上下标和表头合并口径必须显式记录；当前字面值保全仍按原串检查，不由模型自行宣布等价。首轮派生比较属于事后流程分析，其数值不充当新独立验证。

## 恢复开发与停止规则

先处理独立代码审查指出的旧图像来源漏检，再打通新的真实采用内容定位／片段保存。至少取得 5 个正确局部修复、跨 3 份文档、内容保全零违规，才进入下一阶段的模型增益对照；无独立真值时明确写成“经 Astra 审核的修复”，不写成人工验证。

不再以“缺用户人工审核”为停止原因。停止原因应是具体技术问题、材料缺失或模型无法判定，并附实际案例。不确定结果默认保持原样，不要求用户逐项处理。模型审核不能创造缺失的来源关系，也不能把两个字符串视觉相似当作同一份内容的身份证明。

## 当前首轮实测

- 脚本：`scripts/astra_review_pilot.py`。
- 输入与审核响应：`build/astra-review-20260919-01/inbox/`。
- 冻结协议、映射及评分：`audit/astra-review-20260919-01/`。
- 抽样：旧固定 12 个随机检查样本内，按 `SHA256(astra-review-20260919:sample_id)` 排序取前 6 个，不按参考答案或错误挑选；6 份文档、560 个待审格。
- 每例独立实际调用 `gpt-6-astra` 看原图，不继承历史；输出逐格审核及完整模型参考表。
- 这批是历史英文科学表格裁剪，只校准审核流程，不能代表中文财务、真实扫描、照片或整页多表的精度。
- 必报：审核覆盖率、放行精确率、错误检出率、误放格数、模型参考表相对标签的结构／文字准确率、字面一致性、整表结果、不确定格及逐文档结果。
- 实际人工审核数始终为 0。Codex 子任务耗时不冒充生产 API 端点时延，未取得计费回执时不编造费用。

模型说明参考：https://developers.openai.com/api/docs/models/gpt-6-astra 。实际本地可调用模型以本次委派工具的显式模型选择为准。
