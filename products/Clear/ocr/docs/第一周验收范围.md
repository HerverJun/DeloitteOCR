# 第一周验收范围

依据《开发总纲》第 5 节，第一周交付为四个真实 Windows 推理后端、完整解析及表格输出验证、最小便携包。此阶段使用命令行验收入口；托盘启动器、React GUI、项目队列和交互编辑属于后续阶段。

| 引擎 | 必须验证的实际路径 | 表格能力边界 |
|---|---|---|
| PP-OCRv6 medium | Paddle CUDA 检测、行方向分类和识别 | 输出文字与坐标；不具备结构化表格能力，不推测单元格或合并关系 |
| PaddleOCR-VL-1.6 | Paddle 原生完整解析，PP-DocLayoutV3 + VL 识别 | 保留区域、HTML 表格及原始管线输出 |
| GLM-OCR | 本地 Transformers BF16，官方 SDK 布局、区域裁剪、任务提示和格式化组件 | 顺序识别区域；保留官方格式化输出和格式化前原文，不调用云 API |
| HunyuanOCR-1.5 | 固定 llama.cpp Windows CUDA 构建，F16 GGUF + F16 视觉投影 | 官方 doc_parse 提示，保留模型实际给出的表格结构；不将 caption 擅自改成合并单元格 |

验收记录区分：

- 真实推理与模型哈希核验。
- 应用离线策略验证：Python 网络审计钩子阻止非回环访问，Hugging Face/Paddle 禁止下载，llama.cpp 显式 `--offline`。
- 操作系统断网验证：必须另有物理断网或操作系统级网络阻断证据；应用离线策略不能冒充此项。
- 目录搬迁验证：完整运行时和模型移至新目录后实际识别，包含中文、空格和盘符变化。
- 构建机上清理 PATH 后运行不能替代另一台无开发环境电脑验收；后者和 A4000 性能验收在第 6–7 周。

样本是可复现的合成兼容性夹具，不构成不少于 200 张真实样本的识别效果评测，也不产生模型准确率排名。500 张批次、GUI 表格编辑、引擎热更新和最终干净机器交付不在第一周范围。
