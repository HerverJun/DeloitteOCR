# 文档工作流质量与审计报告 · 0.9.0rc1

## 结论

文档分页、原生提取、区域补识别、版本绑定定位、人工绑定、可搜索 PDF 及本机恢复回归已实现并验证。精确表格定位没有达到“覆盖率≥90%、错位率≤1%”目标，按原计划保持实验性，不能作为默认精确定位发布。独立机器与人工效率均未测。

## 冻结定位评测

100 张表、5,819 个完整单元格目标，60 PubTables-1M＋40 FinTabNet；按原始文档分组，一文档一表，推理前冻结。PubTables 使用官方 pdf_bbox 完整单元格坐标，核对转换差异≤2px。冻结文字及逻辑拓扑来自参考标注，模型和匹配器仅收到独立真实 PP-OCR blocks，不传入目标 cell boxes。未调整冻结阈值。数据版本、来源及图像哈希保存在 geometry-holdout/frozen/manifest.json。

历史 C/E 构建材料排除审计扫描 16,557 张图像（2,340 唯一哈希）和 12,139 元数据文件（7,441 唯一哈希），已知文档 ID/图像哈希命中 0、读取错误 0。改名文档和不同裁切近重复不能仅靠哈希完全排除。

| 方法 | 提供 cell 定位 | 正确且 IoU≥0.5 | 错格 | 精确覆盖率 | 错位率 | 无定位 | 整表降级 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 原整表区域 | 0 | 0 | 0 | 0% | 不适用 | 0 | 5,819 |
| Paddle 增强 | 224 | 39 | 3 | 0.6702% | 1.3393% | 95 | 5,500 |
| RapidTable 对照 | 379 | 178 | 1 | 3.0589% | 0.2639% | 51 | 5,389 |

精确覆盖分母为全部目标；错位分母为提供 cell 定位的数量，另一个 GT 行列 IoU 严格高于所指目标即错位，空分母为 null。Paddle 182 个与 Rapid 200 个输出没有指向其他格，却未达到 IoU 0.5，不能计成功。Paddle 91 张、Rapid 87 张表全部 cell 降级。两者在 PubTables 均没有提供 cell 映射，保守拓扑/文字门槛对当前输出的限制明显，不能把检测框召回等同可靠定位。

原始 Paddle 有 1 个损坏 HTML 解析失败（pubtables-1m-003，Overlapping table cells），Rapid 有 1 个（pubtables-1m-028，Truncated HTML table）。原评测按失败保留。最终代码将损坏结构安全降级；对原始 Paddle artifact 静态重放，99 个成功项映射完全一致，失败项全部降为 image，没有重新推理或改写评测。final-mapping-replay.json 记录旧 run-lock、最终模块/函数及每个原始 artifact 哈希。查询索引优化不改变映射算法。重放不是新的 100/100 精度通过。

分组计数/指标在 geometry-metrics.json：合并格 56 表/3,347 格，无合并格 44 表/2,472 格。40 张 FinTabNet 经全量 contact sheet 目视检查均无完整单元格网格（允许横线/底色）；只后补描述标签，没有重选样本。

RapidTable 3.0.2 main.py 与计划 commit SHA 一致；固定本地 SLANet+ ONNX，use_ocr=False，传同份 PP-OCR，socket 禁网。结构预测框标为 structure_prediction，不冒充检测框，不加入生产默认后端。

## 时间与容量

几何冷进程加载 13.619s，其中模型加载 6.116s；PP-OCR 分别 9.676s/6.438s。Paddle 99 个可用推理中位数 120.31ms、P95 355.70ms；100 项墙钟中位数 200.36ms、P95 440.22ms。Rapid CPU 推理中位数 58.55ms、P95 264.71ms，与 Paddle GPU 后端不同，不能直接宣称同硬件速度优势。

200 次持久几何缓存读取（含 SQLite/解码）中位数 1.510ms、P95 1.845ms。ui-07 的 50 次缓存单元格点击对＋DOM 完成断言中位数 66.70ms、P95 70.96ms；最终 ui-08 同规模中位数 66.80ms、P90 72.11ms、P95 77.07ms，低于 300ms 目标。包含两个点击，不是模型冷启动或人工校对时间。开发机为 RTX 4070 Ti SUPER 16GB、驱动 595.97，不外推 A4000。

1,000 页空白容量 fixture：导入 0.345s、初始 0 图像；打开 1/2/500/501/999/1000 后仅 6 图像。6 线程请求最多 2 PDF 子进程，RSS 父进程峰值 35.25MiB、子进程合计峰值 218.18MiB、总计 249.35MiB。缓存渲染 2.74ms。RSS 不含 OS 文件缓存，空白文档不代表复杂扫描最坏内存。

本地有效时钟扣除后台、闲置及系统等待，成功提交后写 SQLite。真实人工中位数、P90、各动作最终错误及时间收益均未测；自动化 timing row 只证明管线可用。

PDF 覆盖原生/混合/扫描/旧 OCR/中文/双栏/乱码 ToUnicode/旋转/非零 CropBox/UserUnit/空白/损坏/加密/多文档 ZIP。独立 PDFium 读回/高亮验证中文、前导零、长编号、金额、定位；原页叠加 3 个留存样本可见像素完全一致，重建页与选定 TIFF/图像版本一致。部分页页序、书签链接调整、旧文字清理、原生表格删除、局部人工绑定无重复、缺字 U+10FFFF 明确失败、导出快照不跟随后续编辑均有测试。

## 运行时与交付

PDF 使用 -I 隔离、独立 CPython 3.12、51 精确锁定 wheel。早期非隔离 metadata 检查读入用户 site-packages，产生 12 个伪依赖错误；原 PDF runtime 与干净重建 runtime 正确隔离时均 51 distributions、0 errors。pdf-runtime-verification.json/pdf-pip-check.txt 是过程记录，不作为最终失败结论。交付采用干净重建环境，verify_pdf_runtime.py 强制 -I。

离线包用真实编译启动器、嵌入式服务、四引擎及文档流程另验收。tested-components 将最终运行文件与验收前清单逐字节对应；ZIP 逐项解压 CRC＋SHA256、完整清单/重复路径检查；源码 ZIP 对应 Git commit 每个 blob。最终通过状态以交付目录独立回执为准。

最终完整应用回归 48 项通过（application-full-02，8 个原始真实 OCR 结果），包括格式解码、UVDoc/版本不变性、失败重试、暂停/取消、校对撤销重做、Markdown/Excel/来源索引以及真实启动器崩溃后的显式继续和完成结果不重复。第一次 full 在旧脚本“工作簿页数=业务表数”断言处停止，原因是已有来源索引页未被计入；修正为核对业务表页和完整来源索引后全部通过，产品代码未因此修改。最终文档验收额外通过中文双栏及 mixed 的真实 HTTP 导入/区域 OCR/导出/独立读回，并验证使用版本 0.9.0rc1。

最终隔离 PDFium 再验三个留存 PDF，可见像素与原页完全一致、读回文字与原证据一致。62,319 个既有 OCR/llama runtime 文件、83 个既有模型文件与上次交付清单一致；85 个新增模型/字体/wheel 锁文件逐项对上独立验收清单。

明确未测：A4000、独立干净 Windows、内网真实业务材料、真实人工计时。需要另建实际证据，不能引用本机结果替代。
