# 融合识别、快速校对与恢复

适用 0.8.0rc2。默认保守，两档/三类当前均只开放候选建议。支持票数是证据，不是正确概率；提示处理完不等于没有漏错。

## 操作

1. 展开「融合识别 · 生成有来源的校对草稿」，选择表格、印刷体或手写、模式和引擎。同图同处理版本同批次有兼容原始结果时，点击「复用当前图片结果」。否则「完整识别并融合」先按单 GPU 顺序跑完引擎，再由 CPU 融合。仅校对模式也支持已有结果融合。
2. 融合结果先预览，点击「采用此预览」才改变正式修订与导出目标。再次融合生成另一份结果，不覆盖旧修订。
3. 在「快速校对」按结构、数字/日期/编号、空值、其他文字和处理状态筛选。查看当前值、候选、原因、来源；选择候选或手工修改后「保存并继续」。也可保留、暂不确定、上一/下一项；下一项仅跳过，不算完成。
4. 有可信坐标时左侧高亮单元格或整表/区域，点击「放大疑点区域」看上下文。缺坐标或版本不匹配则全图显示并聚焦编辑位置，仍可手工缩放。整表候选需核对完整内容和合并；候选长表每页 50 格。缺表可明确插于文首/文末，精确混排顺序用普通编辑调整。
5. 保存完成后人工「确认此结果」。普通导出仍允许未确认内容，也可选仅导出已确认；未处理、有疑问、过期、未人工确认分别记录。

融合 TXT、MD、JSON、XLSX 以 ZIP 交付，同时包含 `fusion-sources.json` 和逐结果来源 JSON。主内容、revision、策略、证据及决策来自同一已保存快照。XLSX 编号/前导零/长数字按字符串保存。

如果文字或手写片段包含结构化表格，整段来源候选只供对照。点击「在编辑器定位」核对文字和表格，再回到快速校对「保留当前并继续」，或先标记「暂不确定」；不直接用整段文字覆盖结构化表格。

## 保存和恢复

草稿与疑点决策串行提交。后端在一个事务中检查结果、版本、revision 和候选依据，保存修订/决策/位置，成功才前进。刷新后恢复本地草稿和数据库位置。响应丢失时保存原请求标识及内容，锁定编辑，点击「重试上次提交」安全重试。多窗口冲突保留草稿供重新核对；不要直接用旧窗口覆盖新结果。清除站点数据会移除尚未提交的本地草稿。

普通编辑仅使受影响疑点重核；结构修改使受影响表决策过期；撤销重做也重核依据。采用结果、处理版本或 revision 变化使人工确认失效。旧来源快照、原始输出和决策历史保留。

OCR 和 CPU 队列分别恢复。意外退出后未完成任务等待手动继续/重试，依赖全部终态后才融合；失败、取消、不支持都显示在覆盖中，无可用来源则失败。取消的 CPU 任务尚未退出时禁止删除项目。

## 升级、搬迁和回退

数据库升至 schema 8。首次打开旧库，SQLite 一致性备份写入 `database-backups/before-v…-to-v8-….sqlite3` 后事务迁移；旧程序遇到未来 schema 会在写入前拒绝。

升级/搬迁前退出托盘工作台并备份完整工作区。搬迁复制数据库、图片版本、输出及备份整个目录，再用启动器 `--data "新目录"` 打开。融合表、来源、位置和决策在 SQLite 内，已验证复制后读取/导出；浏览器未保存草稿不随目录搬迁。应用包与项目目录分离。

降级先保留当前完整副本，再在单独目录恢复匹配旧版的升级前数据库和文件备份；升级后的新增修订不在旧备份中，勿覆盖唯一新工作区。策略回退应部署已验证并重新生成完整性清单的包，只影响新任务；旧结果绑定原策略，不静默重算。

## API 与限制

| 路由 | 作用 |
|---|---|
| `GET /api/fusion/policies` | 类别/模式策略 |
| `POST /api/projects/{id}/fusion` | result_ids + request_id 创建 CPU 融合 |
| `POST /api/projects/{id}/tasks` | 原有批次可带 fusion 配置 |
| `GET /api/results/{id}/issues` | 状态/类别筛选、分页、恢复位置 |
| `PUT /api/results/{id}/issues/position` | 保存位置，不完成疑点 |
| `POST /api/results/{id}/issues/{issue_id}/decision` | revision/request_id/basis 原子决策 |
| `GET /api/results/{id}/evidence` | 分页证据 |
| `POST /api/fusion/queue/recover` | CPU 工作器恢复 |

同引擎/模型只计一次，人工修订和融合结果不计新票。PP-OCRv6 不投结构票。多个唯一长文字锚点仅判断同表身份，不能证明单元格映射。完整合法来源骨架替代残缺基准时整表仍需复核。

复杂多栏/图文表混排不做推测性区域重排；有界行/片段对齐不可靠则保留基准并整段/整文复核。同形表、多表歧义、缺行列、合并冲突、无坐标会产生较多整表提示，当前没有人工校对提速的实测结论。

文字先通过版本一致的真实区域和双向唯一几何对应关联，再对区域内的行/片段有界对齐；区域缺失、重叠、重复文字关联歧义或换序则整文待核。无坐标时使用有界阅读顺序对齐。字符疑点只能高亮其真实所在区域，不冒充字符坐标。表格定位可取可靠映射来源的真实坐标，明确记录提供坐标的 result ID/engine；所有融合编辑表格均清除来源 confidence/polygon，原始数据保留于证据。

哈希口径：冻结报告和交付清单对文件字节做 SHA-256；结果中的 policy_sha256 是选中策略对象的规范 JSON 指纹，策略内 file_sha256 是完整策略配置解析后的规范 JSON 指纹。比较时使用对应口径，不能把对象指纹直接当成文件字节校验值。
