第一周要求已通过：四个真实 Windows 原生后端完成推理，完整解析路线与表格输出可用，并在原构建目录不可见、跨盘搬迁至中文与空格路径后通过系统级外网阻断验收。交付形式为内含模型、独立嵌入式 Python、原生 DLL、命令行工具、双击兼容性验收入口及证据的便携 ZIP。

## 修复审计

1. **Paddle cuDNN 元数据冲突**：上游 Windows 3.3.1 实际编译 cuDNN 9.9.0，依赖却固定 9.5.1.17。修正发行版本为 `3.3.1+ocr.1`、依赖为 `9.9.0.52`，仅修改 metadata/RECORD，推理代码及二进制不变。最终锁定审计另发现 CRLF 使早期版本头替换漏执行，已修复并核对 3503 个未变条目的 SHA-256；最终实际安装版本与文件名一致，见 `audit/paddle-metadata-final-fix.json`。保留上游与最终修正 wheel 哈希；复验无该不匹配警告。
2. **中文模型路径**：实际搬迁后 Paddle 原生 C++ 文件读取失败。改为无管理员权限的临时 ASCII 目录 junction，指向当前包模型；图片使用 Unicode-aware Python 解码后提交 BGR 数组。普通完成和异常均清理链接；强制终止整个进程可能留下小型临时链接，目标模型不删除、不复制。
3. **Defender 误报**：仅将明确的系统 Defender Platform/MpOAV.dll 注入列入操作系统允许项；开发机第三方库仍被拒绝。
4. **静默失败与保真**：GLM 布局／识别失败直接传播，生成截断不提交成功；混元未正常 EOS 则失败；无效／重叠表格拒绝导出。Excel 全部写为文本，避免自动数值舍入或公式执行。
5. **进程清理与离线**：Windows Job Object 管理子进程树；loopback 服务使用随机端口及临时令牌，退出终止；模型使用明确本地路径，关闭下载／遥测／SDK 云端模式，未使用 CPU 识别回退。

搬迁前失败记录保留在 `audit/regressions/`，与修复后最终证据分开；没有用早期成功覆盖后续失败。
