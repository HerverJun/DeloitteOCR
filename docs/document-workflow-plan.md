# DeloitteOCR：精确表格定位与 PDF 文档工作流开发计划

## 1. 调研结论与复用方案

本轮已检查上游具体实现，并核实主要 PDF 依赖有 Windows CPython 3.12 可用发行包。现有 PaddleX 表格管线文件与官方 `v3.7.0` 文件哈希一致，适合在当前环境上增量开发。以下属于源码与部署可行性结论，尚未进行新增模型的同样本推理评测。

| 对标项目 | 已查清的实现方式 | 本项目采用方式 |
|---|---|---|
| [PaddleX / PP-StructureV3](https://github.com/PaddlePaddle/PaddleX/blob/v3.7.0/paddlex/inference/pipelines/table_recognition/pipeline_v2.py) | 表格分类后分别运行有线/无线表格结构模型和单元格检测模型，再匹配 OCR 文字、还原页面坐标 | **复用 `table_recognition_v2` 子管线**，接入已有版面区域与 PP-OCR 输出，关闭重复的整页预处理、版面和文字识别 |
| [RapidTable](https://github.com/RapidAI/RapidTable/blob/22592283c1f9d7c5a014c96c4ecc57de0b3ebfce/rapid_table/main.py) | 结构识别输出 `cell_bboxes`；解码结构得到行列跨度；可以接收外部 OCR 结果，也可以只运行结构识别 | 作为轻量几何方案的评测对照；首版生产路线固定采用 Paddle 子管线，不同时增加多个默认定位后端 |
| [Docling](https://github.com/docling-project/docling/blob/5ea6490ffdc57b2fd7de5cc436f2d0a22f2214d4/docling/models/base_ocr_model.py) | 根据布局与 PDF 内容找出需要 OCR 的区域；原生文字和 OCR 文字按空间关系合并；表格模块把文字坐标与结构对应 | 复用其区域补识别、来源记录和空间匹配方式；适配所需 MIT 代码并保留出处，不引入完整 Docling 模型管线 |
| [Docling Parse](https://github.com/docling-project/docling-parse/blob/1fab490e4e59a39d70f375cd5092f4784036fa93/docling_parse/pdf_parser.py) | 独立提取字符、词、行、图像和图形坐标，保留页面边界信息；支持逐页读取及释放缓存 | **直接使用该库提取 PDF 内容**；使用 PDFium 渲染页面 |
| [OCRmyPDF](https://github.com/ocrmypdf/OCRmyPDF/blob/ffee83231532f4f67b8c0e756cddec67446570c9/src/ocrmypdf/_graft.py) | 将按坐标生成的文字层叠加到原页；处理旋转、旧隐形文字和页面替换 | 复用其文字层渲染与叠加实现，通过适配器输入工作台已采用结果；不再次调用默认 OCR |
| [Scribe OCR](https://github.com/scribeocr/scribeocr) / [Folio-OCR](https://github.com/vorojar/Folio-OCR) | 原图叠字、区域高亮、文档分页、切页保存 | 借鉴交互，扩展现有 ImageCanvas、QuickReview 和保存机制，不替换前端技术栈 |

复用时必须处理两项已发现的边界：

- Paddle 的最终 `cell_box_list` 可能包含合并、补框等后处理结果。必须保留原始预测与派生过程，不能将所有框都标成直接检测框。
- 已核查的 PaddleOCR Local 可搜索 PDF 实现把隐形文字集中排在页角，适合搜索收录，却不满足准确高亮要求；本项目不复用这一导出方法。

范围已确定：**包含可搜索 PDF；混合页按区域补识别；尽量保留原 PDF；跨页表格合并留到后续。**

## 2. 数据基础、接口与兼容

建立统一关系：

**项目 → 文档 → 页面 → 图像版本 → 区域 → 识别及校对结果。**

- 数据库由 schema 8 升级到 9，新增文档、页面、区域、几何证据和处理阶段记录。现有图片作为单页文档关联，保留原图片、版本、任务和结果 ID，不搬移历史原图。
- 页面记录原页码、尺寸、CropBox、旋转及渲染参数；区域记录所属页面、图像版本、类别、阅读顺序及来源。
- 工作台统一使用左上角像素坐标，同时保存 PDF 点坐标与转换矩阵。裁剪、旋转和透视使用可追溯变换；UVDoc 等非线性处理后重新定位，不直接套用旧坐标。
- 几何证据独立于可编辑文字保存，绑定来源结果、模型版本、图像哈希和表格结构指纹。文字修改可以保留仍有效的定位；增删行列、合并拆分等结构变化使相关映射失效。
- 原生 PDF 内容、辅助几何与四引擎 OCR 分别记录来源。原生文字只计一份证据，几何组件不参与文字投票。

新增接口覆盖以下能力，沿用现有鉴权、修订冲突和任务恢复机制：

| 接口 | 用途 |
|---|---|
| `POST /api/projects/{id}/documents` | 导入 PDF、现有图片及多页 TIFF，创建文档和页面记录 |
| `GET /api/documents/{id}/pages` | 分页获取页面状态、缩略图和处理来源 |
| `POST /api/pages/{id}/process` | 按自动、仅原生提取、整页 OCR 三种模式处理页面 |
| `GET /api/pages/{id}/regions` | 获取版本绑定的区域与几何证据 |
| `POST /api/results/{id}/geometry` | 请求补充定位或重新定位 |
| 扩展 `/api/export` | 接受文档或页面范围，新增 `pdf` 格式，固定采用结果及修订快照 |

现有单图接口和四种导出继续兼容。迁移前自动备份，失败整体回滚；旧程序继续拒绝打开新 schema，避免误写。

## 3. 两条功能链的实施

### 精确表格定位与校对

- 增加“补充表格定位”辅助任务，复用现有 GPU 互斥、取消、失败重试及进程释放机制，不作为第五个文字识别引擎展示。
- 使用已有表格区域；缺少区域时调用已有 PP-DocLayoutV3，亦支持用户框选。表格子管线使用官方分类、SLANeXt/SLANet 与 RT-DETR 单元格模型，全部指定本地路径。
- 通过小型适配层保留原始检测框、结构预测、后处理框和文字匹配关系。复用上游匹配实现，再检查行列跨度、唯一对应关系及重复内容歧义。
- 只有可靠对应才展示单元格级定位；否则降级到表格区域，并说明原因。不得按平均行高、列宽或 HTML 格子数量制造单元格坐标。
- 快速校对区同时展示局部原图、当前值、各来源候选，以及所在行、列标题和相邻内容；支持局部与整表切换、原图和编辑器双向定位。
- 复用现有保存并继续、撤销和过期处理。增加人工绑定区域入口，处理无法自动定位的新增内容，明确标记为人工定位。
- 定位首次计算后按版本缓存；仅更新几何不修改原始识别文字、人工修订或当前采用来源。

### PDF 分页、原生提取与区域补识别

- 用 Docling Parse 逐页获取原生文字和内容区域，用 `pypdfium2` 渲染；默认 300 DPI，超出现有像素上限时明确提示调整参数。
- 可靠原生文字优先保留；不可映射字符、无效坐标、隐藏的旧 OCR 等单独标记。不能因页面“存在文字”就跳过整页，也不能把库默认的 `confidence=1.0` 展示成正确概率。
- 混合页按 Docling 的 PDF 感知区域策略处理：保留可靠文字，对扫描图片、图表和未覆盖区域补识别；覆盖关系有歧义时保留冲突供校对，避免静默丢弃文字。
- 原生表格仍运行结构定位，但优先用已提取的文字填充单元格；扫描表格使用现有表格识别入口和新增几何组件。
- 区域任务输出映射回所属页面，生成完整页结果；区域裁剪不改变页面当前显示版本。纯扫描页走现有 OCR 流程，空白页保留正常页码和状态。
- 新增文档树、页码跳转、逐页状态及文档内搜索。切页前保存，恢复后只继续未完成阶段；用户可以强制重新 OCR 某页。
- CPU 解析和渲染采用独立工作器，最多两个页面同时展开，逐页落盘并释放解析缓存；GPU 继续串行。
- 加密 PDF 首版提供临时密码输入，密码不写入项目或日志；重启后需要密码时显示等待解锁，不重复处理已完成页。

### 可搜索 PDF 输出

- 每个文档默认输出一份 PDF，多文档输出 ZIP；支持选择页面，保持原页序，本轮不做跨文档拼接。
- 未修改原生内容的页面保留原 PDF 页面对象、矢量内容和原图；扫描区域追加坐标文字层。
- 复用 OCRmyPDF 的旧隐形文字清理与坐标变换，避免新旧 OCR 重复叠加。页面经过图像处理、原生可见文字被修改或原文字映射损坏时，仅重建该页，并记录重建原因。
- 文字层使用已采用的校对内容，按可靠文字行或单元格区域定位；没有定位的新增内容在导出前列出，补定位后导出，或由用户明确排除相关页面。
- 使用 OCRmyPDF 的 FPDF2 渲染器和 pikepdf 叠加；随包提供中英文字体及符号回退，检查缺字，不联网补字体。
- 保留可用元数据、书签和链接；选择部分页面时调整目标，重建页面时处理失效链接。首版交付普通可搜索 PDF，不声明 PDF/A、PDF/UA 或签名有效性。
- 导出附带页面来源、结果修订、定位覆盖及重建页面清单，与现有来源追溯保持一致。

## 4. 测试与评价

**定位效果**

- 使用 PubTables-1M 的完整单元格坐标和 FinTabNet 表格，另补公开中文、无边框、合并单元格及拍照样本；排除已有调参材料，按原始文档分组后冻结测试集。
- 比较当前区域定位、Paddle 增强定位和 RapidTable 对照。文字结果固定，单独评价几何与映射收益。
- 冻结测试集至少包含 100 张表、1,000 个目标单元格，按表格类型分别报告。
- 定位成功率＝正确目标且框 IoU≥0.5 的数量／全部目标；错位率＝指向错误行列的数量／提供单元格定位的数量。同时报告无定位率及整表降级率。
- 首版目标：精确定位覆盖率≥90%、错位率≤1%。未达到时保留组件和测量结果，功能以明确的实验性入口提供，不把它设为默认精确定位。

**处理时间**

- 分开记录冷加载、定位推理、缓存读取及界面定位时间；缓存命中后的界面定位 P95 目标≤300ms。
- 校对计时仅保存在本地，记录从疑点完整呈现到成功提交的时间，扣除切到后台、闲置和系统等待。
- 报告中位数、P90、处理动作及最终错误情况。自动化操作只证明响应性能；没有实际使用计时就明确标为未测，不声称节省人工时间。

**PDF 正确性与回归**

- 覆盖原生、扫描、混合、已有 OCR、乱码字体、双栏、中文、旋转、非零 CropBox、空白、损坏和加密 PDF。
- 针对“扫描正文＋原生页码”“表格中含原生文字与图片”等案例，检查漏识别和重复文字。
- 对导出 PDF 独立重新提取文字、渲染并核对搜索高亮；检查前导零、长编号、金额符号、中文、页序和书签。
- 原页叠加路径验证可见内容不变；重建路径验证与所选图像版本一致。测试新增文字缺坐标、旧 OCR 清理及部分页导出。
- 使用 1,000 页文档检查按需渲染和内存上限；对含真实 OCR 的批次验证暂停、取消、重试、进程异常恢复及完成页不重复执行。
- 完成现有 Python、前端及核心工作台回归。浏览器截图遵循已有线程协调规则；最终证据截图优先使用关闭 GPU 加速的外部 Playwright。

## 5. 实施顺序与交付

按一名熟悉现有项目的开发者估算约 **25–35 人日**：

| 阶段 | 交付物 |
|---|---|
| M1：上游复用与兼容验证 | 固定源码引用、许可证和模型清单；Paddle 表格子管线及 PDF 库的 Windows 离线最小验证；冻结评测方案 |
| M2：文档及坐标基础 | schema 迁移、页面和区域关系、坐标转换、阶段任务及历史项目兼容 |
| M3：分页与混合页处理 | PDF/TIFF 导入、原生提取、区域补识别、页面导航和恢复 |
| M4：精确校对 | 几何证据、保守映射、局部原图和上下文、人工定位、本地计时 |
| M5：PDF 导出 | 坐标文字层、原页保留、必要页面重建、来源清单与独立读回 |
| M6：验证与离线交付 | 效果和性能报告、回归、完整离线包、依赖锁及更新恢复说明 |

PDF 依赖放入独立 CPU 运行时，避免改变现有四引擎环境。兼容验证起点固定为已核实有发行包的 `docling-parse 7.19.1`、`docling-core 2.96.0`、`pypdfium2 5.13.0`、`pikepdf 10.13.0.post1`、`fpdf2 2.8.8`、`OCRmyPDF 17.11.0`；最终交付锁定全部传递依赖、字体和模型哈希。

本轮不加入跨页表格合并、Office 输入、模型训练或自动文字替换。目标 A4000 与独立 Windows 的测量按实际取得的环境报告；缺少相应环境时保留明确的未测状态，不用开发机结果代替。
