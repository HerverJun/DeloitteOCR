# 外部机器验收交接

当前开发机不是另一台干净 Windows，也不是目标 RTX A4000。随包工具提供可重复的验收步骤；只有实际运行并保留回执后，才能关闭对应门槛。

## 需要的条件

- 另一台 Windows，无 Python、Node.js、CUDA Toolkit 等开发环境，具备兼容 NVIDIA 驱动与 Edge/Chrome。实际操作者核实这一条件。
- 内网目标机：Xeon W5-2455X、64 GB RAM、RTX A4000 16 GB。它可以同时承担干净机器验收，但仍需分别记录两类证据。
- 内网真实图片与人工标注，含手机照片、中英文印刷体、中文手写和业务表格；标注不能从待评测模型输出反向生成。

## 运行方法

将完整候选 ZIP 解压到有中文和空格的路径，例如 `D:\OCR 验收\便携 工作台`。检查 ZIP 附带 SHA-256，双击启动器，保存项目、识别并导出。退出工作台后，在该电脑的管理员 PowerShell 中运行：

```powershell
$ocrBundle = 'D:\OCR 验收\便携 工作台\OfflineOCR'
$ocrEvidence = 'D:\OCR 验收证据\第一次系统禁网'
& "$ocrBundle\tools\offline_guard.exe" $ocrBundle $ocrEvidence --application
```

目录应按实际解压位置调整。证据目录必须不存在或为空。该命令以 WFP 动态规则阻断 OCR 可执行文件的外网连接，保留本机回环，实际运行四引擎；退出自动移除规则。回执必须显示 Python 运行时及原生 Winsock 外网探针被系统拒绝，并绑定当前机器与包清单。

随后从普通 PowerShell 运行干净机器验收；最后一个参数仅在操作者实际核实后填写：

```powershell
& "$ocrBundle\runtimes\service\python.exe" -B -X utf8 -I "$ocrBundle\tools\target_machine_acceptance.py" --bundle $ocrBundle --output 'D:\OCR 验收证据\干净机器' --role clean-windows --os-isolation-evidence $ocrEvidence --confirm-no-development-environment
```

在目标 A4000 上另运行：

```powershell
& "$ocrBundle\runtimes\service\python.exe" -B -X utf8 -I "$ocrBundle\tools\target_machine_acceptance.py" --bundle $ocrBundle --output 'D:\OCR 验收证据\A4000' --role a4000 --os-isolation-evidence $ocrEvidence
```

目标机流程包括完整应用、20 次加载卸载与 500 张工程队列，保存原始时间和显存采样。约 2 GB 余量检查只证明这组负载，需继续测内网真实大图。

再把同一 ZIP 解压到另一盘符的中文/空格路径，退出原实例，使用新的证据目录重复禁网与应用验收，记录两次路径、机器指纹和同一个包清单哈希。不能用开发机目录搬迁替代独立机器。

## 内网样本复核与回传

逐图记录图片哈希、类别、人工参考、选用引擎、原始输出与人工修改。报告印刷/手写 CER、实际业务关键字段的完整匹配率（写明字段定义与分母）、表格跨度/合并结构指标、失败样例、冷加载/单张/吞吐及峰值显存。保留失败和原输出，不用润色掩盖差异。

回传候选 ZIP 的 SHA-256、各 `target-machine.json`、系统禁网回执、完整工程子目录与内网复核报告。若数据不能离开内网，提供机器上执行这些步骤的访问方式或由授权操作者复核；不要把受限原图混入源码或公共交付包。

没有以上实际证据时，候选版可以交接测试，最终发布门槛仍未通过，也不满足“确认无误后关机”的条件。
