## 1. 证据分轨

| 轨道 | 要回答的问题 | 可用证据 | 不可替代的证据 |
| --- | --- | --- | --- |
| 工程 E | 协议、状态、工具与 UI 是否正确 | 合成夹具、模拟服务、故障注入、自动化浏览器、真实数据库/文件 | 真实模型任务成功率不能代替事务和故障检查 |
| 模型 M | 指定主控模型能否正确组织真实工具 | 固定模型/配置的真实调用，中文任务、完整调用轨迹 | 模拟回包、缓存重放不能计为真实模型成功 |
| 内容 Q | OCR/视觉审校是否正确 | 既有质量集与独立内容标签，单列本次回归 | “成功调用 OCR”不等于识别准确率提升 |
| 交付 R | 用户环境能否运行被测构建 | 实际便携包、离线/搬迁/目标机/迁移回执 | 开发目录通过不等于便携包通过 |

检查结果 `pass/fail/not_tested/conditional`；所有缺口有原因、影响范围和复现入口。任务的“评测报告已产出”不等于评测通过。

### 本机演示阶段与生产资格阶段

`demo_ready` 的验收对象是当前机器的实验工作区和用户即将查看的服务/UI。核对当前源码完整后端回归、前端测试与 TypeScript/Vite 构建、当前候选包的独立审计（允许明确标注 qualification limits）、短时服务/界面烟测，并抽查项目/版本范围、写操作授权、凭据不回显或入包、导出哈希/文件对应、取消与恢复不重复副作用等基本数据安全边界。若演示直接使用当前源码而非冻结候选，回执分别记载源码与包身份，不能把旧包结果套给新源码。展示时可使用模拟主控；必须显式说明来源与功能限制。当前服务的启动/页面查看结果单列，不预填通过。

`production_qualified` 是另一判定：下列完整 E/M/Q/R 证据和适用性能/目标环境条件才支持具体配置发布。真实独立主控 24×3、干净 Windows、物理断网、跨用户 DPAPI、旧版可执行程序完整回退、最终候选全量物理搬迁和生产性能门槛均移至该阶段；在本机演示时不要求执行，也不改写原有 `not_tested/not_qualified`。用户已取消新的四小时混合长轨，不安排补跑；历史 05/07/08 formal 原始失败照留，长期稳定资格不能由短烟测推断。

| --- | --- |

| FX04 修订竞争 | 同页两个结果、人工编辑 revision 变化、过期视觉/结构建议 |
| FX05 失败任务 | 可控失败/取消/暂停/中断/已成功任务；支持各崩溃窗口注入 |
| FX06 两个项目 | 相似文档名、相同页码、不同 ID；检验归属、切换及跨项目伪造 |

每份夹具保存生成种子、内容哈希、真值、预期版本/ID 映射；测试断言以稳定逻辑标签解析随机 ID。合成图不充抵真实扫描质量数据。既有工作台质量样本标明已曝光，不重新标为未见封存数据。

## 4. 真实主控评测 M

### 4.1 数据集规模与冻结

按主计划 S01—S06，每类设计 10 条中文任务，共 60 条；每类 6 条开发、4 条封存，共 36 条开发和 24 条封存。任务变体覆盖明确/含糊范围、失败重试、多轮追加、选择目标、不同页集与导出格式。封存集按任务模板和文档组分离，不能只换数字视为独立。

每条包含 intent、输入夹具、初始数据库/选择状态、允许动作、禁止动作、终态判定、必要引用/覆盖范围、可接受澄清、预算。允许多条正确工具路径，不用唯一工具轨迹评分束缚合理规划。

60 条任务内容与真值已由 P0 A03 生成冻结，位置为 build/ocr-agent-20260920-p0/fixtures-final；其合成属性、作者知晓模板与既有曝光边界见历史回执。v2 不改变划分和评分；读取/调试过的封存项需按现有 exposure 流程失效并补新批次，不靠改名恢复独立性。

### 4.2 执行与计分

每个候选主控配置在 24 条封存任务上各运行 3 次，共 72 次；重置独立测试 workspace，不能复用前次成功副作用。至少对一套实际主控配置完成验证。记录模型 ID、端点类别、协议/配置/prompt/tool schema 版本、温度、时间、token/费用可用性、每一步调用与业务结果。

评分由可执行状态断言为主：页集、任务唯一性、结果选择、导出文件、版本、引用均有确定判据。解释质量采用预先固定 rubric 并核对事实；若借助另一模型评分，明确标记辅助评分，不称人工独立标注。

供应商连接错误计入实际可用率并单列；不能悄悄排除失败只报成功率。工具恢复后重试的结果保留原失败，另开 attempt。人工/执行者介入的 run 不算无干预成功。

### 4.3 候选上线门槛

以下是拟定门槛，不是本次成绩；P0 冻结，不能在看见封存成绩后下调。

| 指标 | 门槛 | 定义 |
| --- | --- | --- |
| 封存整体任务成功 | ≥65/72 | 完成要求的工具效果、覆盖和产物；合理的必要澄清由场景脚本回应后继续 |
| 单场景成功 | 每类≥10/12 | 防止整体平均掩盖某一核心场景不可用 |
| 无需参数修正的有效工具调用 | ≥98% | 首次返回已知工具且参数满足 schema/作用域；与工具本身运行失败区分 |
| 证据引用有效 | 100% | 所有实际给出的页面/结果/格引用可解析且版本说明正确；不能靠不提供必需引用达标 |
| 高影响错误 | 0 | 越项目读取/写入、未授权外发/修改、重复副作用、过期覆盖、虚构完整成功 |

## 5. 性能与稳定性

先记录同机器、同项目、agent 关闭的基线，再测开启且空闲、只读问答、OCR 并行、外部审校并行和大规模事件五种状态。机器 CPU/GPU/RAM、包版本和数据哈希写入回执。

建议初始工程目标：不含模型/推理/文件生成的 API 调度开销 p95≤1 秒；后台任务状态变更到可见进度 p95≤2 秒；agent 等业务任务期间新增模型请求数为 0；已授权新步骤取消生效时间在本机控制层≤1 秒。超出时定位和优化，不能把供应商延迟混入本地指标后随意解释。

生产资格规模轨包括 100 页真实任务编排和 1000 页合成/冻结结果压力，两者分别标记。10 万事件测试分页/补读和内存，连续 50 次会话创建/取消/恢复后检查线程、连接、子进程与文件句柄。四小时混合长轨已由用户取消，不再列为待执行项；长期稳定资格保持未获证明，需要今后另议独立、适当的证据标准。

OCR 吞吐相对基线下降超过 5% 时调查锁、轮询和资源争用；记录重复样本与波动，不能仅一次快慢结果判定。缺少 GPU/目标机器时对应性能标 not_tested，继续其余工程。
