## 审计发现与修复

1. Windows 下轮询 JSON 与原子替换竞争可使启动进度或引擎回退报 `PermissionError`。现在同路径读写使用固定数量的锁，跨进程短暂占用有有界重试；写入使用唯一临时文件。三读线程并发替换测试和完整 62 项测试通过，真实启动与回退复验未复现原错误。
2. GUI 刚完成批次时，本地项目状态可能尚未包含最后结果。导出现在重新取服务器项目状态并检查所有选中项，下载 ZIP 经独立读取确实含两份文件。
3. 对话框忙碌时禁用当前焦点控件会使焦点移出，并让 Tabster 错误隐藏仍可见的对话框。已记录 DOM 中 `role=dialog` 与 `aria-hidden=true` 的证据；异步操作前将焦点留在对话框，操作完成后再聚焦已启用的关闭按钮。诊断复验及真实引擎包 GUI 全流程均通过。
4. 新失败恢复验收脚本误把固定样例直接传入会移动文件的导入函数。脚本已改成复制临时导入文件，样例恢复并与完整清单核对一致。原失败目录保留，修复后的实际推理记录单独保存。
5. 原生依赖 stderr 可能不是 UTF-8，已设置可见转义的解码错误处理，避免子进程诊断线程中断或输出变成空值。
6. 依赖 marker 的求值改为从被审计的嵌入式 Python 获取 Python/平台信息，避免构建解释器版本不同影响判断。六运行时重新审计通过，具体环境与闭包数一并保留。
7. PaddleOCR-VL 在不同页面形状之间保留大量闲置 allocator 缓存。十张预选复杂表格实验表明，单张完成后的 reserved 可由 10,726,492,160 字节降至 3,399,489,280 字节，而活跃张量仍为 3,087,663,104 字节；十张原始输出与基线均零差异。0.7.0rc1 在成功推理、输出转入 CPU 后执行垃圾回收和 CUDA `empty_cache()`，不改模型、精度、像素或生成参数。完整 200 张复测已完成：峰值 10759 MiB，吞吐 22.39 张/分钟，198 项成功原始输出零差异，另两项保持原失败。
8. 外部目标机验收现在检查实际 20 次循环、500 张完成记录和约 2 GB 显存余量，不能仅凭子脚本退出码宣称通过。新增测试清单与最终包清单对照，文档或工具后续变化会列出，应用、模型、运行时、配置、启动器及前端字节必须一致。
9. 健康接口残留硬编码 `0.3.0`，已改为读取统一应用版本。此修复在冻结的独立适配器评测结束后同步，由后续真实应用/GUI/禁网验收覆盖。独立推理未执行 HTTP service 模块；组件核验明确列出这个范围差别，其他推理组件仍须字节一致。
10. 最终归档发现 Windows `write_text()` 将磁盘 manifest 换成 CRLF，而 ZIP 内为 LF，造成内容相同但清单哈希不同。打包器改为向两处写入同一 UTF-8 字节序列；实际 Windows 小包回归通过。完整 ZIP 已经含正确 LF 清单，无需改动 ZIP；构建目录规范化为 ZIP 内字节后，重新生成组件绑定。回执为 `release/packaging-regression.json`。包内文档为打包前快照，本条补充位于最终源码及交付回执。

OOM 流程目前有模拟分配失败的单元测试，验证明确失败、释放、后续任务继续和原引擎重试。此项不能写成真实硬件 OOM 已测。
