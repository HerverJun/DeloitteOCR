# 架构修订候选：业务服务与明确操作

修订日期：2026-10-17。正式入口以 `release/Clear/current.json` 为准；本文描述本轮候选的实际实现，不把源码同步或候选封存等同正式切换。

HTTP、Agent 工具、手动带回和批次复用应用服务。OCR、PDF、Data、分类、取证、多模态、作业与审计业务实现位于 `application_services/operations`；原 `agent/tools` 保留工具注册和兼容导出。身份编码、执行上下文、作业观察和要求覆盖也在中立应用服务层，保持历史 canonical/digest 字节不变。

明确图片提取、单份 PDF 的指定页提取、固定 Data 算子及已有模型预测使用持久直接驱动，复用原会话、run、operation 与原生作业，不启动 Harness 或调用模型。开放分析继续由 Harness 编排。图片聊天入口只识别完整、无歧义的已登记提取命令，不用关键词截断复合目标；复杂要求和后续修订保留分析路径。

四个明确操作入口为 `POST /agent/sessions/{id}/direct/image-text`、`pdf-text`、`data-action`、`classification-predict`，完整严格模型见 `packages/contracts/direct*.py`。请求身份绑定原参数、固定输入版本、驱动和范围。恢复优先复用已提交结果与原回执；未知写入保持待核实，不自动重新提交。暂停、停止、人工接管和范围修订在下一写边界生效。

PDF 入口目前明确限制单份文件、最多 100 个 1—1000 范围内的指定页。`native/auto` 保留原文提取能力，不强制 OCR；不处理未选页。Data 只执行现有有类型算子，保留 Decimal、文本前导零、原值与行来源。分类必须显式选择既有项目和模型，不隐式训练，不把预测当作人工标签。

完成度使用 `input-requirements-v1` 派生投影，按原件、版本/哈希、操作、页及用户明确引擎要求核算。后备成功只修复匹配要求，原失败和操作父关系不改；未知回执、其它失败输入和指定引擎仍保留缺失。OCR 原文通过固定结果引用完整分页、复制及 UTF-8 TXT 交付，旧 JSON、下载与结果版本继续有效。

终态结果先提交，再发布同一作业身份的终态事件。门户断流后补齐事件并读取 `/agent/sessions/{id}/jobs`；读取失败显示“状态暂不可核实”。不变的原生观察不重复写事件。PDF 交付核对和门户使用相同页阶段归一化，不能由聊天结束推断成功。

同会话仍独占。直接操作以原生项目身份保护对象，跨 workspace 的不同 link 不能绕过同对象冲突；隐式创建和旧 link 记录保守占用整个族。不同已固定项目、不同族及私有 Data 会话可按实际冲突继续。Harness 的未知原生对象仍保守互斥；手动和批次继续依赖既有版本校验、原生队列与 GPU 所有权，本文不宣称新增锁覆盖所有写入口。

每类新驱动及对象准入写入 reader feature。旧 reader 不得打开已使用不支持驱动的数据；缺少 marker 时也扫描真实记录拒绝降级。回退关闭新请求入口，已接受任务由支持原驱动的候选恢复；需要旧版本时恢复一致性备份到新的 F 盘目录，保留原 DATA 和新记录。

API、私有 OCR worker 副本及构建均按候选身份固定；共享 Python/模型/封存程序只读。加载、推理超时分开，加载阶段不提示缩图。冷/热模型以实际 engine session 和 load timing 核验，服务已热不等于权重已热。性能测量和未达指标见本轮证据，不能将未校对 OCR 一致性称为准确率。

本机路径不引入 PostgreSQL。中央部署须另做真实 PG/outbox 资格验证；缺少环境时保持未验，不扩大多人部署声明。正式档案、人工复核和署名仍是按需审计业务，普通文字提取不强制创建正式档案。
