# Agent 流式交互与聊天工作台

用户提出目标后，Agent 按已注册工具和模型执行，读取结果并选择下一步。聊天区域持续呈现公开回答和实际工作状态，原有工具及人工操作保留。

## 对话与状态

- 模型等待期间显示状态和耗时。公开正文、`conversation_answer.content` 和 `delivery_publish.summary` 从真实 SSE 片段渐进显示；私有 thinking 和其他工具参数不展示。
- 候选文字生成结束后仍需完整协议、参数和业务结果校验，正式回答在原位置确认。交付以已核实成果回执为准。停止、失败或未知回包保留草稿并标记中断。
- 工具活动显示实际开始、恢复原操作、等待原生作业、完成或拒绝。同一调用保持同一项，不把恢复当作再次执行。
- 原生进度读取既有数据、OCR、分类、PDF、批次和取证服务。服务提供总量时展示实际计数，未知时显示阶段和耗时；读取不可用不等于任务失败。
- Markdown 支持表格、列表和代码块。HTML 不执行，代码不运行。上下文预算、环境/Skills 注入、传输方式和供应商用量收纳在诊断区域。

## 控制与阅读

输入发送后立即显示发送状态。可在聊天操作区停止后续动作或人工接管；已提交原生作业是否取消仍由其真实能力决定。返回 Agent 后继续原任务。

靠近底部时跟随新内容；向上回看时保持阅读位置，使用“回到最新”恢复跟随。切换会话保留本次页面中的阅读位置。窄屏提供任务入口和停止/接管控制。系统开启减少动画时仍完整显示文字状态。

订阅中断时显示重连状态，按持久化事件游标恢复。刷新、重连或切换会话不会重新发送模型请求或提交工具。已发送而回包未知的主控请求保留未知状态，不自动重发。

## 主控流式能力

“请求流式”是配置偏好。诊断中的 SSE/整包 JSON 来自当前实际响应；保存连接时的能力测试另外记录检测时间、公开正文和答案参数预览是否可用。

连接测试保留两轮原生工具与结果消费检查，启用流式时另做一次无业务资料的公开文字检查。上游忽略流式、只返回整包 JSON 或不支持公开正文时，会明确显示实际观察结果；原生工具能力可以独立使用。平台不会伪造逐字输出。

旧连接配置保留。历史配置没有流式探针记录时显示未检测；需要用户在连接设置重新测试才产生新的供应商能力证据。开发中的本地延迟控制器和合成资料仅用于工程验证，不代表供应商响应表现。
