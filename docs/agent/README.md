# Clear 智能审计使用说明

本机固定入口为 `F:\OCR\release\Clear\启动智能审计.cmd`，状态与停止由同目录 `product-entry.ps1` 提供。候选和共享资产由 `current.json` 登记；启动检查文件身份、数据库结构/迁移版本和记录读取能力。共享模型继续复用，工作区与所有缓存、日志、临时文件留在 F 盘。

主导航收为智能审计、审计项目、手动工具，设置为次级入口。项目只在全局选择一次；输入目标、添加资料、发送即可开始。背景、规则、计划、技能调整在可收起的任务详情中。浏览设置或平台技能目录不会自动新建项目。

人工处理使用“接管 → 手动工具 → 保存 → 选择成果版本带回”。默认显示当前任务相关成果，其它项目结果和独立原生导入按需展开。取消带回保持人工状态。原生暂停显示真实提示：人工或原因不明的暂停在原工具恢复，观察器只恢复明确冷中断的同一作业。

项目内的发现可明确选定草稿修订、证据哈希和目标正式档案转档。一个工作区允许多个正式档案；同一源证据在各档案拥有独立快照。转档保留原作者和操作人、各段文字、任务范围与背景版本，不自动生成任何人工编制/复核签名。源草稿修改不会覆盖正式快照，日常底稿下载继续直接使用。

平台默认入口是智能审计对话：描述目标，Agent 读取项目与资料，选择已注册工具和专业模型，读取实际结果，调整安排，交付发现、底稿及数据文件。沿用现有 LangGraph、操作账本和原生服务。四类 Clear 手动工具继续可用。

上下文预算、工具按需加载、可信环境和原生 Agent 技能的最新说明见 [Agent 上下文与 Skills](context-skills-20261005.md)。

聊天工作台现支持正文与答案工具参数的真实流式预览、工具开始/恢复/完成、原生任务进度、Markdown、订阅重连及阅读位置保留，见 [流式交互使用说明](streaming-ux-20261005.md)。

手机屏拍及截图的逐图 Excel ZIP、集中复核和运行中自然语言控制，见 [批量图片转 Excel](screen-batches-20261007.md)。

专用 Agent 工程候选与最终候选的验收区别、真实报告及源码/策略/前端绑定格式，见 [候选包验收证据契约](package-qualification-20261007.md)。

## 启动与数据

本机主启动文件：`F:\OCR\output\clear-automation-dev-20261002\启动平台.cmd`。统一首页：http://127.0.0.1:8879/ 。无需另找 `/agent`。

主启动文件的默认业务目录保持为 `F:\OCR\output\audit-platform-dev-20261002\workspace\M2-business-preview`。首次加载只增量建立任务、项目背景、直接证据和草稿表，保留旧批次、正式项目及人工记录，不复制或清空已有项目。

本轮预览与检查另用 `F:\OCR\output\ai-audit-product-dev-20261004\workspace`。当前 8879 若由本轮预览占用，显示的是隔离检查项目，不代表历史项目丢失。双击 `F:\OCR\output\ai-audit-product-dev-20261004\停止本轮预览.cmd`，再运行主启动文件，即可使用原业务目录。停止文件会核对进程和隔离目录，不会停止其他工作区的服务。不要同时用两个平台进程打开同一数据目录。

可显式选择工作区：

```powershell
& 'F:\OCR\output\clear-automation-dev-20261002\worktrees\platform\start-development.ps1' `
  -DevelopmentRoot 'F:\OCR\output\clear-automation-dev-20261002' `
  -Data 'F:\OCR\output\my-audit-workspace' -Port 8879
```

源码、门户、共享运行时、模型、依赖、应用数据、凭据、日志和临时文件全部位于 F 盘。启动使用已验证 Agent 依赖层及私有原生配置。共享 `program` 必须保留，无需重复复制模型。打包脚本生成的独立包用“启动智能审计.cmd”，默认使用包内 workspace；本轮候选位置见 [流式交互使用说明](streaming-ux-20261005.md)。

## 第一次使用

1. 在首页输入目标或问题，如“检查付款台账与凭证表，按供应商编号核对金额，整理差异并形成底稿草稿”。
2. 点击“添加资料”上传或选择项目资料。可直接建立轻量项目，不要求先填正式项目表。
3. 从“连接模型”或设置配置主控。支持 OpenAI Chat Completions 兼容接口及 Anthropic Messages，接口必须支持原生工具调用。可读取模型列表或手填 ID，测试后保存。
4. 发送目标，查看公开安排、工具实际进度和结果。普通讨论可直接回复，普通处理和草稿下载连续执行；影响结果的歧义才提问。
5. 在任务区、发现与底稿、成果中心继续编辑、查看来源和下载。刷新后从“最近任务”恢复，可按名称查找。

未连接模型时仍可保存目标、上传资料、填写背景和手动工作，不以固定演示冒充模型回复。开发检查使用隔离合成资料；实际会话的模型用量以会话诊断中的供应商回执为准。

凭据存入独立 Windows DPAPI 存储，不借用 OCR 视觉审校凭据，跨 Windows 用户恢复需重新填写密钥。连接探针不发送项目资料。流式默认开启，可在设置关闭；完整工具参数通过校验后才执行，未结束的流不会执行工具，私有 thinking 不显示。

## 接续与人工接管

补充目标、资料、期间或业务口径可以继续同一任务。运行中的范围修改在下一操作边界生效，已有结果保留原版本。

点击“手动接管”，打开原工具并保存修改。Agent 停止后续动作，已提交原生作业按真实能力继续或取消，已有结果保留。保存后点击“带回结果”，选择新版本并填摘要，回到同一对话发送继续要求。返回本身不暗中调用模型。

带回候选支持搜索和分页，跨页保持选择。ClearData 手动上传的同名相同文件复用可核实的项目资料身份；新文件自动登记到当前项目，带回时明确提示需要加入任务的资料，确认返回才同时加入范围。聊天、交付和任务侧栏的结果链接保留原任务，可以从工具继续返回。

没有主控也能从工具工作台独立使用 ClearData、ClearOCR、ClearClassify、ClearForensics。资料、数据核对结果和成果可“交给智能审计”。

工具内独立导入的 OCR/PDF 和已完成分类推理结果也可接回：手动接管后，在“带回结果”选择原生项目和结果，点击“核实原件并接回”，再勾选下方候选。新原件会明确列出，只有选择返回后才加入任务范围。结果可以继续转为数据输入、固定证据、生成发现/底稿和导出，原工具仍可继续编辑。

## 证据、发现和底稿

数据表/核对结果、OCR、分类、取证报告及成果可以直接固定为证据，无需伪造批次。保存实际观察、来源、哈希和版本。数据来源读取固定历史表格；OCR/分类发现可查看保存时的快照及原资料。

固定证据有独立的类型引用。分类人工标签等原生结果更新后，Agent 仍可读取保存时的事实、描述证据、生成底稿和交付，所有读取继续验证当前项目、原资料内容与授权范围，并显示来源更新提示。Agent 可以根据目标选择保留历史事实或重新绑定当前结果。

发现分别记录事实、解释、口径、待补信息、建议及证据。有事实必须关联实际证据。Agent 来源记录会话、执行、模型和连接版本；人工编辑不自动产生正式署名。

底稿包含五个文件：`workpaper.md`、可编辑 `workpaper.html`、`findings.json`、`evidence.json`、`sources.csv`。CSV 记录来源位置；业务数据附件继续由 ClearData 导出。普通草稿和下载无需先编制或复核，正式人工署名仍在原页面明确操作。

源结果、任务范围、背景、口径、目标或发现修订后，受影响内容显示需更新或历史版本。旧文件保留固定内容，新请求生成新成果。发布中断后重试同一请求继续原快照，不混入中断之后的新发现。

调用对象版本发生冲突时，工具返回可读取的错误，Agent 可以查询当前版本后修订；执行身份或连接竞争发生在调度层时，本轮明确终止为失败，已有成果保留。人工接管和停止仍阻断迟到动作。当前调用修复记录见 [invocation-fixes-20261005.md](invocation-fixes-20261005.md)。

## 当前范围

- 数据：CSV/XLSX/Parquet 探查、清洗、精确核对、重复候选、类型化区间筛选、分组计数和 Decimal 金额合计。保留全部来源行；未知金额使合计报错，不静默按零计入。
- 资料/规则：原文按字符分页、PDF 明确页码读取，OCR 文字及单元格可分页；原文及已有 OCR 文字匹配返回文件、页/行和版本，支持文件、文件内命中和 OCR 结果接续。读取用户项目口径；每次最多读取 200 文件、单文件 8 MB，尚无向量语义检索。
- OCR/PDF：真实引擎和显式页集，保留原件的旋转/对比度处理、同图多引擎 CPU 融合、冲突事项、文字/单元格/标题编辑、显式版本采用和历史。专业视觉模型通过原生连接调用，建议可继续显式编辑采用。只读取实际返回结构，不猜造表格。
- 分类：固定资料导入、读取/保存标注、发布不可变训练版本、调用原生训练器、等待并读取实际模型、活动模型条件切换和模型包导出。预测、Agent 标注、人工类别和事项处置分别表达，可以继续选择资料子集交给 OCR。
- 取证：metadata、noise、frequency、jpeg、jpeg_grid、copy_move 六项既有算法，呈现线索和限制，不自动裁定真伪。
- 结果桥：明确顺序的完整结构表可以在原值表头和列数相同、无合并单元格时拼接，保存逐行/单元格来源，再转为数据输入。
- 平台业务：资料标签、任务目标、项目背景；模板/批次执行、等待、读取、控制、处置、历史和导出；正式项目/程序/发现草稿的创建、修订与历史，以及待办查询定位。AI 作者明确，人工编制复核署名仍独立操作。

尚未增加 Word/PDF 底稿导出、任意扫描票据字段抽取、通用跨页拼表或子 Agent 调度。专业模型按本地安装与项目状态提供。

当前实际注册 110 个工具，包括 105 个业务工具、4 个技能工具和 1 个完整会话历史读取工具。新增业务能力、恢复机制、手动接回方式和工程验证见 [coverage-completion-20261005.md](coverage-completion-20261005.md)；上下文、可信环境与技能宿主见 [context-skills-20261005.md](context-skills-20261005.md)。可直接提出“读取已标注资料并训练分类模型，然后把凭证子集交给 OCR”或“接回工具内已处理结果，保留原文来源，与付款台账核对并整理底稿”；Agent 发现工具后调用已有服务，按实际模型与结果决定后续步骤。

## 备份与版本

关闭要备份的平台及相关原生服务后冷备，不停止其他会话的服务。平台和原生 OCR 用 `scripts/backup_workspace.py create/verify/restore`；分类用既有 `image_platform.backup`。平台备份包含操作库/checkpoint、派生来源、任务、背景、证据、发现和托管底稿。

恢复到新的 F 盘目录后用相应版本程序打开，保留原目录和备份。不要用旧程序直接打开新增表后的数据库作为回退。关闭 Agent 是功能回退，程序/数据回退需相应备份。

[baseline.md](baseline.md) 保留历史工程基线，其中旧 PA08/PA16 计分要求不作为本阶段产品开发前置。实际交付与检查见 [product-delivery-20261004.md](product-delivery-20261004.md)。
