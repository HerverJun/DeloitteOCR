# TableFormer 可选接入与 local-v3：开发和验收

2026-09-15 启动的下一轮实验。接续 [扩大实验的开发顺序](tableformer-expanded-20260914-quality.md)，完成网格标签契约、可选择的原始几何提供方、邻居锚点对应和公开 PDF 工程开发。默认仍为 Paddle + `local-v2`，TableFormer raw 和 `local-v3` 是实验选项。

**新封存测试确认覆盖提升：控制轨 72.57% → 77.50%，实际采用结构轨 65.12% → 69.71%。工程开发完成，生产质量门槛未通过。** 重复值改善最明显，实际合并格覆盖仍只有 43.75%；200ms 预算导致少量既有正确定位丢失，原始回执和失败分母全部保留。

## 已完成的产品接入

- 完整格定位以 `full_grid` 为正式评测边界，和 `text_extent`、`pdf_cell_extent` 分开。标签只由独立行列、跨度和图像转换生成，旧报告保持原样。
- 「表格定位与人工绑定 · 实验性」提供 Paddle、TableFormer raw、RapidTable 选择，以及 `local-v2` / `local-v3` 对应方式。API、任务快照、模型进程、状态读取和前端已接通；人工绑定优先。
- TableFormer raw 保留原始编号、跨度、`upstream.json`、来源哈希及裁剪坐标转换；继续复用共享页面检测与 OCR。候选推理不修改采用文字，不新增文字识别票。
- 缓存区分提供方、模型、图像、共享 OCR 与对应策略。修订后可纯 CPU 重放；读取时验证候选和上游原始产物。模型和依赖离线校验，缺失时明确失败。
- `local-v3` 在已有唯一文字锚点基础上加入独立邻居和双侧夹定约束，保留到初始锚点的无环来源。重复值仍需独立行列支持；并列、复用、顺序冲突和非连续并集继续拒绝，空格不作为新文字锚点。

token 包含率 0.8、margin 0.2、其他候选重合上限 0.2、表身份 margin 0.2、单表 200ms 预算和原分组上限未降低。没有缩小模型框、增加 OCR、放宽字符比较或按测试样本挑选提供方。

## 标签及测试边界

开发集 80 表、8,488 格与官方 PubTables 结构图像 XML 全部交叉校验通过，最大边界差 0.9943 像素，小于 2 像素转换舍入容差。该容差只用于标签交叉检查；评分仍要求目标身份正确、没有并列且 polygon IoU≥0.5。合并格、空格、宽列间距和有框线图像已经 Codex 视觉抽查，回执明确标注未进行人工签核。

正式配置见 `config/geometry-evaluation-v3.json`。完整格覆盖要求 C/N≥90%，错位率 W/A≤1%，提供框达标率 C/A≥95%；缺失输出、推理失败和不能建立独立参考身份的目标均保留在 N 中。真实结果轨另报告 C/(A+额外或重复输出)。这些额外输出包含无法建立参考身份的采用格，不能将其都解释成错误定位框。

新测试从 140 个新合格候选按固定 seed 选出 120 个文档、11,278 格，含重复值 3,164 格、空格 718 格和合并格 352 格，分组可能重叠。准备时已排除历史 100 表、v2 全部 320 个已准备文档、扩大实验全部 160 个已准备文档和既有排除记录，并过滤图像及文字近重复。网格标签在推理前构造并单独封存；代码、策略、采用规则、开发/验证报告和测试输入均在推理前锁定。

控制轨使用固定 reference edit，用于比较对应器；真实结果轨固定采用 PaddleOCR-VL 实际输出，不按样本选择引擎。参考身份关联只使用文字和跨度的唯一最优顺序匹配，不读取预测框或 GT 框。两轨都以表格裁剪为输入；它们不能单独证明整页检测召回率。独立性是相对本项目开发曝光而言，不保证上游模型预训练未见过公开文档。本轮测试评分后，这批文档也不再属于后续开发的新测试。

## 开发与验证

两种对应器使用相同 TableFormer raw 候选。以下都采用预定完整网格标签，C 为正确格数、A 为提供完整框的格数、W 为独立评分错位数。

| 划分 | v2 覆盖 C/N | v3 覆盖 C/N | v3 提供框达标率 C/A | v2 → v3 错位数 | 新增正确净数 |
|---|---:|---:|---:|---:|---:|
| 开发 80 表 / 8,488 格 | 74.18% | **78.32%** | 99.79%（6,648/6,662） | 4 → 4 | +352 |
| 验证 60 表 / 5,930 格 | 66.17% | **72.19%** | 99.58%（4,281/4,299） | 3 → 4 | +357 |

| 分组 | 开发 v2 → v3 覆盖 | 验证 v2 → v3 覆盖 |
|---|---:|---:|
| 重复值 | 64.76% → **76.77%** | 50.50% → **65.73%** |
| 合并格 | 46.82% → **48.73%** | 52.23% → **54.46%** |
| 空格 | 43.54% → **54.43%** | 70.16% → **75.54%** |

验证新增错位是 `PMC2557016_table_0` 的零基 row=17、column=4 空格：自身 IoU=0.17918，其他格最大 IoU=0.43694。不能把覆盖提升描述成没有风险代价；验证后未针对该样本修改算法或阈值。CPU 重放 P95：开发 v2/v3 为 92.52/93.35ms，验证为 77.99/113.27ms，包含产物读取、提供方转换和对应，不含模型推理。

## 新测试结果：120 文档、11,278 格

共享 PP-OCR、Paddle、RapidTable、TableFormer 和实际 PaddleOCR-VL 采用结构各 120/120 次成功；两轨四方法共 960 个对应产物完整。开发、验证、新测试控制和真实结果四份评分均为 `complete=true`。封存源码、配置与各阶段产物哈希均通过检查。

| 方法 | 控制轨覆盖 C/N | 控制轨提供框达标率 C/A | 控制轨错位 W/A | 真实结果覆盖 C/N |
|---|---:|---:|---:|---:|
| Paddle-local-v2 | 15.05%（1,697 格） | 95.82% | 13/1,771 = 0.734% | 12.70%（1,432 格） |
| RapidTable-local-v2 | 13.65%（1,539 格） | 64.91% | 7/2,371 = 0.295% | 11.62%（1,311 格） |
| TableFormer-local-v2 | 72.57%（8,184 格） | 99.91% | 0/8,191 | 65.12%（7,344 格） |
| **TableFormer-local-v3** | **77.50%（8,741 格）** | **99.91%** | **0/8,749** | **69.71%（7,862 格）** |

控制轨新增正确 565 格、失去 8 格，净增 **557 格 / 4.94 个百分点**；成对文档 bootstrap 95% 区间为 **3.20–7.00 个百分点**。真实结果轨新增正确 534 格、失去 16 格，净增 **518 格 / 4.59 个百分点**，区间 **3.01–6.48 个百分点**。这些比较使用同一批目标、同一候选和共享 OCR，没有跨测试集直接相减。

v3 控制轨覆盖的文档 bootstrap 95% 区间为 73.81%–80.40%，逐表平均覆盖 75.67%；120/120 表至少有一格正确，30 表达到 90% 覆盖。真实结果轨区间为 65.15%–73.40%，逐表平均 66.21%；119/120 文档至少有一格正确，16 个文档达到 90% 覆盖。两轨样本中未观察到错位，不能据此认定真实错位风险为零；验证集的新增空格错位仍是有效反例。

实际采用结构产生 121 个表、11,598 格，其中 119 个裁剪产生单表，1 个产生两表。独立参考身份审计有 **1,734 个参考目标无可关联输出**，另有 **2,054 个采用输出无法关联或属于额外输出**。评分器沿用的 `inference_failed` 名称在这里表示参考目标没有对应记录，并非 1,734 次模型调用失败；本轮全部模型调用均成功。这些目标没有从分母删除。

| 方法 | 真实结果提供框 A | 错位 W | 提供框达标率 C/A | 含额外输出的 C/(A+2,054) |
|---|---:|---:|---:|---:|
| Paddle-local-v2 | 1,499 | 8 | 95.53% | 40.30% |
| RapidTable-local-v2 | 2,026 | 4 | 64.71% | 32.13% |
| TableFormer-local-v2 | 7,349 | 0 | 99.93% | 78.10% |
| **TableFormer-local-v3** | **7,867** | **0** | **99.94%** | **79.25%** |

v3 对实际采用格共提供 8,103 个完整框，其中 236 个属于不能关联参考身份的输出。额外输出分母同时保留了只回退到文字/区域/图像的采用格，所以最后一列是预定的严格输出指标，不能把它解释成全部 8,103 个定位框的直接几何精度。高 C/A 也不能掩盖未关联结构和低总体覆盖。

## 新测试分组及剩余失败

| 分组 | 目标格 | 控制 v2 → v3 覆盖 | 真实结果 v2 → v3 覆盖 |
|---|---:|---:|---:|
| 重复值 | 3,164 | 59.89% → **76.74%** | 57.30% → **72.98%** |
| 空格 | 718 | 56.27% → **60.03%** | 56.55% → **60.31%** |
| 合并格 | 352 | 66.76% → **68.47%** | 43.75% → **43.75%** |

真实合并格没有改善，且 153/352 个目标没有可关联采用输出，说明采用结构和跨度错误仍是主要限制之一。邻居规则主要解决重复值歧义，没有解决所有局部缺锚点类型。

以下互斥结果分别加总为 11,278 个目标；“无参考输出”和“超时”从历史评分器的同一个 `inference` 大类中拆开解释。

| TableFormer-v3 结果 | 控制轨 | 真实结果轨 |
|---|---:|---:|
| 正确定位 | 8,741 | 7,862 |
| 提供框边界不达标 | 8 | 5 |
| 错位 / 身份并列 / 非法几何 | 0 | 0 |
| 无可关联参考输出 | 0 | 1,734 |
| 文字锚点拒绝 | 1,007 | 751 |
| 局部对应拒绝 | 1,504 | 900 |
| 对应预算超时 | 18 | 26 |

控制轨仍有 720 格重复值歧义、287 格空格缺锚点、1,476 格无局部锚点和 28 格顺序冲突；真实结果对应为 587、164、865、35 格。原因是首个拒绝阶段，并不排除同时存在其他结构问题。

控制轨丢失的 8 个既有正确格全部来自 `PMC5663128_table_3` 超时；真实轨另外在 `PMC5960211_table_1` 丢失 8 格。阈值与预算未改，没有重跑挑选更好的计时结果。这说明 v3 当前并非逐格单调改善：邻居搜索的少量成本会影响接近预算上限的表。

## 推理及对应成本

本机 RTX 4070 Ti SUPER，GPU 阶段串行，RapidTable 使用 ONNX CPU。以下均为新测试 120 项；冷加载单独保留在 audit，未混入分位数。各阶段计时边界不同，不能相加当作整份 PDF 端到端耗时。

| 阶段与计时范围 | 中位数 | P95 |
|---|---:|---:|
| 共享 PP-OCR，逐项墙钟 | 0.579s | 1.000s |
| Paddle 候选，内部推理 | 0.172s | 0.365s |
| RapidTable 候选，内部推理 | 0.117s | 0.470s |
| TableFormer 候选，内部推理 | 0.493s | 1.047s |
| 实际 PaddleOCR-VL 采用结构，逐项墙钟 | 9.709s | 20.350s |
| 控制轨 TableFormer-v2，CPU 重放 | 15.65ms | 73.81ms |
| 控制轨 TableFormer-v3，CPU 重放 | 18.14ms | 70.19ms |

| 真实轨 TableFormer-v3，CPU 重放 | 18.53ms | 73.83ms |

P95 低于 200ms 并不表示每表都未超时；上述超时目标照常计入结果。产品接入的模型加载、候选复用和纯 CPU 修订重放由真实队列回执验证，未把不同路线的冷启动时长混入匹配性能比较。

精简证据：`audit/tableformer-next-20260915/`。PDF、图像、逐格模型输出、评分和封存标签：`build/tableformer-next-20260915/`。运行命令和来源固定方式见 [复现与使用](tableformer-next-20260915-reproduction.md)。
