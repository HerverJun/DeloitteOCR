# ADR 0001: Versioned platform/adapter boundary

Status: accepted for protocol v1.0, 2026-09-25. The routes describe the target adapter protocol; implementing the services is assigned to later tasks.

## Ownership and trust

The portal calls `/api/platform/v1`; adapters retain the two applications' native APIs and translate their statuses. The platform owns workspace links, asset identities, immutable asset-set manifests, cross-application handoff intentions, job references, artifact identities and resource grants. OCR and classification own their project data and native job state. A platform workspace may link multiple projects of the same application; a name or coincident ID never establishes identity. The tabular workbench remains a separate module.

`AppManifest` is declarative. Only a trusted installation record, outside this wire contract, can contain executable, working directory, bundle hash, permitted arguments and proxy target. Never treat an uploaded manifest, open context or asset locator as a disk path or launch instruction. `OpenContext` is issued after server-side authorization, is bound to app instance and link, expires, and permits only simple internal routes. Credentials are not transmitted through it. The application handshake must verify identity; a discovered process is not owned and must not be stopped by the platform.

## Single source and versioning

`packages/contracts/models.py` is the authoritative strict Pydantic 2 wire definition. Run `python -m packages.contracts.generate` to create the versioned `*.schema.json` files, `adapter.openapi.json`, `types.generated.ts`, and synthetic `examples/*.json`; `--check` fails when any generated artifact drifts. The contract suite verifies generated equality, component references and valid/invalid examples. The generated TypeScript file stays in `packages/contracts/`, where the portal can import it when its integration task begins. It does not define runtime semantics and should not be copied into an independent UI state model. Unsupported JSON Schema shapes make generation fail instead of silently emitting `any`. The nested `packages/contracts/pyproject.toml` builds an independent `workbench-contracts` wheel containing Python models and schema/TS resources under the `packages.contracts` namespace. Since the platform root project packages only `src`, distribution must install this wheel alongside the platform wheel and check compatible versions. Repository-root imports alone do not prove a packaged runtime; T004 builds and imports the separate wheel, and the later distribution task must bundle it with the platform.

Every object carries required `schema_version: "1.0"`; unknown fields are rejected and integer values cannot be booleans. Breaking changes to status meaning, coordinate basis, amount representation, permission, handoff idempotency or error behavior require a new schema version and explicit compatibility mapping. A consumer rejects future versions it cannot understand, especially for writes. Compatible display additions still require a generator/test update. The OpenAPI document is a protocol specification, not a claim that the endpoints are already running.

The v1.0 native-ID compatibility correction accepts a leading digit only for `ModuleProjectLink.module_project_id`, `JobRef.native_job_id`, and the receiving application's `HandoffItem.target_asset_id`. OCR's actual `src/ocr_workbench/store.py` `uid()` returns `uuid.uuid4().hex`, whose first character can be a digit; classification's `src/image_platform/store.py` `uid(prefix)` returns a letter-prefixed UUID fragment. Native identifiers remain opaque and are stored unchanged. The corrected `NativeId` still permits only 1–64 ASCII letters/digits/underscore/hyphen, forbidding paths, URLs, whitespace and empty values. Platform-generated IDs retain the stricter first-letter `Id` pattern. This expands the accepted range for real existing native identities without changing any previously valid payload or its meaning, so the wire schema remains 1.0; generated schema/OpenAPI/TypeScript and positive/negative examples are regenerated together. It does not assert that every application ID format is known; a future incompatible format needs explicit protocol review.

The models validate HTTP JSON with `model_validate_json`, so a UTC timestamp remains a JSON string and must match a real calendar instant ending in `Z`. `DecimalValue` carries up to 18 integer and 6 fractional digits as a decimal string and a three-letter currency, never a JSON float or JavaScript Number. `size_bytes` has a separate nonnegative JavaScript-safe integer bound (`2^53-1`); item counts have a smaller operational bound. IDs reject path separators, drive-letter paths and URL punctuation.

## Structure versus persisted semantics

Schema validates shape, enums and bounds. Model validators additionally check relationships inside one payload: count conservation, completed/partial job and handoff states, asset-to-locator identity, box transform identity, grant time ordering and artifact input identity. General JSON Schema cannot fully express those conditional checks; consumers must call the strict wire model, not merely accept a schema-only validation pass.

`semantics.py` defines checks requiring trusted current state: workspace/link/object access and expiry, manifest capability plus job control status and sequence, expected revision, list snapshot, asset-set manifest hash, idempotency payload identity, and resource generation/owner reconciliation. These checks cannot be inferred from a standalone JSON document. An adapter must check them in the same persistence transaction or guarded operation as its mutation. `HandoffLedger` is a conformance reference, not production durable storage; a later implementation must persist the request ID, normalized semantic hash and operation ID before executing imports. A repeated same request returns that operation and its per-item state, a changed payload conflicts, and an unseen status lookup returns `NOT_FOUND`. A lost response triggers status lookup, not a new request. Unknown submission state remains unknown until reconciled; a partial import preserves imported item mappings and resumes pending work. Terminal handoff states contain no pending items. Cross-database atomicity and exactly-once compute are not promised.

Page queries cap `limit` at 200 and carry a cursor and optional snapshot revision. Responses carry `items`, `next_cursor` and `snapshot_revision`. The store must pin a snapshot across pages; if it cannot serve the supplied revision, return `SNAPSHOT_EXPIRED` rather than mixing versions. A fixed job total equals succeeded + failed + cancelled + pending. An unknown total is null and cannot produce a fabricated progress percentage. Capability presence alone does not authorize a control: the current job state and event sequence must also match. A cancellation request is not terminal until the native worker confirms cessation.

The local workspace service adds `WorkspacePage` and `WorkspaceCreate` to the existing 1.0 wire without changing `Workspace`. Its ordered list is read from one SQLite query; a digest of the complete serialized list becomes a positive JavaScript-safe snapshot revision. A subsequent page checks that revision against current content and returns `SNAPSHOT_EXPIRED` if changed. This is a bounded read for the present local ledger, not a claim of persistent historical snapshots. The database path comes only from trusted startup configuration. Absent configuration reports service unavailable. Reads reject non-loopback Host values to prevent DNS rebinding of workspace names; writes additionally require an exactly matching HTTP Origin, strict JSON and a bounded body. The standalone portal may show an unselected context and inspect applications without first creating a workspace. Portal query keys include workspace and application identity, and use abort signals for superseded queries; inactive pages do not invent cross-application results.

The portal's `?workspace=` URL selection is a local navigation context only. `OpenContext.return_route` deliberately permits a simple path and excludes query parameters. T015/T016 integration must retain and restore selected workspace through a separately authorized server-side context or canonical simple route; it must not widen `return_route` or smuggle the query string into that field.

## Locator and artifact basis

Every locator binds asset ID, revision and byte hash. Page, table, row and column numbers are **1-based**; row number means original source row, never a filtered UI row. A table locator identifies exactly one PDF page or named worksheet and a 1-based table index. Structured row results must preserve stable row IDs and the original sheet/row in their workbench-specific protocol. A region with exact or approximate precision requires a finite box, image version, coordinate space and transform revision; normalized coordinates stay within `[0,1]`. Without reliable transformed geometry, emit `page_only` with a page and no box/transform identity, or `unknown` without a claim of coordinates. A rotated/cropped box cannot be reused in another image version. `Artifact` availability is explicit: failed download integrity checks report an error, never silently regenerate under the same artifact ID.

Errors are fixed code, message, retryable, request ID and bounded details. In particular, Pydantic `ValidationError` text includes untrusted input and must never be serialized directly. `public_validation_error` emits a fixed message and empty details; other contract errors use fixed safe text. Implementations must not put credentials, original source excerpts or arbitrary paths in error details or logs. The error code matrix in `contracts.md` remains authoritative for retry policy; `SUBMISSION_UNKNOWN` permits status queries only, and `RESOURCE_BUSY` waits on queued resource events.
