# 首次完整校验与日常快速启动验证

实施时间：2026-09-12 至 2026-09-13（香港时间）。现用便携目录：`E:\OCR-fusion-20260912\bundle`。

本项实现首次、安装更新和迁移目录后的完整校验，以及成功记录有效时的日常快速启动。按用户最后指示，最终实际验证范围仅为启动；识别、融合、校对和导出的完整功能实测已停止，本报告不对这些功能作新的通过结论。本项完成不等于原多引擎融合与快速校对开发计划的所有范围均已完成，也不增加人工验收门槛。

## 启动行为

普通入口为 `启动工作台.cmd`，默认自动选择校验方式。首次校验前显示：

> 首次启动需要校验离线模型和运行文件，所需时间较长，请耐心等待。校验完成后将自动继续启动工作台，之后日常启动会更快。

安装清单更新后显示：

> 检测到应用版本更新，需要重新完整校验，所需时间较长，请耐心等待。校验完成后将自动继续启动。

说明文字与阶段进度使用独立控件；校验期间说明保持可见，进度可更新为“正在校验离线文件：12,500 / 65,209”。没有新增确认按钮或固定等待时长承诺，校验成功后自动继续启动。失败时显示具体原因。

成功记录保存在 `%LOCALAPPDATA%\OfflineOCR\Verification`，由规范安装路径、`manifest.json` 内容摘要和规则版本识别，与项目目录分离。缺失、损坏、未完成、规则变化和首次启用识别会触发重新检查；完整记录覆盖仅校对模式，反向不能复用。没有周期性重扫。

完整检查前作废旧记录，使用安装目录级跨进程锁串行协调；只有检查成功且清单前后一致，才原子写入成功记录。保存成功记录失败时允许已通过检查的启动继续，并提示下次重验。缓存目录不可用时走完整检查。日常路径只读清单、检查必要入口与磁盘空间；不遍历离线目录、不读模型权重、不启动独立依赖探针。GPU 和模型的实际加载错误仍由识别任务报告，保留失败与重试机制。

外部引擎包在启用、升级、回退时继续完整检查并记录成功版本；正常启动按包清单身份复用，变化或无有效记录时只检查相关包。主体包检查成功后外部包失败，不会使下次重扫主体。项目清理、会话令牌和识别算法未在本项调整。

需要排查文件损坏时，退出托盘中的工作台，再双击 `完整校验并启动.cmd`，或给启动器传入 `--verify-startup`。服务支持 `--startup-check auto|full`，原 `--verify-startup` 始终优先强制完整检查。开发服务未传校验参数时保留原有跳过行为。`ocr.cmd verify` 始终逐文件校验。详细操作见 [工作台使用说明](工作台使用说明.md)。
