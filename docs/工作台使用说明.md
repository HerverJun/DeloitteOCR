# DeloitteOCR 工作台使用说明

## 打开与退出

将完整 ZIP 解压到本地目录，双击「启动工作台.cmd」。首次启动、升级或迁移安装目录后，会完整校验离线文件、驱动、GPU/显存和运行库。首次开始前，窗口显示：“首次启动需要校验离线模型和运行文件，所需时间较长，请耐心等待。校验完成后将自动继续启动工作台，之后日常启动会更快。”升级时会说明版本更新需要重新校验；说明文字在校验期间保持可见，另行显示阶段和文件进度。无需确认，通过后自动继续启动。

日常启动显示“正在快速启动工作台…”，复用成功记录，只核对版本清单、必要入口和项目磁盘空间，不扫描模型或逐个运行引擎依赖探针。记录存放在 `%LOCALAPPDATA%\OfflineOCR\Verification`，切换项目可以复用；记录缺失、损坏或校验规则更新时重新完整检查，不设置定期重扫。开始识别时才加载模型，不需要联网下载；GPU 或模型加载失败由任务提示，修复原因后可重试。每次启动分配本机端口和会话凭证，外部网站无法调用识别接口。

需要排查文件损坏时，先从托盘退出工作台，再双击「完整校验并启动.cmd」，或运行 `launcher\OfflineOCRLauncher.exe --verify-startup`。`ocr.cmd verify` 始终逐文件校验。服务命令行支持 `--startup-check auto|full`，原 `--verify-startup` 仍强制完整检查。仅校对模式可复用完整记录，仅校对记录不能用于启用识别。日常快速启动不会发现清单未变化时所有文件内容的损坏，应按需使用完整校验入口。

项目默认保存于 `%LOCALAPPDATA%\OfflineOCR\Workspace`。关闭浏览器后，后台和队列继续运行。系统托盘「DeloitteOCR · 离线 OCR 工作台」菜单可打开工作台、查看状态、打开项目目录和日志、退出。关闭状态窗口会隐藏到托盘。只有退出工作台才结束后台。不要仅删除应用目录来清理项目。

如果旧页面显示“工作台连接已失效”，从系统托盘重新打开工作台，或重新运行「启动工作台.cmd」。页面会接收新启动链接并恢复连接，当前校对草稿保留；也可点击「重新连接」重试。无需手工输入会话凭证。

需要指定独立项目数据目录时，可运行 `launcher\OfflineOCRLauncher.exe --data "D:\我的 OCR 项目"`。同一数据目录只允许一个启动器实例；四引擎共用单 GPU 锁。

新版本提供 `launcher\OfflineOCRLauncher.exe --review-only`，可在 GPU 或引擎不可用时打开已有项目进行校对、导出及普通图像处理；识别、区域重识别、去弯曲和引擎启用被禁用。该模式仍校验核心文件和 service 依赖，不会执行被跳过的引擎。这是本轮源码新增能力，需要重新构建后随包交付。

## 识别、版本与对比

1. 新建项目，导入文件、整个文件夹，或将图片/文件夹拖入界面。支持 JPG、PNG、BMP、单页 TIFF、WebP、HEIC/HEIF；损坏图片、超过 8000 万像素或 128 MB 的图片会明确提示。多页图片须先拆页。
2. 选择「照片文字」「手写」「表格」或「模型对比」。默认模型是操作预设，不代表准确率排名。PP-OCRv6 提供文字与坐标，不生成结构化表格。
3. 可缩放、拖动、旋转、裁剪、增强对比度，或按左上、右上、右下、左下选取透视四角并拖动调整，也可在「坐标输入与微调」直接输入边界或角点。方向键微调 1 像素，Shift+方向键微调 10 像素，Escape 取消。去弯曲使用随包 UVDoc，作为 GPU 队列任务执行。处理生成新版本，原文件和哈希始终保留。「查看原图」和版本选择器用于前后对照。
4. 区域重识别会保存所框选区域为新版本，再使用当前所选引擎识别。不同版本的坐标不会叠加混用；结果提示「另一图像版本」时可点击定位。
5. 模型对比默认按同一图像版本与同一批次分组，显示来源和处理条件；可以选择基准，切换原始识别/已保存校对内容，查看对齐文字及单元格、行列、合并差异。下拉切换与队列「查看」只改变预览；只有明确「采用此预览」或「采用结果」才改变批量导出的采用值。文字区域列表可定位原图；没有坐标或分数的区域显示未知，不生成虚构坐标或置信度。

## 校对与导出

文字支持编辑、查找、复制；结构化表格支持单元格编辑、标题、行列增删、合并与拆分。按住 Shift 点击两个单元格，或 Shift+方向键选择矩形。表格设置内可以新建/删除整表、粘贴 TSV 区域，前导零和长编号保留为文字；删除结构表保留文字视图的原文，且可撤销。跨越已有合并单元格时须完整选择。合并保留被选单元格文字，拆分后文字保留在左上单元格。

编辑自动保存，切换项目、图片、识别结果和导出前会先保存。撤销/重做按保存的编辑历史进行；短时间连续输入会合并为一次保存。保存失败时可重试保存或下载 JSON 草稿副本。多窗口编辑冲突会拒绝过期写入；「放弃本次修改并重新加载」须确认，且仅在读取成功后替换草稿，读取失败保留修改及离开保护。已有结果加载失败会有限自动重试，也可「重试加载」，无需重跑 OCR。原始识别 JSON 与人工校对独立保存。

TXT/Markdown 使用校对文字及校对表格，JSON 同时包含原始结果与人工修改。Excel 将各表放入独立工作表，保留合并、空格、前导零和长编号，全部单元格按文本写出，不推断公式。没有结构化表格的结果不能导出 XLSX。导出范围可选当前预览、所选图片采用结果或整个项目采用结果。即使当前图片未识别，也可从「导出所选」导出其他图片。选择批量范围后，默认每张图片生成独立文件，多张打包为 ZIP；每张图片中的多个表分别放入其工作簿的工作表。需要合并时再勾选「汇总为一个工作簿」。导出在同一个数据库快照中固定内容、revision 与来源，再生成文件；Excel 附「来源索引」，批量 Excel ZIP 另附 sources.json。临时文件写在项目磁盘，下载结束自动清理。

复核状态与识别任务分开，分为「待校对 / 已确认 / 有疑问」。确认绑定当前图像版本、采用结果及校对 revision；更改采用、切换版本或修改内容后须重新确认。资料栏可按复核状态筛选，复核操作可跳转下一张待校对，导出可限定「仅导出已确认结果」。

模型表格解析或附带 Excel 失败时，可用文字与原始 JSON 仍可打开，界面显示格式提示；先导出 TXT/JSON 或人工修复表格，再尝试 Excel。文字及表格的待核对阈值仅使用当前引擎实际返回的分数，不可当作跨引擎统一准确率。

## 队列与恢复

模型按组顺序处理，GPU 同时只运行一个引擎。暂停等待项不会中断正在处理的图片；需要中断当前项时点击取消。失败或已取消项可重试，已完成项不会重做。退出或异常终止后，原来正在运行的任务标为等待继续，原来排队的任务暂停，用户手动继续后才运行。失败、暂停和取消的当前图片直接提供重试或继续入口。临时存储故障会有限退避；持续故障显示队列异常并暂停工作线程，处理原因后点击「重试恢复队列」，未完成项再手动继续。正常批次结束且无异常时队列自动收成摘要。

在「批次预处理」选择保留图像、增强对比度、旋转或组合预设。创建批次时固定图像版本、预处理参数和引擎包版本；之后切换引擎包不改变旧任务。处理后的版本可与原图对照。图像解码最多同时进行两项，GPU 识别串行执行。显存不足会明确记录失败并释放引擎，可在释放显存后重试；不会自动降低精度。

## 项目空间

左栏「项目占用与清理」显示原图、处理版本、任务输出、缩略图、数据库内容和压缩后的完整撤销历史占用，并解释共享数据库及磁盘剩余空间。磁盘低于 2 GB 时提示处理，历史不会自动丢弃。「审查工作区未登记文件」可扫描因强制退出遗留的图片暂存或未引用文件；只有选择后才隔离，保留原路径恢复清单。先暂停或取消任务，并等待当前项退出，再输入完整项目名称确认删除。清理永久删除该项目的文件、结果及人工校对，操作前先导出或备份。其他项目、共享模型和诊断日志保留。文件或数据库操作失败时恢复原文件；已提交删除但未释放的文件在下次启动继续清理。

## 离线引擎包

「引擎管理」导入完整 ZIP，内容须包括模型权重、独立运行时、适配器、配置、依赖锁和 SHA-256 清单。暂存阶段只校验并解压，不执行包内代码。核对来源、名称、版本和哈希后点击「启用此引擎包」，系统再次校验，并实际检查依赖和模型识别，然后切换。哈希只能证明内容一致，不能证明发布者可信。

启用前须等待当前识别结束，可先暂停等待任务。新任务使用启用版本；已有任务、历史结果和人工校对继续关联原版本。版本下拉框可切回随应用内置版本或已安装版本。旧版本保留，不会因回退被删除。完整包需要同时容纳 ZIP、暂存文件和保留版本的磁盘空间；不应手工删除仍有关联任务的版本目录。

启用、升级和回退仍执行引擎包完整校验，成功后记录版本。正常启动只核对已启用包的清单身份；相关记录缺失或清单变化时，只重新检查该引擎包。

## 验收范围

本机专项证据包括真实四引擎闭环、20 次加载卸载与 500 张合成压力样例，后者用于工程稳定性。公开真实图片的区域评测、目标 A4000、另一台无开发环境 Windows 和内网样本的状态以《最终阶段验收矩阵》为准；本机数据不替代目标机结论。

## 数据库升级与回退

数据库现为 v7。首次打开旧工作区时先在 `database-backups` 生成一致性备份，再逐级迁移；失败回滚。高于支持版本的数据库会拒绝打开，保留原版本号。迁移后的数据库不能直接交给旧程序写入。需要回退时先退出所有工作台进程，完整备份当前工作区，再在独立副本中使用迁移前数据库及与其匹配的项目文件；迁移之后的校对不会出现在旧备份中。不要覆盖唯一的工作区副本。
