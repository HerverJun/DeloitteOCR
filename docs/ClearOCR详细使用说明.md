# ClearOCR 详细使用说明

编写日期：2026-10-14；开发状态更新：2026-10-25。**当前源码尚未定版、尚未正式发布。** 本文面向在 Clear 源码预览中完成图片、PDF、文字及表格识别和校对的使用者；历史候选与资产目录不构成正式安装身份。

平台入口、其他子工具及跨工具操作见[Clear 审计平台使用说明书](Clear审计平台使用说明书.md)。本说明重点解释 ClearOCR 的界面、按钮、操作顺序、结果状态和交付限制。

## 1. 适用版本与入口

本项目中保留了主线开发源码、兼容入口、共享依赖和历史候选记录，不能只按目录中的版本号判断功能或发布状态。

| 对象 | 实际位置与用途 | 本说明中的定位 |
| --- | --- | --- |
| 既有源码预览 | 本机平台预览使用 `http://127.0.0.1:8992/`，原生 OCR 由实际预览配置装配 | 该地址不自动代表最新源码或构建，使用前核对实际原生源码、前端和 DATA |
| 统一主线原生 OCR 源码 | [products/Clear/ocr](../products/Clear/ocr/)；在 `main` 直接维护 | schema 22；已整合 MinerU Pro、屏拍批次、诊断、精细候选与单元格复核，来源见[整合记录](platform-automation/分支整合记录-20261024.md) |
| 根目录 OCR 兼容入口 | [src/ocr_workbench](../src/ocr_workbench/) 与 [frontend/src](../frontend/src/) | schema 22；同步收齐屏拍后续实现，完整 Clear 开发以 `products/Clear` 为准 |
| 共享 OCR 资产包 | `release/Clear/versions/0.10.0/program/bundles/ocr` | 开发环境复用的模型、运行时和配置；遗留的旧 `src/web` 不代表当前服务实际加载的源码和 UI |

主线源码已整合 MinerU Pro 文档路线；共享 `program` 仍位于带旧版本号的依赖目录，该路径不表示产品已发布。启动链的关键点是：平台预览配置明确选定原生 `ocr/src`，并传入 `--web-root` 指向选定的前端构建，同时通过 `--bundle` 引用资产。历史 `current.json`、8879 和“启动智能审计.cmd”不再作为现行正式入口建议；查看资产包里的旧网页也不能证明当前页面版本。

从平台首页打开 ClearOCR 后，可通过页眉品牌入口返回审计平台首页；从平台项目进入时，应核对平台项目上下文。会话链接由启动入口生成，服务重启后从平台重新打开，避免反复使用已经失效的旧链接。

本机源码、资料、导出、备份、临时文件与缓存只允许保存到 F 盘。运行及开发路径配置见[项目文件存储规范](项目文件存储规范.md)。每个源码预览或独立 OCR 进程都须明确配置 `--data`、应用数据和临时/缓存目录，不能假定旧启动入口会代为配置，也不能只更改项目目录。

## 2. 第一次使用：完成一份资料

1. 在左侧选择或新建项目，按业务事项、资料来源或批次命名。
2. 点击「导入图片 / PDF」，选择文件；也可使用文件夹入口或拖入文件、文件夹。
3. 打开图片，选择「照片文字」「手写」或「表格」。PDF 在「文档与页面」中选择页面处理方式。
4. 核对识别范围。上方「已选 N 张」表示处理勾选范围；没有勾选时使用当前图片。
5. 点击「开始识别」，或对 PDF 点击「处理当前页」「处理全文」。在任务队列查看进度。
6. 对照原图检查文字和表格。切换结果后，若要将当前预览用于批量导出，点击「采用此预览」。
7. 修改错字、金额、编号和表格结构，等待保存状态成为「已保存」。需要时使用模型对比、融合、结构复核和视觉审校。
8. 核对整页，点击「确认并下一项」；快速校对面板也提供「确认当前图片」。
9. 点击「导出结果」，选择格式与范围，下载到 F 盘后实际打开文件，检查内容及来源记录。

任务成功说明程序产生了结果；交付完成还要求内容已保存、采用对象正确、人工核对充分，以及导出文件已经读回检查。

「表格」「文字」是常驻标签。融合结果会增加「快速校对」。「专业工具」菜单包含「结构复核」「模型对比」「视觉审校」，选择后相应标签会显示在当前结果视图中。页面的显示密度、栏宽等偏好可记忆，不改变项目数据。

## 4. 项目、图片列表与导入

### 4.1 项目和资料范围

在项目选择器切换项目；新建项目填写名称，重命名只改变项目显示名称。导入前再次确认当前项目，原图、处理版本、任务和人工修改都会关联到该项目。

图片列表支持按文件名搜索，并按未识别、待校对、已确认、有疑问等状态筛选。列表的勾选框确定批量操作范围，点击条目打开当前图片。注意界面中「筛选外已选图片」的提示：隐藏的勾选仍可能计入识别或导出范围。需要只处理眼前资料时先清除旧勾选，再重新选择。

图片很多时列表按批次显示，使用「继续显示图片」加载更多。未显示全部条目只是显示限制，不能据此认为导入缺失。

### 4.2 输入格式

| 文件类型 | 导入后表现 | 注意事项 |
| --- | --- | --- |
| JPG/JPEG、PNG、BMP、WebP | 图片列表中的独立图片 | 图片清晰度直接影响小字和数字识别 |
| HEIC、HEIF | 解码后作为图片使用 | 解码异常时，可先在 F 盘另存为 PNG/JPEG 再导入 |
| TIF、TIFF | 单页图片或多页文档 | 多页 TIFF 在文档树按页打开 |
| PDF | 保留文档和页码，按需展开页面 | 可选择原生文字提取、自动补识别或整页 OCR |

文件夹入口和拖放会处理支持的资料。导入提示会列出失败项；先核对成功数量和失败文件名，不要因为一份资料失败就重复提交整批文件。

图片及 PDF 渲染有像素和资源限制。当前图像处理上限涉及 8000 万像素，超大页面应降低 DPI 或拆分范围；格式可打开不表示可以在任意尺寸下完成处理。

### 4.3 PDF 临时密码与页面展开

加密 PDF 在文档树中显示待解锁。输入「PDF 临时密码」并点击「解锁」，密码仅用于本次运行，退出后清除；重新启动后可能需要再次解锁。

PDF 默认按 300 DPI 展开。文档树显示「尚未展开」时，点击页面后先等待生成页面图像。渲染失败且页面还未生成图像时，可在错误区输入较低 DPI 后点击「调整 DPI 并重试」；允许输入范围为 36–1200。默认重试输入可能为 150 DPI，应按原图可辨认程度选择。

成功展开的页面不能直接在原记录上更换 DPI。如确需不同分辨率，重新导入一份文档，保留旧版本和校对来源。

## 5. 识别模式、四引擎与批次预处理

### 5.1 模式和引擎如何选择

| 模式或引擎 | 主要用途 | 结果特点 |
| --- | --- | --- |
| 「照片文字」默认 PP-OCRv6 medium | 印刷体、截图、需要文字坐标的资料 | 提供文字、坐标及模型分数；不生成结构化表格 |
| 「手写」默认 HunyuanOCR-1.5 | 手写及复杂内容的候选识别 | 可产生文字和表格候选；仍需逐字检查 |
| 「表格」默认 PaddleOCR-VL-1.6 | 表格行列、合并关系及文档解析 | 提供结构化表格，坐标通常是区域级，不等于精确单元格坐标 |
| GLM-OCR | 文字及表格的另一独立候选 | 可生成表格和区域信息，适合与其他引擎对照 |
| 「模型对比」/「四引擎顺序对比」 | 同一图像获取四种独立结果 | 四引擎顺序运行，每份结果分别查看、编辑和采用 |

模式只是预设，会选中推荐引擎并切换常用结果视图。需要更换引擎时，打开「识别设置」选择「识别引擎」；模式和引擎可以按当前资料调整，默认值不表示准确率排名。

GLM、PaddleVL、Hunyuan 产生的表格结构、原始文字与单元格坐标能力不同。没有表格时先看引擎能力，不能把 PP-OCR 的纯文字自动当成可编辑 Excel 表格。

### 5.2 识别范围

提交前看识别栏的范围提示：

- 「已选 N 张」：按图片列表中的勾选范围提交，包括可能处于筛选外的勾选。
- 「当前图片 · 1 张」：没有批量勾选时处理当前图片。
- 「等待导入资料」：没有可用输入，不能开始识别。

一次任务使用所选图片的当前图像版本。图像版本改变后，旧结果仍保留，但不再自动代表新图像。

### 5.3 批次预处理

「识别设置 → 批次预处理」提供：

| 选项 | 效果 |
| --- | --- |
| 保留当前图像 | 按当前图像版本识别 |
| 增强对比度 | 生成增强版本，再进行本次识别 |
| 顺时针旋转 90° | 旋转后识别，适合统一方向错误的一批资料 |
| 旋转并增强对比度 | 组合上述处理 |

批次预处理会影响整个提交范围。只有部分图片方向不对时，先逐张修正更容易核对。点击「开始识别」后在任务队列查看；四引擎和其他 GPU 工作顺序执行，排队不表示程序卡死。

## 6. 原图区：浏览、图像版本与局部处理

| 控件 | 操作方法与作用 |
| --- | --- |
| 图片版本选择器 | 切换「原始图片」或带操作名称的处理版本；旁边显示当前像素尺寸 |
| 查看原图 | 返回最初图片，便于核对处理是否破坏细节 |
| 拖动图片 | 放大后拖动查看各区域，也可使用滚动条 |
| 缩小 / 放大 / 缩放百分比 | 加减缩放；点击百分比使图片适合窗口 |
| 裁剪 | 拖出矩形范围，确认后生成新版本 |
| 四角透视 | 按左上、右上、右下、左下指定四角；可拖角点、键盘微调或输入像素坐标 |
| 区域重识别 | 框出困难区域，确认后生成裁剪版本，并用当前所选引擎提交识别 |
| 更多 → 顺时针旋转 | 顺时针旋转 90°，生成新版本 |
| 更多 → 增强对比度 | 生成增强版本，适合灰暗或对比不足的图像 |
| 更多 → 去弯曲 | 使用去弯曲任务处理弯曲页面，需要相应运行环境和 GPU 队列 |
| 放大疑点区域 | 存在可靠定位范围时，将视口聚焦到对应区域 |

区域工具进入后会出现操作提示、确认和取消。按 `Esc` 可退出区域选择回到拖动模式。矩形必须具有有效面积；过小的框选无法确认。四角透视必须完成四个角点，角点顺序要符合页面方向。

图像处理不会改写原文件，而是增加图像版本。区域重识别也不是在原结果上直接补几个字；它会得到新的图像及识别结果，原结果保持可追溯。完成后应检查当前版本、当前结果和采用结果是否一致。

## 7. PDF 文档处理与文档内复核

「文档与页面」中选择文档，用页码输入、上一页/下一页或缩略图打开页面；超过 30 页时用「前 30 页 / 后 30 页」浏览页码批次。

### 7.1 三种页面处理方式

| 处理方式 | 程序行为 | 适用情况 |
| --- | --- | --- |
| 自动：原生优先，区域补识别 | 优先使用可用的原生 PDF 内容，再为需要的区域补 OCR | 混合原生文字、扫描图片的 PDF，通常先尝试此项 |
| 仅原生提取 | 提取 PDF 已有内容，不发起新的整页 OCR | 文字清晰可复制的原生 PDF，或仅校对模式 |
| 整页重新 OCR | 对页面图像重新识别 | 扫描件、原生映射不可靠或需要重新识别的页面 |

「处理当前页」提交当前页面，「处理全文」提交该文档所有页面。空白页、等待 GPU 结果、失败、等待解锁等状态均会显示。页面可能需要等待补充区域 OCR 后才发布最终结果，不要把中间状态当成缺页。

文档级「暂停 / 继续 / 重试 / 取消」控制页面处理队列，与普通图片任务的单项按钮相配合使用。服务重启后中断任务需要手动继续；加密文档先重新解锁。

### 7.2 搜索与冲突

文档搜索入口提示「搜索已采用的内容」，搜索的是该文档已经采用的结果。临时预览或未采用候选不会替代文档搜索基线。命中结果显示页码与片段，点击跳转到对应页；界面最多显示前 50 项，不能把显示数量当成全文命中总数。

文档复核队列可聚合页面上的融合、结构和视觉审校待办。「检查全文候选」更新全文已有候选的检查，「下一处」跳转到下一条待办；筛选可选择「待处理与暂缓」「仅暂缓」「含已处理」。点击条目进入对应结果和工具。队列中的本地有效复核时间用于记录实际核对活动，不是模型准确率或交付完成证明。

原生内容与 OCR 存在冲突时，结果区会提供冲突核对入口；对照原图处理后，再确认页面和导出。

## 8. 预览、采用、保存、人工确认与撤销

这五个概念决定最终导出内容：

| 状态或操作 | 含义 |
| --- | --- |
| 预览结果 | 当前结果区正在查看的那份结果；结果下拉框和任务「查看」通常只改变预览 |
| 采用结果 | 该图片用于批量导出和文档搜索的结果；需要明确点击「采用此预览」改变 |
| 已保存 | 当前修改已经存入工作区；尚在保存或保存失败时不应直接离开 |
| 人工确认 | 当前图像、采用结果及其修订已被人核对；后续修改可能使确认失效 |
| 撤销 / 重做 | 在修订历史中恢复前一/后一状态；不是删除原始 OCR 结果 |

进入结果后先检查文件名、引擎、图像版本、预览/采用标记。若提示「当前结果对应另一图像版本」，切到结果对应版本核对，再作确认。不能拿旧图结果确认新图。

文字、表格和复核决定会保存修订历史。「撤销」「重做」可恢复编辑及已采用的建议，但应重新检查采用和人工确认状态。来源 OCR 原文保留，可在模型对比中查看。

「确认并下一项」确认当前采用结果并移动到下一份待校对资料。「复核操作」包含「暂缓：有疑问」「重开为待校对」「下一张待校对」：

- 有疑问：记录尚不能确认的内容，便于筛选和交接。
- 重开为待校对：撤回完成状态，重新进入人工核对。
- 下一张待校对：只导航，不表示当前资料已经确认。

保存失败时使用「重试保存」或下载草稿副本。版本冲突时先保留草稿，再核对服务器结果。界面提供「放弃本次修改并重新加载」时，该操作会用成功读取的服务器内容替换本地未保存修改；先下载需要保留的草稿。读取失败不会成为继续覆盖的理由。

## 9. 文字视图与表格编辑器

### 9.1 文字视图

「文字」显示可编辑正文；当结果包含结构化表格时，文字表示会与表格内容联动。修改表格文字应关注是否仍保持行列结构；多级表头、增删行列及合并关系建议在表格编辑器操作。

查找框输入词句，按 `Enter` 或「下一个匹配」逐项查找。选择一段正文可供人工定位、视觉审校使用；选择跨越多个不同内容区的范围时，可能不能作为单一审校目标，应缩小选区。

展开「定位文字区域与置信度」，可查看原始文字块、模型分数及「下一处待核对」。有坐标的文字块可在原图定位；无分数显示未知。阈值只筛选当前模型提供的分数，不是准确率承诺，也不能跨引擎横向排名。

### 9.2 表格区域

表格顶部选择「表 1、表 2……」，查看行列数量及当前单元格地址，例如 `B3` 或矩形选区 `B3:D5`。点击格子编辑；点击行号/列号选择行或列。`Shift` 点击或 `Shift + 方向键` 扩大矩形选区。

| 按钮 | 具体作用 |
| --- | --- |
| 加行 / 加列 | 在当前选择对应位置后增加行或列，随后核对相邻跨度 |
| 删行 / 删列 | 删除当前选择的行或列，需要检查合并格和数据归属 |
| 合并 | 将有效矩形选区合并；跨越已有合并关系时按界面校验处理 |
| 拆分 | 拆开当前合并单元格 |
| 切换表头 | 标记/取消所选单元格的表头属性 |
| 新建表格 | 输入行列数后「创建表格」 |
| 删除整表 | 移除该结构化表格；文字视图中的原文会保留 |
| 粘贴区域 | 输入 TSV，从当前选区左上角填入；点击「应用粘贴」 |
| 表格标题 | 修改表格的标题字段 |
| 下一处 | 在有分数且低于当前阈值的单元格之间移动 |

「新建表格」「删除整表」「粘贴区域」「表格标题」和分数阈值位于「表格设置与更多操作」中。没有结构化表格时，界面直接给出手工建表入口，可先建表再粘贴 TSV。

`Ctrl + V` 可粘贴包含制表符的矩形区域；只有一列的多行数据建议用「粘贴区域」，避免被当成普通格内文本。粘贴、新建和删除可撤销。编号以文本保留，金额暂不应为了计算随意转换原值。

当前交互创建/粘贴有较小的 50000 格预算；服务器单表上限为 10000 行、1000 列且最多 100000 格，单个结果最多 100 张表。这些上限同时生效，例如 10000×1000 并不意味着可保存千万格；超大表应拆分处理。

### 9.3 推荐的表格校对顺序

先检查整表有没有漏表、漏行、错列；再检查标题、多级表头、合并跨度与行列归属；最后核对金额、日期、负号、小数点、百分号、前导零和长编号。结构有错时先修结构，避免在错误格位上逐个改字。

## 10. 模型对比、融合和快速校对

### 10.1 模型对比

从「专业工具 → 模型对比」打开。按相同图像版本和识别批次分组，选择「比较批次」及「比较基准」，再决定查看模型原文或已保存的校对内容。

对比包含正文差异、表格数量、行列及合并跨度、单元格文字等。新增一行可能导致多个格位看起来不同，先理解结构变化，再看文本差异。大量差异按批次显示，使用继续显示按钮查看剩余项。

对比结束后明确采用需要的结果。看到了另一模型结果，不会自动替换当前图片的采用结果。

### 10.2 融合识别

展开「融合识别 · 生成有来源的校对草稿」：

1. 选择内容类型：表格、印刷体文字或手写文字。
2. 选择保守或积极策略；保守为默认。
3. 勾选参与引擎。表格融合不能把没有结构化表格能力的 PP-OCR 当成结构来源。
4. 同一图片版本已有兼容识别批次时，选择批次并点击「复用当前图片结果」。没有兼容结果则点击「完整识别并融合」。
5. 完整流程先顺序运行所需引擎，再由 CPU 生成融合草稿；完成后在结果列表预览并采用。

融合草稿保留来源、分歧和策略信息，不是保证正确的新真值。人工修改、融合结果不会增加原始 OCR 的支持票数。票数说明有多少独立来源支持该候选，不代表正确概率。

### 10.3 快速校对

融合结果增加「快速校对」标签。采用该融合结果后，可按未处理、有疑问、已过期、已处理等状态筛选；类型包括结构与缺表、金额、日期、编号、其他数字、空值和文字。面板显示当前已保存值、候选、来源覆盖、原因、行列标题及相邻内容。

| 操作 | 结果 |
| --- | --- |
| 在编辑器定位 | 跳到正文或表格中的相应位置，适合整段或结构问题 |
| 定位原图 | 在原图区显示可用范围；可能是单格、整表/文字区域或全图 |
| 选择候选 → 保存并继续 | 将候选作为本项人工决定保存 |
| 手工修改 → 保存并继续 | 保存输入值后继续；输入期间先保存或清除才能切换 |
| 保留当前并继续 | 明确记录当前值经过人工选择 |
| 暂不确定 | 标记待进一步人工核对 |
| 下一项（跳过） | 仅移动到下一项，不把本项标记为已处理 |
| 确认当前图片 | 对当前图片作最终人工确认，仍应先检查整页 |

缺失整表候选可选择插入文档开头或末尾，插入后还需核对阅读顺序。整段包含结构化表格时，候选可能仅供对照；按提示在表格编辑器调整后，再返回记录保留或存疑。

无可靠单元格框时显示整表或全图，不要把文字片段范围误当成完整单元格边界。所有疑点都处理完也不能证明没有漏表、漏段或跨页关系错误。

## 11. 表格定位、结构候选与复杂表格

### 11.1 表格定位与人工绑定

展开「表格定位与人工绑定 · 实验性」。选择表格单元格，或在文字编辑区选择一段文字，再选择定位模型和对应方式。

| 设置 | 可选项 |
| --- | --- |
| 定位模型 | Paddle（默认）、TableFormer raw（实验）、RapidTable（对照） |
| 对应方式 | 现有局部对应、邻居锚点对应（实验）、复杂表格空间对应（实验） |
| 补充表格定位 | 使用已有缓存或排入定位任务 |
| 重新定位 | 强制重新计算 |
| 人工框选绑定 | 将当前目标与原图上的人工框选范围绑定 |

人工绑定步骤：先选目标，点击「人工框选绑定」，到原图区准确框出相应原文，确认提交。金额和小格子应放大后操作，框选不要包含相邻行列的不同内容。没有可靠定位时，界面会退回整表/全图，仍可人工核对。

结构改变后需要重新定位。文字、图像版本或修订变化也可能使原证据不再匹配，不应继续把旧框作为当前内容的证明。

### 11.2 结构复核

从「专业工具 → 结构复核」打开：

1. 采用并保存当前结果，点击「检查已有候选」。
2. 无候选时，可在表格辅助定位区运行提供方；PDF 表格提取失败且允许重试时，使用「重新提取 PDF 表格」。
3. 选择结构建议，对照「当前结构」「候选结构」，核对行列、跨度、表头、缺失行和影响的金额格。
4. 点击「定位原图」或「在表格编辑器调整」，检查变更区域及整表上下文。
5. 确认合适后「接受结构建议」；也可「保留当前结构」「拒绝此建议」或「暂缓」。

候选使用已有来源文字填充；没有文字来源的格子会保留空值并要求人工核对。接受按钮被禁用时先处理未归属文字、冲突、失效状态或所需确认。不能为了采用结构而忽略金额、编号及人工清空值。

展开「结构与文字来源」可查看结构提供方、文字来源、模型、基准修订及保留人工值。接受后可以撤销；结构改变后重新检查候选和定位。

### 11.3 复杂表格与财务一致性

「复杂表格空间对应（实验）」用于为复杂跨度、合并、多级表头等情况补充对应证据，不代表自动恢复所有复杂表格。表格结构正确和坐标正确是两项独立检查。

「财务一致性疑点」显示程序能够明确判断的关系、差额和定位入口。未知单位、范围和空值保持不确定，程序不会为了凑平合计改写原值。合计吻合也不能证明每个明细值正确。

跨页表、断续表头和全页阅读顺序需要人工连续检查。结构复核主要围绕已有候选，不承担全项目自动发现全部漏表的保证。

### 11.4 外部 API 结构仲裁

在视觉审校中先配置可用外部连接，再在结构复核展开「外部 API 结构仲裁（实验）」。界面会要求确认发送本页与结构证据，满足有效候选和采用状态条件后可「提交结构仲裁」。

仲裁会发送当前页图像、候选结构及固定文字片段。模型只能选择已有候选或弃权；返回推荐后点击查看候选，是否接受仍由人决定。内容或候选改变后仲裁记录会过期，按新修订重新检查。

## 12. 本地视觉审校与外部 API

### 12.1 发起审校

「专业工具 → 视觉审校」打开「多模态二轮审校」。它结合原图检查现有文字和表格，产生保留、修改或存疑建议。

1. 先采用结果并保存，确认原图版本一致。
2. 在「审校模型」选择可用模型；本地配置默认 Qwen3.5-4B · Q4_K_M，其他配置按列表及可用原因显示。
3. 在文字区选择片段，或在表格中选择单元格，然后「复核选中内容」；需要整页检查则「复核本页」。
4. 在「审校任务」查看排队、处理和错误状态；按情况取消、重试或恢复。
5. 对照审校时原文、模型建议、模型依据及原图，决定采用、记录保留、拒绝或人工存疑。

模型不可用时展开原因，修复模型资源或服务后「刷新模型」。目录中有模型名称不等于当前可以运行；以页面的可用状态为准。

### 12.2 处理建议与覆盖范围

| 按钮 | 含义 |
| --- | --- |
| 采用这条修改 | 将建议值写入人工修订，可撤销 |
| 记录保留原文 | 记录人工同意保留当前值 |
| 拒绝此建议 | 记录拒绝，识别内容不改变 |
| 人工标记存疑 | 保留待人工进一步核对的状态 |
| 导出校验清单 | 以 Excel、Markdown 或 JSON 导出建议及人工处理记录 |

本页审校覆盖已有正文片段及已保存表格的逻辑单元格，不覆盖缺失整表、跨页结构关系、表格标题和全页版面完整性。单任务最多 256 个目标，单目标最多 4000 字符，总计最多 40000 字符；超出时缩小范围或分次提交。

没有可靠局部定位时会使用全图上下文，小模型可能误读小字或误改数字。普通编辑、换结果、换图像版本、撤销/重做等会使旧建议过期，过期建议不能直接采用。模型建议和「记录保留原文」均不能替代最终整页人工确认。

### 12.3 配置外部 API

点击「配置外部 API」：

1. 选择协议「OpenAI 兼容」或「Anthropic」。
2. 填写 API URL、API Key 和视觉模型 ID。地址示例只是格式示例，应填写实际服务。
3. 可点击「获取模型」搜索选择，也可直接输入模型 ID。获取列表失败不表示指定视觉模型一定不可用，可继续进行图片测试。
4. 点击「测试并保存」。测试发送内置小图片验证视觉能力，不使用项目文档。
5. 保存后选择该外部模型发起审校；「清除连接」可删除本机保存的连接。

已保存的 Key 在相同连接中可留空复用，修改地址或协议时按界面重新填写。Key 加密保存在本机，换电脑后需重新输入，不要把 Key 写入项目说明或 Git。

正式发起外部审校会发送页面上下文、目标裁剪图和对应文字；结构仲裁发送范围也会在对应区域标明。需要本地处理时选择本地模型。平台主控、原生文档助手主控与视觉审校连接是不同配置，配置其中一个不会自动配置其他连接。

外部审校队列异常时使用「恢复外部审校队列」。上次提交状态尚未核实时优先使用「重试上次请求」，该入口会沿用原请求，避免重复创建任务或重复采用建议。

## 13. 文档助手

ClearOCR 的「文档助手」是原生 OCR 页面内的助手，负责查询当前项目、组织文档处理和生成导出等操作。平台首页的统一助手使用方式见主手册，二者的入口和连接不要混淆。

1. 打开「文档助手」，通过齿轮或「配置主控连接」设置主控。
2. 按页面提示允许所配置地址读取当前项目文字和文档信息。
3. 新建会话或从「历史会话」选择记录。可在「会话管理」修改名称、归档或恢复。
4. 输入明确目标，例如指定文档、页码、表格名称及期望输出，在发送前检查本轮范围和权限。
5. 阅读实际工具步骤、页面证据、覆盖情况及导出产物，点击页码证据回到结果核对。

「范围、审校与预算」可指定文档页码（例如 `1-3,8`），也可使用工作台已选页面；按需授权处理、重新处理、部分失败仅导出成功页、结构候选及视觉审校。向外部视觉连接发送图片有单独的本轮权限。

运行中可追加指令，追加内容会在安全边界处理。「停止助手」停止主控继续执行；「停止并取消本轮自建任务」还会取消本轮拥有的后台任务。关闭面板不会停止后台运行。重启后中断的运行可通过「继续」恢复，预算不足按界面增加本轮上限。

助手依赖不可用或发行入口未启用助手时，普通识别、校对和导出仍可使用。助手回答应结合原文及实际证据核对，覆盖统计中的失败或未覆盖内容不能当成已经检查。

## 14. 研发版新增：拍屏表格批量转 Excel

本节对应 [frontend/src/ScreenBatchPanel.tsx](../frontend/src/ScreenBatchPanel.tsx) 及 Clear OCR 中对应的前后端实现，整合源码数据库为 schema 22。此前两个研发方向都曾使用 schema 18，整合迁移按实际表结构补齐 MinerU 路由和屏拍记录；升级检查覆盖两种旧库及事务回滚。历史2026-10-14的 Clear 0.10.0 候选没有此功能；当前预览、主线源码和依赖资产身份仍按第1节分别核对。

### 14.1 新建批次与查看进度

点击「拍屏表格批量转 Excel」，选择「本项目全部图片」或「已选图片」，可勾选「提高精度（增加必要核对）」。一次支持 1–1000 张图片，点击「开始处理 N 张」。每张图片生成一个 Excel，同一图片中的多张表放在不同工作表。

批次会自动准备业务表区并处理，状态区显示已处理、可交付、处理中、待核对、失败和已取消数量。预计剩余时间仅针对当前阶段，不包含后续准备、模型切换、升级、导出和人工核对；重复图片等待复用时也会显示相应提示。

「最近批次」可重新打开记录，「刷新批次」重新读取列表。批次操作包括「暂停批次」「继续处理」「停止未完成项」「只重试失败项」。停止未完成项不等于撤回已完成结果。

### 14.2 单图集中核对

按待核对、失败或可交付筛选图片，选择一张后查看业务处理图、疑点和单元格：

- 「原图与处理图」切换原图、业务表区、透视校正候选和局部分块；原图支持 100% 查看、缩放、拖动及局部定位。
- 选择疑点后查看记录值、另一转录和文字证据，再核对原图。
- 通过表、行、列定位，编辑「当前单元格」；候选面板可对照不同候选及填入候选值。
- 「打开完整表格编辑器」用于调整结构；有未保存修改时先保存或清除草稿。
- 「重试这张图」只重试失败图片；「只对这张图提高精度」只升级该图。
- 「保存并标记核对完成」保存修改并作人工核对记录；「保留当前内容，仍待核对」保存为待核对；「稍后核对」保留待办。

每次集中保存最多处理 100 个修改格；切换图片、候选、关闭窗口前需要处理未保存修改。模型一致、合计一致或自动进入可交付状态，都不等于人已经核对；界面区分「自动交付」和「人工已核对」。

### 14.3 批次下载和数值列

「下载逐图 Excel ZIP」默认下载可交付项；需要包含待核对结果时明确勾选「下载时包含待核对结果」。未完成和失败项会列在下载清单中，交付时应一起检查。

默认金额、编号按原文保存，保留前导零及长编号。完成单图人工核对后，可在「本图数值列可计算（可选）」选择金额或数量列，确认后下载当前图片的可计算版本；编号列及不宜转换的数字仍保留文本。该选项只作用于当前图片已选列，不把整批编号或所有数字强制改为数值。

## 15. 复制、常规导出与可搜索 PDF

### 15.1 复制与导出范围

「复制」先保存当前编辑，再复制纯文字表示。需要来源、结构或可交接文件时使用「导出结果」。

| 范围 | 导出内容 |
| --- | --- |
| 当前预览结果 | 当前正在查看的结果，即使尚未采用 |
| 所选图片的采用结果 | 每张勾选图片的采用结果，不受临时预览替换 |
| 整个项目的采用结果 | 项目内每张图片的采用结果 |
| 仅导出已确认结果 | 进一步限制为当前图像、采用结果和修订仍被人工确认的内容 |

范围内尚无结果时，界面会列出不能导出的数量，应等待识别或调整范围。批量默认每张图片独立文件，多张打包 ZIP；Excel 批量需要集中整理时，可选「汇总为一个工作簿」。

### 15.2 输出格式

| 格式 | 用途与内容 |
| --- | --- |
| TXT | 纯文字；表格以制表符分隔的文本表示 |
| Markdown | 正文及可阅读表格，适合审阅和文字交接 |
| JSON | 保存识别、结构及人工修改等机器可读信息，适合追溯 |
| Excel | 结构化表格；每表单独工作表，保留合并关系、前导零和长编号 |
| 可搜索 PDF | 按文档输出，采用保存后的内容并先检查定位等条件 |

没有结构化表格时不能只靠选择 Excel 格式得到正确表格，应换用支持结构的引擎，或手工创建表格。Markdown/TXT 也不保证恢复原页面的全部视觉排版。

融合、结构复核或视觉审校等来源可能让单结果导出为 ZIP，里面同时包含主文件、来源证据和决策记录。所有文件应基于同一已保存修订。不要只交付 ZIP 中第一眼看到的文件而丢失来源清单。

普通 Excel 导出将前导零、长编号及以等号开头的内容按文本保存，避免自动丢失或解释成公式。需要运算时另存副本后转换；研发版拍屏流程的数值列选项见第 14 节。

### 15.3 可搜索 PDF

在文档树展开「导出此文档为可搜索 PDF」，页码留空为全文，也可填写 `1-3,5`。点击「预检并导出 PDF」；预检失败时根据页码和原因处理，再重新预检。

| 预检问题 | 处理方式 |
| --- | --- |
| 文字缺可靠定位 | 选择正文或单元格，人工框选绑定相应原文区域 |
| 页面或区域 OCR 尚未完成 | 等待任务结束，失败先检查错误后重试 |
| 原生文字与 OCR 冲突 | 对照原图处理冲突，避免不一致的文字叠加 |
| 字体缺字或页面错误 | 核对具体页码和字符，修复后重试；需要时明确选择其他可导出页 |

可靠且未修改的原生页面可保留原页；原生文字有修改、图像有处理或映射不可靠时，程序可能重建相应页面。PDF 内附页面来源清单。

下载后检查页数、页序、可见文字与搜索内容是否一致，搜索一处人工修改和一个长编号，关注负号、小数点及重复叠字。可搜索 PDF 不自动成为 PDF/A、PDF/UA，不保证保留输入 PDF 的签名；输入有密码也不表示输出自动加密。

## 16. 任务队列、仅校对模式与故障恢复

### 16.1 任务队列

| 控件 | 行为 |
| --- | --- |
| 暂停等待项 | 暂停尚未开始的任务，不中断正在处理的图片 |
| 继续 | 继续暂停或中断后可恢复的任务 |
| 重试失败项 | 重试失败范围，已成功项无需重复 |
| 单项取消 | 取消该项排队或执行任务 |
| 查看 / 查看图片 | 打开对应结果或生成的图像版本，通常只改变预览 |
| 查看审校 | 跳到该审校任务及建议 |
| 错误详情 | 展开具体错误，先处理原因再重试 |

GPU OCR、去弯曲、定位及本地视觉相关工作受串行资源调度约束。CPU 融合和外部审校有相应队列；某个队列异常时使用界面的专用恢复入口，不需要把所有任务重建一遍。

### 16.2 仅校对状态

当界面显示当前只能校对时，可打开已有结果、编辑、复制和导出；普通图像处理、原生 PDF 提取及复用已有结果的 CPU 融合按界面条件可用。新 OCR、去弯曲及需要本地识别资源的操作会禁用。外部审校是否可用依其连接、队列和当前界面条件判断。

### 16.3 常见问题

| 现象 | 排查和恢复 |
| --- | --- |
| 排队很久 | 看当前执行任务及 GPU 占用；等待前项完成，避免重复提交 |
| 显示等待 GPU 结果 | 页面处理依赖区域 OCR，等待依赖完成后发布 |
| 识别失败 | 展开错误，检查输入、模型、显存、磁盘或运行时，再重试失败项 |
| 服务重启后暂停/中断 | 核对任务范围后手动继续；加密 PDF 重新解锁 |
| 结果暂时加载失败 | 先「重试加载」，不要立即重新 OCR |
| 当前结果不是采用结果 | 核对内容后「采用此预览」，再确认和批量导出 |
| 没有表格 | 检查引擎结构能力，尝试另一结构引擎，或手工建表 |
| 按钮禁用 | 检查忙碌/保存状态、采用对象、图像版本、目标选择、模型可用性和仅校对状态 |
| 没有视觉建议 | 查看任务是否完成、筛选条件及覆盖范围；无建议不代表没有错误 |
| 提交后没有最终响应 | 优先「重试上次提交/请求/结构决策」，先核实原请求，避免重复采用 |
| 保存冲突 | 下载草稿，核对服务器最新修订后再处理 |
| 会话链接失效 | 从平台/启动入口重新打开；先保留已有草稿 |
| 队列持续异常 | 处理资源或存储原因，再用对应队列恢复入口 |

关闭浏览器或助手面板不会自动结束后台服务。真正停止时使用「环境检查」中的「退出工作台」或正式启动入口提供的退出操作，等引擎与任务状态保存后再处理工作区文件。

## 17. 环境、离线引擎、空间清理与备份

### 17.1 环境检查与引擎管理

「环境检查」展示启动、运行时、引擎及其他诊断情况；需要排错时展开技术详情，结合具体不可用原因处理。

「引擎管理 → 导入完整离线引擎包」接受完整 ZIP，经过暂存、完整性校验和启用流程。暂存页显示名称、版本、文件数、容量和 SHA-256，可「启用此引擎包」或「放弃暂存」；未完成的暂存可继续或删除。

各引擎「启用版本」可选择随应用内置版本或已安装包。新任务使用新版本，历史任务和结果仍关联原版本。等当前识别结束后切换；不要手工删除仍被任务引用的目录。文件校验只证明完整性，启用会运行包中适配器代码，因此应使用可信来源的完整包。

### 17.2 项目占用与清理

「项目占用与清理」显示当前项目文件、数据库内容、撤销历史、共享数据库和磁盘可用空间。永久删除项目需要输入完整项目名称，再「清理并删除项目」；会删除原图、处理版本、识别结果和人工校对，应先导出或完整备份，运行中的项目先停止任务。

「审查工作区未登记文件」扫描整个工作区，只列出数据库未引用的图片文件。勾选后「隔离所选文件（保留恢复清单）」会移入隔离位置并给出恢复清单；这与直接永久删除项目是不同操作。恢复时按清单核对原路径，不要凭文件名把隔离文件随意混回项目。

### 17.3 完整备份与恢复

1. 等待编辑保存，暂停或取消未完成任务，并等正在运行的工作退出。
2. 退出后台服务，避免复制过程中数据库和文件继续变化。
3. 在 F 盘复制整个资料工作区，包含数据库、原图、图像版本、任务输出、修订和相关备份目录。
4. 备份外部连接所需信息时按凭据自身机制处理；换电脑后加密 Key 通常需要重新填写。
5. 恢复时使用独立 F 盘副本验证，检查项目、原图、采用结果、修订和导出，再继续正式工作。

应用目录与资料工作区是两套内容；只复制发行程序不等于备份资料，只复制 SQLite 文件也不等于完整备份。平台整体备份还应覆盖平台数据和其他子工具原生资料，见主手册。

正式 0.20.0 candidate-006 的原生 OCR 为 schema 18；本轮整合开发源码与根兼容入口均为 schema 22，尚未用它升级正式工作区。新版可能先备份数据库再进行迁移，但自动数据库备份不包含所有图片和输出。旧程序不能写入新版数据库；回退时使用与旧版匹配的完整备份，不手工改版本号。

## 18. 交付前核对与文档依据

交付前应逐项核对：

- 文件、页面和表格数量完整，特别检查漏页、漏表和跨页关系。
- 当前图像、预览、采用结果一致，最新修订显示已保存。
- 金额、日期、编号、前导零、长编号、负号、小数点与多级表头已对照原图。
- 人工已确认的是当前修订；有疑问和未覆盖项已明确交接。
- 导出格式和范围正确，主文件、来源清单、失败/待核对清单齐全。
- 文件已下载到 F 盘，并实际打开检查；工作区已按需要完成备份。
