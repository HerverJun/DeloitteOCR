# 从 GitHub 源码启动工作台

适用环境：Windows x64、Python 3.12、Node.js 22 和 npm。源码仓库不含模型、独立 Python 运行时或已构建的网页。以下命令首次执行需要从包源安装 Python/npm 依赖，不适用于完全断网的新机器。

在解压或克隆后的仓库根目录运行：

```powershell
py -3.12 scripts\run_from_source.py setup
.\.venv\Scripts\python.exe scripts\run_from_source.py check
.\.venv\Scripts\python.exe scripts\run_from_source.py smoke
.\.venv\Scripts\python.exe scripts\run_from_source.py serve
```

`setup` 在仓库内创建忽略的 `.venv`，安装 `config/service-requirements.txt`，执行前端 `npm ci` 和生产构建，不下载 OCR 模型。`check` 核对依赖和页面产物。`smoke` 在临时目录创建项目、导入仓库里的测试图片、旋转、读回图片和项目，完成后删除测试数据；输出中的 `model_inference: not_run` 表示没有测试识别准确率。`serve` 在随机本机端口打开 React 工作台，终端会显示带会话令牌的地址；按 Ctrl+C 停止。

源码体验默认使用 `build/source-preview-data`，与正式安装的 `%LOCALAPPDATA%\OfflineOCR\Workspace` 分离，数据可在下次启动时继续使用。也可显式传入 `serve --data <独立目录> --port <端口>`。在无模型模式下可以创建项目、导入图片、使用旋转/裁剪/对比度等普通图像处理，以及打开已有结果进行校对和导出；识别队列、去弯曲模型、完整 PDF 工具和引擎包启用不可用。不要把正式用户工作区直接传给源码体验入口，数据库升级后旧程序可能无法读取。

## 使用已有 GLM-OCR 模型

源码体验入口只负责无模型功能。GLM 推理还需要单独的 Windows GLM 运行时、`PP-DocLayoutV3_safetensors` 布局模型和支持 BF16 的 NVIDIA GPU。若已有完整的 OCR 离线运行目录，可按[导入本地 GLM-OCR 模型](导入本地GLM-OCR模型.md)生成完整引擎 ZIP，再在正式工作台的「引擎管理」导入。只有 GLM-OCR 权重目录时，尚不能从 GitHub 源码直接执行识别；这条路径需要先按[构建与复现](构建与复现.md)准备运行时。
