## 3. 优先处理的发现

### F01 / P1：大结果集可能遗漏异常并误报复核完成

批次在 [data.py:290](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/batches/data.py:290) 只读取前 100,000 条结果并据此生成异常，而摘要使用全量 `page['total']`。结果接口的 count 与 LIMIT 分离，见 [结果分页](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/data_api/service.py:345)；每侧最多 100,000 行，左右不匹配项分别形成结果，见 [比对分类](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/modules/data_workbench/comparison/exact.py:244)。[复核完成判断](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/batches/service.py:93) 只检查已生成事项的 pending/deferred。

因此左右各 50,001 行且键完全不相交时，结果为 100,002 条，末尾两条可能不进入异常队列。已入队项确认后，完成判断无法看见这两条。**这是静态源码链路成立的高优先级缺陷，本次没有执行大规模运行复现。**

修复应采用分页/流式生成持久事项索引，避免把十万条以上事项作为单个批次 JSON 反复读写。独立保存结果总数、应处置数、已索引数、各处置数和覆盖状态。覆盖未完成时阻止复核完成，不能以放大单页 LIMIT 代替完整性保证。输入文件数、左右原始行数、结果行数、异常数分别展示。

### F02 / P1：人工修订无法自然回流，分类存在旧建议覆盖新判断的路径

[批次页](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/apps/portal/src/features/batches/BatchCenter.tsx:50) 指引用户到原生改标签或校对 OCR。分类平台确认却固定使用旧 `prediction_label_id`，见 [native.py:309](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/batches/native.py:309)。如果本次结果在原生已经从 A 改为 B，回平台确认原建议存在再写回 A 的路径。

OCR 的实际校对会增加 [结果 revision](/F:/OCR/output/clear-automation-dev-20261002/worktrees/ocr/src/ocr_workbench/store.py:553)，平台确认仍要求等于执行时固定的 [旧 revision](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/batches/native.py:323)。原版本保护是必要的，但缺少明确接纳新修订的路径，导致“校对后返回确认”不闭合。两种情况均为静态发现，尚未在当前页面动态复现。

应区分“接受原建议”“采用修订后解决”“暂缓”“重开”。原始结果始终保留；采用修订时显式保存新结果版本、旧新关系和人的判断，更新事项关联并重新核对来源。不得通过取消 revision 校验或原地覆盖旧成果解决。

### F03 / P1：处置留痕与复核成果仍不足

平台 [处置契约](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/packages/contracts/automation.py:51) 只有事项、动作和说明；[事件表](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/batches/store.py:36) 有动作/时间历史，但没有操作人、处置版本、用户所见版本和请求身份。原生分类已有 revision 与历史接口，平台应复用并补齐跨模块一致性；不能先读最新 revision 再写，从而绕过用户所见版本冲突。

[处置服务](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/batches/service.py:113) 更新处置后没有生成新复核成果；页面继续下载运行时固定的成果。保留旧成果不可变是正确的，但需要另建**复核版成果**，承载最终采用结果、处置说明、历史和未解决事项。

单机第一版记录真实本机操作身份及明确的编制/复核人标识；手工填写的姓名不冒充组织认证。处置需要 expected_revision 和 request_id；提供历史查询、冲突反馈与新旧版本对照。复核完成与“可以作为最终交付”分别定义；未解决事项可导出中间材料，但必须保留未完成状态。

### F04 / P1：重复启动保护回归与 F 盘路径边界

当前 [Start.cmd](/F:/OCR/output/clear-automation-preview-20261002/Start.cmd) 设置运行环境后直接调用启动器，旧 Clear 候选入口存在的端口占用检查已经不在此文件中。[bootstrap main](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/scripts/candidate_bootstrap.py:258) 在绑定端口前执行 configure，而 [configure](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/scripts/candidate_bootstrap.py:123) 会写用户数据指针和安装记录。重复启动或换数据目录后启动到已占用端口，存在先改配置再失败的路径。本次没有操作活动实例来复现。

应在配置写入前取得程序根/数据根的跨进程互斥并检查端口；端口检查用于反馈，互斥负责处理并发竞态。重复双击相同实例只打开已核实的页面；同包不同数据根或不同端口并行启动按当前单实例边界拒绝，既有配置与任务保持不变。

现入口已把 TEMP/APPDATA 等指向候选目录，但这还不是全部写入边界。[OCR 中文模型路径兼容](/F:/OCR/output/clear-automation-dev-20261002/worktrees/ocr/src/ocr_workbench/windows_paths.py:21) 会跳过非 ASCII 临时父路径并尝试 SystemRoot/ProgramData。候选放到 F 盘中文目录时，可能退回 C 盘系统目录。当前默认英文目录没有证明已发生盘外写入，不应写成已有违规事故。

所有入口及子进程必须解析并核对真实 F 盘写入目标；Paddle 兼容目录固定使用登记的 F 盘 ASCII 临时目录，不可写则明确阻断。验收检查原生子进程实际 TEMP/TMP/APPDATA/LOCALAPPDATA 与缓存位置及文件落点，不能只检查根批脚本，因为受控启动可能使用白名单环境而未传递全部变量。拒绝盘外自定义数据根、junction 逃逸和系统临时目录回退；不更改 HOME/CODEX_HOME，不删除或搬迁历史盘外资料。

### F05 / P1 验证缺口：真正保存成果到用户机器尚未证实

[交付报告](/F:/OCR/output/clear-automation-preview-20261002/交付报告.md:32) 记录 HTTP 200 与完整字节正常，但 headless Chrome 下载事件为 canceled，根因未确定。不能据此判断所有浏览器下载故障，也不能把 HTTP 成功视为用户保存成功。

使用实际目标浏览器完成“点击下载 → 保存到 F 盘 → 重开 CSV/XLSX/来源 JSON → 核对身份与内容”。如果只有 headless 工具失败，记录工具边界；如果用户浏览器也失败，再针对实际根因修复。取消下载与重试不重新计算或替换固定成果。

### F06 / P2：运行、模板和异常解释仍增加用户负担

这些能力可以在核心完整性修复之后并行推进：

- **原生服务自动准备。** [最新限制](/F:/OCR/output/clear-automation-preview-20261002/交付报告.md:111) 要求首次/重启后先到应用页启动。批次应调用已有受控启动能力，保留已选模板与资料，展示“校验/启动/等待资源/可执行”，不让普通用户记住服务顺序。
- **模板的可读摘要与首次引导。** [当前模板选择](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/apps/portal/src/features/batches/BatchCenter.tsx:187) 主要显示名称、场景和版本；首次 Data 模板还依赖高级工作台中的已完成作业。补左右角色、匹配键、列映射、清洗、金额/空值政策、模型/引擎及版本摘要，首配以小样本预览明确确认。
- **事项可解释展示。** [Output 组件](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/apps/portal/src/features/batches/BatchCenter.tsx:10) 对复杂结构打印 JSON。默认显示业务键/文件名、两侧字段变化、原行、原文和实际采用规则，技术 JSON 收入详情；数值容差结论由后端提供。
- **上传恢复。** [当前上传循环](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/apps/portal/src/features/batches/BatchCenter.tsx:151) 顺序提交，失败中断。显示逐文件成功/失败/未提交，成功项保留，允许仅重试失败项，避免用户整批再传。
- **能力一致性。** 前端 OCR 候选类型包含 HEIC/HEIF，而 [后端预检](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/batches/native.py:82) 不接受；场景名称却包含“文档识别与提取”。由同一能力声明提供允许类型、设备和恢复动作。当前准确名称为“图像 OCR”，PDF 给出原生文档入口。
- **跨批次待办。** 首页汇总需介入、待复核、暂缓、归集失败和运行中事项，保留工作空间及批次上下文。服务端执行全局筛选/排序，不把当前页排序宣传为全局优先级。初期优先级采用可解释的问题类型和人工设置，不把分类分数当审计风险分数。

### F07 / P2，审计平台主线：缺少最小审计业务层

当前 [Workspace](/F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/store/workspaces.py:30) 主要是名称、版本、时间和原生项目关联。在当前门户/API/契约范围未找到完整的审计期间、工作目标、工作程序、调查事项、结论和复核签署对象。现有异常处置可以说明“这个输出已处理”，但不足以说明“为哪个审计目标执行了什么程序、形成何种结论”。

首版补齐小范围业务层：审计项目保存对象、期间和目标；工作程序保存依据、范围、执行规则、关联批次及覆盖；调查事项关联一个或多个结果和证据，保存说明、结论、编制人与复核信息。技术错误与业务发现分开，不能每次重试都生成一条新的审计发现。由一项两表差异完整生成底稿，再决定扩展计划、整改或多人审批。

## 4. 目标操作流程

```mermaid
flowchart LR
    A[审计项目与工作程序] --> B[选资料并核对模板摘要]
    B --> C[受控准备应用并自动处理]
    C --> D[核对全量覆盖]
    D --> E[集中处理异常与人工修订]
    E --> F[采用版本和处置历史]
    F --> G[生成复核版成果与底稿]
    G --> H[保存读回与归档备份]
```

成功的确定性阶段保持自动执行。人工集中确认首次规则、解释异常、采用修订和形成结论。资料版本或规则改变时另建版本；已交付材料保留原身份，受影响事项重开，新版交付可说明与旧版的关系。

## 7. 验收场景与效果指标

集中使用以下场景验证核心改进；合成/公开资料用于工程检查，不推断真实审计业务准确率。

| 场景 | 必须证明 |
|---|---|
| 大量不相交与混合比对 | 输入覆盖守恒；应处置异常 = 已索引异常；不同分页、重启和处理顺序无遗漏重复；暂缓仍未完成 |
| OCR 错字与分类改判 | 原输出保留，新修订可采用，旧建议不会覆盖人工判断，事项/成果/导出绑定同一采用版本 |

| 首次/重复启动与路径 | 同包单实例，拒绝操作无配置副作用；F 盘中文/空格目录、临时不可写和非法目标不触发盘外回退 |
| 首次与重复模板 | 用户能说明左右资料、匹配键、金额/空值政策和输出范围；结构变化停在确认，不猜列位置 |
| 逐文件上传故障 | 成功、失败、未提交可见；恢复只补必要项，资料来源身份不混合 |
| 原生冷启动和故障恢复 | 普通用户从处理入口完成准备；校验/能力/资源原因可区分；响应丢失或服务恢复不重复执行 |
| 调查到交付与重开 | 项目目标、工作程序、输入、规则、异常说明、采用版本和复核版底稿能互相定位；重开明确标记旧交付状态 |
| 下载与冷备 | 用户浏览器真正保存，文件重开内容正确；停止组件后备份/恢复新增领域，旧新版本和关系保持 |
