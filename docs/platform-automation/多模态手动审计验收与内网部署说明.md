# 多模态手动审计验收与内网部署说明

本轮以 v0.9.4 手动工具版为基线，按“导入原件、分析、原件对照、人工校正、核对、归集和导出”建设。工程版本的发布与整体业务验收分别登记；公开及合成样例不能代替业务准确率、人员授权或目标硬件资格。

## 已建设的工作流

| 工具 | 操作与结果 | 判断边界 |
|---|---|---|
| ClearForensics | 原有六类经典分析；CAT-Net JPEG 原始 DCT、区域热图、原图对照、人工框选、参数与报告 | 热图不是整图真实性概率；文档改字与自然图拼接分别评测 |
| 人脸工作台 | YuNet 检测和质量提示；选脸、SFace 两图比对、项目内参考库 Top-K、人工说明、导出和审计引用 | 相似度不是身份概率；阈值尚未用业务样本校准；无活体、视频或反换脸结论 |
| 音频工作台 | 播放、波形、频谱、Paraformer 中文时间戳、VAD、标点、匿名说话人、修订和字幕导出 | 模型原始转写与修订分开；引用前回听；说话人姓名由人工填写 |
| ClearOCR 印章 | 整页布局定位、章内文字及编号、原页区域、人工校正、主体字段转 Data | 文字和主体核对不等于真伪鉴定；低清、遮挡允许无法辨认 |

保留原有 OCR、分类、Data 和经典取证。新增音频片段来源支持起止毫秒和声道；图像结果保留原页坐标与变换。原件哈希、模型哈希、参数、运行环境、实际设备和人工修订分别记录。新增 GPU 路线在完成共享资源协调和推理验证前保持关闭；CPU 工程版本不代表这部分已经交付。

## 内网介质与首次运行

1. 核对外部 ZIP SHA256，再解压到本机 F 盘真实目录。路径可含中文、空格；不使用盘外链接、网络共享或云同步目录。
2. 留足程序、工作区、导出和备份空间。程序包不带业务资料，`workspace` 应为空；业务分类模型及既有数据另行迁移。
3. Windows 11 专业工作站版为目标系统，A4000 16GB 为最低目标显卡，A6000 48GB 为扩展配置。完整 GPU 运行建议 NVIDIA 570.65 或更新兼容驱动，最终按现场实际推理验收。本介质提供官方签名的 572.83 RTX Enterprise 驱动和 VC++ x64 安装材料，不自动替换系统驱动。
4. 先运行 `program\runtimes\platform\python.exe -I -B diagnose.py`。检查 `runtime/diagnostics.json` 是否通过；文件完整性通过不能代替真实处理测试。
5. 双击“启动审计平台.cmd”，访问 `http://127.0.0.1:8879/apps`。可用 `-Port 8891` 改端口；用 `-Action status` 查询、`-Action stop` 停止。
6. 原件、模型、临时目录和全部缓存留在 F 盘；首次加载可能明显慢于后续运行。后台任务可查看阶段和取消，遇错保留任务与日志，按原身份重试。

日常运行无需下载模型或安装完整 CUDA Toolkit。程序自带 Python 环境、模型、字典、配置、DLL、编解码库、字体和许可材料。Agent 默认关闭。本轮网络隔离证据采用 Python socket/audit 拦截和开发目录读取拦截，不等同于操作系统防火墙或物理断网现场认证。

当前门户单文件上传上限为 128 MiB；音频解析另有四小时上限，实际可处理时长取决于格式、文件大小和资源。超限文件、长录音稳定性与复杂多人场景需单独验收，不能用短样例推断。

## 现场逐项验收

CPU 和 GPU 分别建立记录，写明显卡、驱动、内存、程序与模型哈希、实际设备、耗时、峰值内存和显存。对每项能力执行导入、真实处理、人工修订、保存、关闭服务、重开、定位原件、归集和导出。对 ZIP 内文件重新计算哈希，确认原件未变、修订版本一致、时间或区域仍可定位。

共用故障检查包括：重复请求幂等、运行中取消、失败重试、重启后的待核实状态、资源不足和显存不足。GPU 功能须在共享资源控制下与既有 OCR、分类共同验收。不得仅凭权重存在、页面可打开或 `nvidia-smi` 成功登记通过。

## 业务评测登记

| 方向 | 建议样本 | 校准与最终测试必须保留的指标 |
|---|---|---|
| 图像取证 | 300–500 图；正常扫描/压缩、拼接、复制粘贴、文档改字分别覆盖 | 正常图误报、检测召回、区域定位、不同来源稳定性 |
| 人脸 | 约 50 名获准测试人员；多照片及未入库人员 | 检测失败、同人/异人、误接受与漏识、Top-K、未知人员拒识 |
| 音频 | 3–5 小时；多设备、声道、噪声、多人和长录音 | CER/WER、姓名金额日期、时间对齐、说话人分段、资源和稳定性 |
| 印章 | 约 200 页；无章、多章、不同章形、遮挡、旋转、低清 | 区域召回、文字/字段准确率、误检、坐标映射和人工校正成本 |

同一原件及其派生资料不得跨校准集和最终测试集。阈值在校准集确定，最终测试前固定。无样本时登记“待验收”，不填写虚构准确率，不采用统一“99%”承诺。现场完成前，工程版本与整体升级均须保留适用范围说明。

## 备份、恢复与回退

升级前停止门户及原生 OCR、分类进程，对完整工作区做冷备份并核对文件哈希和 SQLite `quick_check`。平台 `scripts/backup_workspace.py` 支持创建、验证及恢复到新目录；OCR 使用其 `--kind ocr` 模式，分类使用自身备份/重定位工具。三部分业务数据必须一并交付，不能只复制数据库而遗漏资料、模型或成果。

新增多模态记录和媒体片段带读取能力声明。旧程序不能直接读取已经写入新记录的工作区；回退使用升级前冷备份的副本和旧程序，新工作区原样保留。不得删新记录强行降级，也不得覆盖已有工作区。回退演练至少检查旧程序可启动、原工作区可读、旧入口可用，以及停止后能够恢复新入口。

## 后续方向

首先完成独立业务集、目标硬件和新增 GPU 路线验收，再按“跨资料比对增强、专项反伪、局域网共享部署”推进。跨录音声纹、多语种 ASR、视频人脸、活体、换脸、音频反伪和参考章精细对齐分别立项；账号、协作和权限随局域网部署单独建设。
