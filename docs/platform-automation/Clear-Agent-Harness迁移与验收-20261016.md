# Clear Agent Harness 迁移与验收

本轮目标：用官方 DeepSeek Harness 接管模型循环、持久会话和上下文整理；Clear 继续负责工具、权限、凭据、原生作业回执、长任务调度及交付验收。默认模型轮数、工具次数和主动执行时长均为空；完成、失败、停止或需要用户输入时才结束或暂停。

## 模型与上下文

模型容量按人工声明、网关元数据、精确连接身份匹配目录的顺序解析。网关别名不会自动继承官方同名模型容量。当前连接保留本地 `65536` 输入总窗口预算和既有输出设置，真实模型容量显示未知；每个运行冻结配置与连接版本。

有效窗口取声明容量和本地上限的较小值，再扣除输出预留与安全余量。占用由实际 HTTPX UTF-8 序列化请求测量，覆盖系统提示、工具、历史及工具结果；提供商 usage 单独保存，缺失数值保持未知。

输入预算达到 80% 时先回收无关工具定义，再生成可追溯的工具结果预览，最后整理较早历史。摘要必须符合结构、明显缩小上下文，保留目标、约束、计划、作业和成果引用；格式不合法时最多修正一次。失败保留原文与进度，并说明原因。原始事件和实际请求正文继续可核对、分页回查。

已经加载的工具候选保存在运行状态中，临时回收定义不会删除加载记录；整理后重新测量并恢复可容纳的工具。新加载工具的保护维持到实际模型回应，不能被同一请求中的多次准备提前消费。真实 HTTP 回归覆盖这两个边界。摘要仍使用当前输出预算 2048，并设置紧凑目标；只有提供方确认 length/max_tokens 时允许一次更短修正，普通 EOF 或未知协议错误不作长度修复。

## 持久化与恢复

- `operations.sqlite3` 保留业务操作意图、回执、模型请求、任务和展示记录，并增加 Harness 运行投影、不可变事件、配置及实际请求正文。
- 原生作业等待通过权威状态查询完成，不消耗模型轮询。页面关闭不会取消服务端运行。
- 模型已收包而 Node 尚未写入 assistant 事件时，从原始回包恢复，不重发 HTTP；已提交工具先查询原操作身份。
- 不可重放且回执未知的写操作进入待核实状态，不按成功处理。
- 暂停、停止与人工接管使用 generation 隔离迟到响应；暂停后立即继续可在旧进程关闭后重新调度。
- 用户修改资料范围时，阻止旧模型回包继续提交操作，在下一安全请求边界应用新范围。
- 连续三个相同无进展动作或连续三轮无进展会暂停；正常等待外部作业不计入停滞。

## 交付与迁移

交付核对真实引用、原生状态及实际成果字节。CSV 完整流式读回，支持行数、去空格、精确文本、小数位和前缀条件；失败保留证据并继续修复。保存草稿也返回精确版本和哈希的可验证结果引用。已修复的同对象错误保留历史，但不永久使交付降为部分完成；未修复的覆盖缺失仍明确显示。

大批成果可用 `delivery_publish(finalize=false)` 逐件保存引用、固定文件身份和验收条件到现有任务记录。批次成功不会结束任务或生成最终答复。最后仅提交总说明即可合并所有条件，服务器重新验证实际字节；不得修改或降低已保存条件，未核实的旧运行操作也会阻止最终交付。已消费批次保留在任务历史，模型当前事实仅携带活动批次和历史索引。

迁移前保留包含已提交 WAL 的原数据库和旧检查点。全量转换完成、失败、等待与运行中会话，并通过只导入模式建立官方 JSONL；不运行模型或工具。转换、实体化与哈希核对分别登记，支持中断续作。原有失败状态和所有项目、会话、下载身份保留。

备份对普通业务 SQLite 使用一致性备份接口；`agent/harness/legacy` 中已经固定哈希的迁移 SQLite 证据逐字节复制，先验证 DELETE 文件头、完整性与无 journal/WAL/SHM。不通过重写迁移清单掩盖证据变化。002 的真实官方备份、恢复及 Agent 重启已通过；001 的失败原件保留。
