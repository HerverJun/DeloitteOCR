已有基础直接复用：

- 资料登记、资料集和成果存储已有后端，资料库与成果中心页面尚未接通。
- 数据工作台已具备 CSV/XLSX/Parquet 导入、清洗、版本撤销、配方复用、比对和下载。后续补成果归集和实际使用问题，不重新开发这条链路。
- OCR 幂等导入已有实现；分类导入和平台跨应用交接仍待补齐。

下一阶段的核心成果：**用户可以管理资料、选择真实应用处理，并在平台找到任务与成果，不需要开发者手填内部 ID。**

## 2. 具体开发顺序

### 第一批：可使用的资料库与成果中心

对应 T036，复用 T030/T031/T035/T044。

分两个可独立交付的切片：

1. **资料可管理。** 完成上传/登记、列表、中文关键词搜索、类型/标签筛选、多选、分页、打开原件与查看来源。选中资料后形成固定输入集合。
2. **成果可找到。** 将数据工作台生成的清洗表、差异表、摘要和来源清单，归集到用户选择的工作空间；成果中心展示版本、输入、生成时间，支持再次下载和返回出处。独立数据作业继续允许不关联工作空间直接使用。

本批只做日常查找、选择和下载，不加入全文/语义检索或复杂标签体系。

**可交付成果：** 从平台登记资料，运行现有数据比对，再从成果中心找到并下载结果，能返回对应输入。提供实际入口和演示成果。

### 第二批：OCR 与分类的实际业务接入

对应 T032/T033/T034，使用现有适配器和任务中心。

先交付 OCR 闭环，再交付分类闭环：

- 从资料库选择输入，再选择目标应用与已有原生项目；需要新项目时通过原应用 API 创建。分类类别集由用户明确选择或定义。
- 补普通用户可操作的项目关联，消除预置链接和手填原生项目 ID 的依赖。
- 完成分类持久幂等导入，将两端接入平台交接记录。重复点击不重复导入，响应不明时查询原请求，部分成功可以继续。
- 用户提交处理后自动登记原生任务，显示真实阶段、成功/失败/未处理数量及资源等待原因。
- 完成后关联成果与出处，手工填写任务 ID 只保留为辅助补录功能。

OCR 的 PDF 场景沿用原生文档/拆页能力并保留页码。保留原应用的人工编辑、标签、数据集划分与模型版本。仅显示原生当前支持的操作与模型能力。

**可交付成果：** 两个应用各有一条“选资料 → 进入正确项目 → 处理 → 查看任务 → 找到成果”的真实流程，普通使用不要求输入内部 ID。

### 第三批：解决连续使用时会卡住用户的问题

对应 T028/T046/T047，复用现有资源协调和数据工作台。

- 刷新、断流或重启后能继续已有作业，失败、取消和待核实状态清楚可见。
- 交接恢复不重复导入，取消不覆盖人工修订、不影响用户其他进程。
- 原生应用异常退出时，门户、数据工作台和已完成成果仍可使用。
- GPU 等待原因可见，资源未确认释放前不允许另一个模型任务取得所有权。
- 用固定十万行样例观察导入、分页、比对、导出和取消；发现实际瓶颈后再优化，不提前做百万行扩展。
- 优先修复错误结果、数据丢失、卡死和核心流程不可用，再统一必要的加载、空状态与失败提示。

**可交付成果：** 一段连续使用演示：提交、取消、刷新、恢复、再次下载均有明确结果。真实 GPU 测量在具备条件时另行记录。

### 第四批：候选包、备份恢复与离线使用

对应 T037/T050/T051/T056；实现顺序为备份与组件准备、候选构建、综合使用检查后演练回退，保留原任务依赖。

- 在一致快照基础上备份数据库、原件、原生项目映射和成果；恢复到新目录后重新打开。
- 修复离开源码仓库后的启动与导入问题，提供统一启动入口；最终用户无需自行安装 Node 或补开发依赖。
- 形成基础门户与可选应用包，固定运行时、模型、依赖版本和许可。缺可选包只影响对应能力。
- 静态资源、字体和运行资源本地化，消除对开发机缓存的隐形依赖。
- 演练候选切换与失败回退，同时处理程序和数据版本，保留旧包和用户原数据。

**可交付成果：** 可启动候选包、一致备份、恢复说明和回退演示。同机隔离验证与独立设备验证分别说明。

### 第五批：集中走通首版并交付

对应 T017/T052/T053/T054/T055/T057，以及前述任务的正式收口。

对固定候选集中走原方案关键场景：三个应用独立使用、旧项目可读取、GPU 协调、交接不重复、同内容多来源保留、单应用故障隔离、任务恢复、离线运行、备份恢复、中文与实际浏览器。

综合使用检查 T052 通过后执行 T056 回退演练，再形成 T057 交付报告；第四批与本批围绕同一候选衔接，不绕过依赖。

**可交付成果：** 候选包、简明使用说明、样例、已知限制、恢复/回退说明及明确的工程/设备/业务资格结论。

真实 GPU、干净 Windows 和业务材料具备时执行相应验证；缺失时记录具体解除条件，保留未通过状态，不虚构结果，也不阻塞其他可交付工程。原始资格任务不取消。

## 3. 避免再次陷入重复工作的规则

1. **从功能切片开始。** 下一次实施先做“资料上传、列表、搜索”，不以重做计划工具、扩验收次数或重绑全部旧回执开场。
2. **小步产生可用结果。** 每个切片交付实际入口和输出，进展报告先说用户新增能做什么。
3. **开发期只做必要检查。** 构建、受影响的小范围检查和一条真实操作冒烟；发现失败后只针对受影响点补查。
4. **全量回归集中。** 同一固定源码与环境的完整基线只运行一次。门户或数据模块没有影响 OCR 时，不启动 OCR 全量回归。固定候选形成后再集中综合验证。
5. **不抹掉未完成。** 旧证据保留，过期记录不伪造通过；正式验收状态在相应功能批次末尾统一处理。
6. **配套工作随功能收口。** 必要的写域、任务记录和 NEXT 随提交更新，不另起长期工具工程。适用用户最新的功能优先要求。
7. **控制首版范围。** 不引入多人企业权限平台、微前端框架、通用流程画布、新 AI 助手、BI 系统或额外行业应用。

数据保真、权限隔离、幂等、取消和恢复是功能的一部分，保留；没有新变化时的重复验收、形式性回执维护和提前优化应压缩。
