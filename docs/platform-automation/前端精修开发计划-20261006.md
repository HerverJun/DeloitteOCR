## 1. 本轮目标

把现有平台打磨为精致、简约、具有科技感的专业审计工作台。视觉中心是用户目标、Agent 对话、真实工具执行和交付成果；手动专业操作继续清楚、可达。

产品路径沿用：提出审计目标并添加资料 → Agent 选择已注册工具/模型 → 执行并读取结果 → 决定下一步 → 交付成果；用户可接管工具、保存修改并带回原任务。

本轮以布局、排版、语义颜色、公共组件和执行反馈为实施范围，沿用门户 React/Ant Design 6、分类 Ant Design 5、OCR Fluent UI。三套界面通过同一静态视觉规范分别适配，公共规范不扩建为跨仓库运行时依赖。主题适配完成后，再精修页面结构。

业务和调度边界沿用 v0.8.1：三个主导航、四类手动工具、现有工具与 Skills、来源版本、操作回执、恢复能力和原工作区。Agent 提示、上下文预算、模型策略、审计规则、数据库结构和原生算法不列入本轮改造。原生静态资源绑定与候选打包只做确保新前端实际交付所需的改动。

## 3. 视觉与交互规范

以下为实施起点。FP02 用实际中文页面完成对比度及小屏核对后，在原主题文件中固定最终值并同步三套映射；后续页面沿用该规范。

| 项目 | 初始规范 |
|---|---|
| 整体方向 | 浅色工作区、石墨色导航、白色内容面、小面积 Clear 品牌绿 |
| 语义颜色 | canvas #F5F7F8；surface #FFFFFF；subtle #F0F3F4；navigation #161C1F；border #E1E6E9；text #1D272E；muted #596873 |
| 品牌与操作 | 品牌绿保留 #86BC25；深绿色 #527A17 用于需对比度的操作/链接，浅绿色 #EFF5E7 用于选中背景；最终组合须实测对比度 |
| 字体 | 沿用本地系统中文字体；正文/表单 14px；Agent 回复 15–16px；辅助信息 13px；12px 仅用于低频元数据，主要操作不用 12px |
| 标题 | 页面标题 26–28px/600；区域标题 18–20px/600；正文行高约 1.6，表格行高按密度校准 |
| 间距 | 4/8px 基础尺度；页面内边距 24px，紧凑桌面 16px；区域间距 24–32px；窄屏 12–16px |
| 外壳 | 页头保持紧凑约 44–48px，侧栏约 216–224px；页面标题与项目上下文减少重复占用 |
| 控件 | 常规高度 36px，主要动作 40px；窄屏关键触控目标至少 44px；控件圆角 6–8px，面板 10–12px |
| 面板与层级 | 内容面使用轻边框；阴影限浮层和必要悬浮层；消息及内部结果避免连续嵌套面板 |
| 图标 | 每个应用沿用现有图标库，统一尺寸、描边视觉重量和文字对齐；不用 emoji 作为功能图标 |
| 状态 | 文字说明配合状态色/图标；GPU 支持、GPU 当前就绪、排队、服务故障分别表达 |
| 动效 | 常规交互 120–180ms；展开/出现 180–220ms；加载标记沿用现有组件；减少动态时关闭非必要位移和循环动画 |
| 可访问性 | 正文对比度至少 4.5:1，焦点及主要图形至少 3:1；可见键盘焦点；执行状态有可访问说明，避免每个流式 token 重复播报 |

Agent 页面具体安排：

- 顶部只呈现当前项目、任务身份及必要状态；背景、口径、Skills 和高级诊断通过现有详情入口展开。
- 空状态突出“描述目标、添加资料、开始”，示例短且少；有对话时让对话占据主要高度。
- 对话阅读区桌面宽度约 800–960px；长工具结果可使用更多宽度。用户消息、Agent 回复、工具执行、最终成果采用不同的轻量排版，不全部做成同形卡片。
- 复用现有消息 ID、事件顺序和运行状态；布局优化不得改变事件协议。连接中、生成中、调用工具、工具运行、等待资源、暂停、失败、完成各有准确标签。
- 仅在真实回复或已有阶段说明到达时显示相应内容，不推断或补写模型的内部思维。进度百分比仅使用原生工具真实进度；未知时显示不定进度。
- 工具活动默认显示名称、简短状态、耗时和可用结果，输入参数及原始日志按需展开。成果保留来源、版本、采用/下载和手动带回动作。
- 阅读旧消息时保持当前位置，提供“有新内容/回到底部”；仅在原有跟随条件满足时跟随流式输出。
- 输入区有稳定位置，附件和次级选项不挤压主要输入；保留草稿隔离、输入法组合输入、发送规则和停止/接管语义。
- 由外壳、工作区、对话阅读区明确分配剩余高度，使用 flex/grid 和 min-height: 0；清理多段视口减固定值的补丁。浮层/输入区不遮挡末条消息。

手动工具目录具体安排：

- Data、OCR、分类、经典取证四项统一名称、图标、用途、状态及主要进入按钮的位置；桌面按可用宽度排两至四列，390px 单列。
- 默认展示用途与真实可用状态；资源、格式、导入导出及控制能力保留在现有声明折叠区。
- 声明来源继续使用 v0.8.1 的后端数据。CPU/GPU 支持不等于设备就绪；503/410 等故障不得美化为“可准备”。
- 状态通过文字和图标表达；卡片有明确焦点与点击目标，按钮操作不被整卡点击覆盖。
