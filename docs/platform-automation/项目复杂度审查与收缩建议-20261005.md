# 项目复杂度审查与收缩建议

日期：2026-10-05。审查对象：正在 8879 运行的 Clear 智能审计 v0.7.0，以及对应平台源码。性质：只读产品与架构审查；本次仅新增本报告，没有修改业务代码、数据、运行配置或旧开发记录。

## 结论

**项目已经出现范围偏宽、入口重叠和维护分散，需要进入收敛阶段。** 用户的复杂感有具体依据：当前产品同时呈现智能审计工作台、专业工具套件、模板批次、待办，以及两套发现/底稿生命周期。

Agent 的主要执行架构合理：当前只有一个 LangGraph 调度主链路，专业工具复用已有服务。权限、资料版本、操作身份、取消代际、未知回执和恢复记录解决实际问题。收缩应优先减少用户需要理解的概念，以及开发时需要同步修改的位置。

产品主线应固定为：**提出审计目标并添加资料 → Agent 调用工具/模型 → 查看过程和成果 → 按需手动调整并继续。** 四个 Clear 工具围绕同一项工作提供能力。

这些规模数据说明维护面已经较广，不作为质量评分。以下结论来自入口、对象和调用关系的实际检查；没有测量真实用户使用频率，也没有运行新的模型调用或业务测试。

## 主要发现

### 1. 产品入口把辅助功能提升为多个工作中心

[App.tsx](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/apps/portal/src/App.tsx:49) 同时提供智能审计、审计项目、资料与证据、发现与底稿、成果文件、工具工作台、设置；高级区另有正式底稿与人工记录、待办、模板批次、运行任务、手动快速处理。

资料、发现、底稿和下载成果都属于用户正在处理的项目或任务，现在需要用户在多个页面之间理解它们的关系。`/apps` 与 `/manual` 又分别提供工具目录和快速处理入口。

**建议：**主导航收敛为“智能审计 / 审计项目 / 手动工具”，设置作为次级入口。资料、发现、底稿和成果成为项目或任务内页；批次、作业和待办作为相关任务的详情。保留现有深链接和业务能力，统一手动工具目录。

### 2. 默认聊天页面仍有重复控制和前置选择

全局项目选择在 [App.tsx](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/apps/portal/src/App.tsx:80)，聊天内还有一次项目选择，以及新任务、最近任务、Agent 技能、项目背景，见 [AgentWorkbench.tsx](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/apps/portal/src/features/agent/AgentWorkbench.tsx:237)。自动草稿保存已经存在，界面仍并列保存目标与发送；人工接管也有多个入口。

查看技能会经过 `openProjectAction`，空白首页没有项目时会先创建项目，见同文件第 123 行。这使单纯浏览能力目录也产生业务对象。

桌面任务侧栏固定占用 300px，无计划、无结果时也显示空区域，见 [agent.css](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/apps/portal/src/features/agent/agent.css:4) 和 [TaskPanel.tsx](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/apps/portal/src/features/agent/TaskPanel.tsx:18)。

**建议：**保留一个项目选择器、一个主要发送动作和一个任务操作入口。已有自动保存继续工作，保存目标放次级菜单；背景、技能和资料口径按需展开。空白首页主要显示目标输入与添加资料；桌面任务详情也可折叠。纯查看技能不创建项目。

上下文、工具和请求诊断在本轮已收进详情，不能继续把它们描述成每轮默认全展开。连接设置中的预算、超时等高级参数仍可进一步折叠，见 [ControllerSettings.tsx](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/apps/portal/src/features/agent/ControllerSettings.tsx:56)。

### 3. 日常审计草稿与正式档案存在两套对象体系

[drafts.py](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/audit/drafts.py:30) 保存任务归属的 `direct_audit_evidence`、`audit_finding_drafts`。旧正式体系使用项目、程序、调查事项、正式证据和人工编制/复核记录。

[service.py](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/audit/service.py:186) 的正式发现证据入口接受已保存的正式证据、取证报告或程序关联批次证据；本次未发现直接将任务草稿及其直接证据按原身份转为正式对象的现成通道。两套对象的 Agent 工具都在提供，见 [platform_management.py](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/agent/tools/platform_management.py:402)。

产品页也同时表达 Agent 项目与“已有正式审计项目”，见 [ProjectHome.tsx](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/apps/portal/src/features/agent/ProjectHome.tsx:24)。

**影响：**用户需要理解两种项目、两种发现和两种底稿；维护需要处理两套版本、证据和导出关系。这是比工具数量更实质的复杂度。

**建议：**对外统一审计项目、发现和底稿的表达，明确任务草稿与正式档案的关系。短期提供统一查询和明确的转正式衔接；后续逐步统一业务身份及关联模型。人工编制/复核作为后续署名步骤保留。数据模型合并另行设计迁移，不在界面收缩时直接改存量数据库。

### 4. 审计执行与模型开发管理同时进入了常规能力说明

[providers.py](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/agent/providers.py:23) 在通用系统提示中列出分类无模型时的标注、发布训练版本、训练后推理路径。[classification_management.py](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/agent/tools/classification_management.py:283) 覆盖训练、模型切换和模型包导出。

这些能力满足此前“Agent 覆盖已有板块”的要求，但维护范围已经包含模型开发管理。现有训练 Skill 已说明训练需要用户目标授权，本次没有发现越权训练的复现证据。

**建议：**保留训练和模型管理能力；普通审计优先使用已发布模型。只有目标明确包含标注、训练或模型切换时，才引导发现相应工具组和专用 Skill。通用系统提示保留执行规则，具体 OCR、分类流程由相应 Skill 承担，减少两处同步维护流程说明。

### 5. 维护复杂度来自分散的协调和重复实现

已确认以下同步点：

- 原生准备分别出现在 [batches/native.py](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/batches/native.py:120) 与 [application_services/native.py](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/application_services/native.py:24)。它们共用下层服务；应逐步统一任务准备与恢复事实接口。
- [runtime.py](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/agent/runtime.py:591) 与 [tasks.py](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/agent/tasks.py:153) 分别实现取消状态、代际和展示收尾。可以集中为支持现有事务调用的取消操作。
- 新任务族需要同步恢复、读取/取消、进度、结果转换和引用核实，分散在 runtime、jobs、progress、results、references 等模块。代表入口为 [runtime.py](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/agent/runtime.py:307)、[jobs.py](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/agent/tools/jobs.py:40)、[progress.py](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/agent/progress.py:57)。建议集中同一工具族的适配登记。
- 请求组装经 [runtime.py](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/agent/runtime.py:196) 和 [skills.py](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/src/workbench_platform/agent/skills.py:295) 触发重复 Skill 来源扫描；静态调用路径包含三次完整扫描。建议单轮生成一次上下文快照并复用，保留版本固定与完整性校验。具体耗时尚未测量。

另有迁移双轨：`tool_step` 保存完成回执、引用和覆盖信息，`tool_activity` 保存生命周期。同一调用部分状态和摘要重复，但两者仍有不同消费者；需要迁移消费者和补齐字段后，才能停止新记录的双写。

`as_langchain_tool` 和旧 `bounded_messages` 在本次仓库引用检索中只由测试调用，可核对外部约定后退役或移出生产模块。它们不是当前主执行路径。

OCR/分类的 `settle` 会恢复 paused 任务，代码没有明确区分人工暂停与冷恢复中断。本次仅记录控制权需要明确的结构风险，尚未复现人工意图被覆盖。

**建议：**集中已有实现和登记点；当前单一 Agent 调度循环继续作为主线。批次作为一种已注册能力参与执行。

### 6. 交付与文档没有形成唯一的当前入口

[package_agent_candidate.py](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/scripts/package_agent_candidate.py:91) 使用绝对共享 `program` 路径，启动 CMD 也绑定带日期的开发目录。共享模型和独立 Python 环境有实际依据，但当前版本的用户启动方式仍依赖研发目录布局。

[主开发索引](F:/OCR/docs/platform-automation/README.md:3) 仍写流式改造尚未实施，第 7 行还写产品改造尚未实施，与本轮完成报告和当前运行版本冲突。[Agent 使用说明](F:/OCR/output/clear-automation-dev-20261002/worktrees/platform/docs/agent/README.md:15) 仍引用较早一轮的停止脚本。旧计划可以保留，但当前状态不能让接续者从多份文件推断。

**建议：**建立一个稳定安装根、一个启动入口和一份当前版本登记；日期目录保留研发证据。主索引只指出当前候选、源码、工作区、启动/停止方式及唯一活动任务清单；旧计划明确标为历史。共享模型继续复用，依赖环境继续隔离。

## 下一轮建议限定的范围

1. **先简化用户入口。** 收拢导航、去掉重复项目选择和主要操作，折叠任务详情与高级配置；统一手动入口和带回当前任务的路径。保持服务接口和现有资料/成果有效。
2. **集中维护热点并整理交付。** 合并取消实现，复用单轮请求上下文快照，集中原生任务族适配；同步唯一启动登记和主文档当前状态。
3. **统一业务表达与衔接。** 明确任务草稿、证据、发现和正式档案的关联及转正式方式；冻结新增底稿体系，后续按迁移设计逐步统一对象。

这轮收敛期间暂停新增业务模块和新的调度机制。完成的判断应直接观察：描述目标无需额外准备步骤；过程和成果围绕当前任务可找到；手动调整能回到原任务；增加一种工具族无需到多个无关模块同步分支。

应保留：四类专业能力与手动操作、单一 LangGraph 执行循环、按需工具加载、真实模型/任务状态、权限和来源校验、操作幂等、取消代际、恢复及未知回执语义。源代码中的复杂度需要按职责收敛，不能通过移除这些机制来换取表面简洁。
