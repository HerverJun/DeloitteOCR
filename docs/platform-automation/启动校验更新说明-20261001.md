# 首次启动校验与进度反馈更新

日期：2026-10-01。按用户新增要求，当前版本改为同一安装首次完整校验成功后复用记录，并显示校验反馈。更新已经接入原交付目录和 8784 演示，未发现未解决阻断问题。

## 使用行为

- 首次启动仍逐件校验 OCR/分类文件。门户先可用；卡片显示等待、校验中、完成和失败，以及百分比、文件计数、用时和当前文件，每两秒更新。两应用启动状态仍一次发布，无需刷新页面等待开放。
- 成功记录绑定当前程序清单 SHA256、安装位置和校验规则版本，保存在 `program/data/startup-verification.json`。后续启动只核对应用声明和必要入口，不再扫描全部模型/运行时文件；更换用户数据目录可复用同一程序包的记录。
- 点击原生启动也复用同一完整校验结果，同时仍检查安装字段、应用/包声明、必要入口哈希和实例所有权。复用凭据绑定当前目录代次；重新加载安装目录会作废本代凭据，没有凭据的安装仍走原完整声明校验。
- 程序升级、搬移、成功记录缺失/损坏或入口不匹配时重新校验。失败或未完成不存成功。需要重新排查时先停止服务，再运行交付根的 `完整校验并启动.cmd`；该入口先作废旧记录。独立 `program/verify.cmd` 的全文件校验仍保留。
- 日常快速启动不逐件检测非入口文件的内容变化；这一边界与仅首次全验的策略一致。
