U01 的源码原因：`apps/portal/src/features/artifacts/ArtifactCenter.tsx:160` 保存页码，第 163 行按该页码查询，但没有随 workspace 变化重置。第 190 行只在 total>20 时显示分页。`apps/portal/src/App.tsx:81` 的顶部项目选择只切换 URL，当前 ArtifactCenter 组件的 page 状态继续保留。由于乙项目总数小于一页，用户无法用分页控件返回正确位置。本轮使用真实项目选择和界面，仅对成果列表提供甲 21 项、乙 1 项的受控夹具；没有编造或改写真实成果文件。

U02 的源码原因：`apps/portal/src/App.tsx:130` 新建项目只提交 schema_version/name，没有稳定创建请求身份；`src/workbench_platform/workspaces/routes.py:132` 每次调用 store.create_workspace，`src/workbench_platform/store/workspaces.py:233` 每次生成新的 UUID。本轮首次 POST 由真实后端完成，随后仅丢弃其浏览器响应；第二次通过普通弹窗重试提交。数据库中的两个不同项目 ID 和同名项目数量 2 均已实际读回。创建记录只在本轮隔离工作区。

另核查了异步导入失败提示：真实上传损坏 XLSX、执行隔离 Data worker，任务返回 failed，页面显示“处理失败，请检查文件格式、工作表和列映射。”及“导入失败”。`DataWorkbench.tsx:401` 已展示最终任务错误。这一怀疑已排除，不列为 bug。本轮执行页面未出现 JavaScript pageerror；这不代表所有流程已无 bug。
