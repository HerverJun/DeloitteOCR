# Clear 智能审计平台收束开发计划

日期：2026-10-05。执行状态以 [8 项任务清单](platform-convergence-tasks-20261005.json) 为准。本文件定义范围与完成条件，不另存一份任务进度。

依据：[项目复杂度审查](项目复杂度审查与收缩建议-20261005.md)。当前产品基线为 v0.7.0，详见 [流式交互完成报告](F:/OCR/output/agent-streaming-ux-dev-20261005/完成报告.md)。本计划承接已完成开发，成为下一轮唯一活动计划。

## 1. 目标与范围

把平台收束为一条清楚的工作路径：

> 描述审计目标、添加资料 → Agent 选择已注册工具或模型并执行 → 持续查看过程和成果 → 按需手动修改 → 回到原任务继续。

本轮完成三件事：降低默认界面的选择负担，集中执行链路的重复实现，明确日常草稿与正式档案的关系。四类专业能力继续服务这一主线。

| 项目 | 本轮目标 |
|---|---|
| 主导航 | 7 个一级入口收为 3 个：智能审计、审计项目、手动工具；设置放次级入口 |
| 项目选择 | 全局保留 1 个；聊天内重复选择器退出 |
| 开始任务 | 输入目标、添加资料、发送；创建项目和任务继续按需自动完成 |
| 默认任务详情 | 可以收起；无计划、无成果时不显示空栏目 |
| 人工处理 | 一个接管入口、一条带回路径；独立导入结果放扩展区域 |
| 取消逻辑 | 两处重复 SQL 收为一个支持调用方事务的操作 |
| Skill 来源扫描 | 每模型轮最多一次来源扫描，复用固定请求输入 |
| 原生作业适配 | 读取、恢复、取消和进度按工具族集中登记 |
| 发现与底稿 | 一个项目入口、明确的草稿和正式档案关系；可按固定版本转档 |
| 启动交付 | 固定 F 盘入口和当前版本登记；现有模型资产继续复用 |

106 个注册工具继续按需加载，不以机械减少工具、文件或代码行数作为完成条件。保留单一 LangGraph、操作账本、来源与版本校验、取消代际、未知回执和冷恢复能力。

本轮暂停新增业务模块、Agent 调度框架、通用 workflow 或审批引擎。分类训练和模型管理保留为目标相关的专业能力；普通审计优先使用已发布模型，不增加额外的训练管理产品入口。

## 2. 用户界面的确定安排

### 主导航与旧路由

| 主入口 | 组织内容 | 兼容路由 |
|---|---|---|
| 智能审计 `/` | 当前任务对话、资料范围、执行反馈、采用结果与下载 | `/agent` 继续兼容首页 |
| 审计项目 `/projects` | 项目概况；同一层资料、发现、成果；正式档案及相关运行详情按需进入 | `/workspaces`、`/assets`、`/findings`、`/artifacts`、`/audit`、`/todos`、`/batches`、`/jobs` |
| 手动工具 `/apps` | 一个工具目录，进入现有四类工具、快速处理与专业设置 | `/manual`、`/apps/*`、旧 `/data`、`/forensics` |
| 次级设置 `/settings` | 模型连接、技能管理、高级参数和产品设置 | 原设置路由继续可用 |

旧页面可先保留，仅修改导航归属、项目内入口和返回链接。`workspace`、`session`、`bundle`、`task_return`、来源引用及其版本参数完整保留。项目级归集视图不自动扩大当前任务的资料授权范围。

### 首页与人工处理

默认首页以输入区和添加资料为主。自动保存草稿继续工作；“保存目标”进入次级操作。背景、口径、任务计划和技能调整收入任务详情。技能目录、版本与资源阅读进入设置或高级区域；单纯浏览这些信息不创建空项目。

模型连接默认呈现地址、模型和凭据，协议、输出参数、预算、超时放高级区域。真实失败、上下文超限、来源更新和运行状态保持可见，技术诊断仍可展开。

人工路径固定为“接管 → 打开相关工具 → 保存 → 选择成果带回”。默认候选来自当前任务相关资料和成果；独立导入的原生结果仍可从扩展区域接回。用户选择结果和版本、确认新增资料范围，原有操作回执及固定来源保留。取消带回不暗中恢复 Agent，浏览结果也不隐式接管。

默认顺序：**SC01 → SC02 → SC03 → SC04 → SC05 → SC06 → SC07 → SC08**。SC04 与 SC05 可独立开发，SC07 的契约梳理、SC08 的入口设计也可提前只读准备。共同修改 runtime、store、contracts、App 或同一数据库服务时由主执行者集成，避免并行覆盖。

阶段 A 先给出可启动的界面候选，使用户能够直接看到选择负担减少。阶段 B 集中维护热点，阶段 C 衔接业务对象并统一最终交付。任务完成后更新同一份任务清单和证据，不再维护另一套并行进度 JSON。

### SC04：取消与接管的实现边界

在现有 AgentStore 中提供可参与调用方事务的取消操作，供 runtime.cancel 和 AuditTasks.control 复用。接管的 manual、scope、revision 与 generation fence 保持原子更新。停止 Agent 与取消原生作业继续分别表达；默认接管保留原生 job ID 和成果。

重复取消不反复增加代际，已完成 run 不变为 stopped。接管冲突完整回滚；取消后的迟到回复和 settle 不能提交新结果或恢复原任务。

### SC05：请求快照与提示责任

同一任务分两个顺序步骤实施：先收敛请求组装，保持 SYSTEM、Skill 正文和权限语义；结构检查通过后，再迁移通用提示中的重复专业步骤，单独检查行为变化。

每模型轮固定所需任务事实、环境、技能目录、激活技能的固定字节/版本、权限和工具选择，复用到请求构造与账本。请求快照承担本轮输入固定，不承担跨服务原子事务。来源变化按现有版本检查处理；received 恢复使用原请求快照，未知响应不自动重发。

input_state_version 包含 SYSTEM/host_contract。提示迁移须保留已保存请求的原提示/契约快照或等价兼容版本，以原版本核对 received 恢复。原固定输入无法核实时保留原回执并按原冲突机制停止恢复，不自动重发。目标、范围、权限或契约的实质变化仍须拦截；不能通过忽略哈希差异或放宽输入冲突检查解决兼容性。

不引入跨轮缓存、后台 watcher 或新的缓存失效系统。保留 14 核心工具、按需发现、预算计算和原始历史。通用提示保留执行、授权、来源和交付规则；OCR、分类等详细步骤由已有 Skill 承担。训练/模型切换须对应用户明确目标，已有专业能力仍可调用；不增加意图分类服务或逐工具确认流程。

### SC06：原生作业适配与暂停调查

在现有 application_services/Agent 适配边界内，以轻量登记表选择已有 read、settle、cancel、progress 函数。业务实现继续在原工具族，不创建新插件发现或调度层。范围限定为已有 job_ref；没有 job_ref 的未知提交恢复继续沿用原账本机制。

先核实 OCR/分类的 paused、interrupted、人工暂停与冷恢复标记，以及原生手动入口是否保存控制来源，使用隔离场景判断 observer 是否覆盖人工意图。当前审查只确认结构风险，没有证明缺陷。确认的 interrupted/冷恢复沿用必要恢复；确认的人工暂停保持暂停。历史 paused 原因未知时保留原 job，只读观察并提示在原工具恢复，不能自动推定冷恢复。新增控制意图只覆盖后续动作，按调查结果作最小修复，不全面重写原生暂停入口。

本轮不合并模板批次与 Agent 的顶层业务事务；先统一作业生命周期适配。原生准备中的相同低层步骤可在后续据实际重复进一步提取。

### SC07：草稿转档的确定方案

- `workspace_id` 对应用户看到的项目，session 为项目内任务；现有正式审计项目作为正式档案。一个工作区可有多个正式档案，转档明确选择目标，不强行建立一对一关系。
- AuditDrafts 已属于 AuditService 并共用 AuditStore。本轮保留现有表与 ID，复用正式实体、evidence_snapshots、请求回执和历史；不全量合库，也不新增第三套发现或底稿存储。
- 扩展现有正式发现创建接口与对应工具，使其可接受固定的源草稿身份、修订和哈希。服务端读取源版本并转换；界面提供明确的转档动作。通过现有回执保证同请求同记录，参数改变的重放冲突。
- 正式直接证据引用沿用已有 DirectEvidenceSnapshot，补齐正式 selection/ref、查询、执行依据、渲染、导出和过期判断的支持。保留源 evidence_id、哈希及完整 origin；目标正式快照使用所属档案的现有身份并关联源身份。同一源证据可以转入不同正式档案，各档案快照互不覆盖，不把源 ID 当作多档案共享主键。不重跑业务工具，也不伪造 batch。
- 绑定源草稿修订、任务范围/背景版本、证据哈希和目标所见版本。完整保存事实、解释、口径、待补信息、建议、原作者及转档操作人。
- 转档生成正式草稿；不自动 resolved，不生成 prepared/reviewed 人工署名。日常底稿生成和下载仍无需进入正式人工记录流程。
- 源草稿后续修改不暗中改变正式快照；统一视图展示正式关联与来源更新情况。跨 AgentStore、原生服务和 AuditStore 使用固定来源、版本保护和回执恢复，不承诺跨库原子提交。

### SC08：稳定入口与数据兼容

规划稳定产品目录为 `F:\OCR\release\Clear`，其中提供一个启动入口、状态/停止方式和 `current.json`。登记当前候选及身份、共享 program、工作区、端口、数据兼容要求。第一阶段直接引用现有资产路径；旧 program、模型和历史候选保留，不复制模型或搬迁目录。

复用候选 launch.py 的哈希校验、数据目录锁、私有原生绑定和 storage_environment；当前进程及子进程的临时、缓存、日志和应用数据均明确落在 F 盘。启动失败不改工作区、不自动下载或调用模型。停止只针对已核实身份的自有进程。

稳定入口消除用户对日期目录和多份启动说明的选择；共享资产实际路径仍由登记表明确引用。候选切换写回执，失败保留原登记。兼容检查依据实际数据库结构、迁移版本及记录格式，不只比较产品版本。旧候选打开新记录前检查兼容性；发生不兼容时使用备份恢复到新目录或保留当前候选关闭 Agent，不能直接修改指针降级读新数据库。

每项在任务清单记录真实证据路径与结果。SC08 复用前面完成且仍适用于最终源码的证据，补最终集成场景；只对新修改影响的检查重跑。使用本地 HTTP 控制器和隔离工程数据检查链路，不重放用户旧聊天；本轮不自动调用保存的远程连接。原生模型算法与 GPU 训练未改动时，不重复运行全量 GPU 资格检查。

最终串起两个实际场景：一次从目标与资料到真实数据成果，再手动调整后带回；一次将已有发现按固定版本转入正式档案并读取/导出。确认流式显示、停止、重连和历史引用在新候选中继续工作。
