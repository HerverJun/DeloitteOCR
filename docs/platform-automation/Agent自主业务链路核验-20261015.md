## 发现并修正的实际阻碍

首轮不是业务成功：原主控配置 context_cap=16384、预留输出 2048，加载数据与计划等工具后，下一次请求估计需 19887 输入 tokens，超过可用 14336，运行明确 failed。此时只执行了目录与契约查询，没有创建数据作业或导入资料。

随后在同一会话和选中资料范围内，以新请求身份开始新运行，保留原 failed 运行；不是修改旧状态，也不是假称原失败已自动恢复。上表为调整后的真实执行结果。64K 是当前配置上限，本轮请求成功不等同于已认证第三方模型服务的完整上下文窗口。

## 自主长任务机制与边界

LangGraph 遇到 pending 工具结果时进入 await_jobs，保存 checkpoint 并中断。后台观察器约每 0.5 秒读取权威业务状态；完成后恢复图执行，更新工具回执，再调用模型决定下一步。该过程由服务器执行，不依赖网页保持打开。电脑与后台服务仍须保持运行。

当前每轮默认最多 20 次模型调用、60 次工具调用。后台等待不等于消耗模型轮次；预算耗尽会等待明确追加预算。缺少信息、原生状态不明、连接变更或结果无法核实时会停止或请求人工处理，不会无限重试。

启动代码支持从 checkpoint 恢复运行与等待状态；不明确的外部请求不盲目重发。本轮没有对运行中的正式服务实施断电或重启注入，也没有进行数小时 OCR/训练、多工具交叉业务或所有失败分支资格验收。此次 3 分钟数据链路不能被表述为所有长任务已可靠无人值守完成。

优先补齐项是新多模态 Agent 工具、目标业务跨工具链的真实验收、预算与异常后的续作体验，以及隔离环境中的数小时/中断恢复资格。
