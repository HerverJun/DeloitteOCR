## 导航层级

首页保留为总览入口，其余页面按以下四组组织。组标题用于解释层级，不增加中间页面。

| 分组 | 入口 | 工作目的 |
| --- | --- | --- |
| 审计作业 | 审计项目、统一待办、成果与底稿 | 管理审计对象与程序，推进人工调查和复核，查看各工具报告与底稿 |
| 资料处理 | 资料库、处理批次、运行任务 | 管理输入，组织按模板处理，查看执行状态及中断恢复 |
| 应用工具 | 应用 | 统一选择 Clear 系列工具，查看实际服务状态并打开 |
| 平台管理 | 工作空间、设置 | 管理作业上下文与平台配置 |

“统一待办”处理需要人工判断或继续处置的事项；“运行任务”记录工具执行及技术恢复。“处理批次”是模板化处理的作业单位；“应用”是工具目录。工作空间管理跨工具上下文，实际选择继续使用顶部切换器。

## Clear 应用目录

| 品牌 | 功能名称 | 前端入口 |
| --- | --- | --- |
| ClearData | 数据清洗与比对 | `/apps/data` |
| ClearClassify | 图像分类与复核 | `/apps/classification` |
| ClearOCR | 文档识别与校对 | `/apps/ocr` |
| ClearForensics | 图像取证与审阅 | `/apps/forensics` |

四个工具使用同一个目录网格与卡片结构：品牌、中文功能、用途、实际状态、操作入口。原生应用继续按现有安装及实例核实条件启动，图像取证进入后使用工作空间。原生工具的输入类型和资源声明收纳在可展开的工具声明中。

单个工具不占独立一级导航。应用详情及工作流页均高亮“应用”，页面保留返回应用目录入口；审计、成果、待办等业务页面仍可按当前事项直接进入相关工具。

## 链接与新增应用规则

- 图像取证新链接统一使用 `/apps/forensics`。旧 `/forensics` 地址使用替换式跳转，保留完整查询参数与锚点，包括工作空间和报告身份。
- 导航和目录打开工具继续携带当前工作空间。报告链接保留原任务身份。
- 品牌显示名称统一维护于 `apps/portal/src/clear-ui/theme.ts`，不修改后端 API、持久化标识或固定证据身份。
- 后续工具首先加入应用目录，使用 `Clear + 能力名称` 品牌和中文功能说明；只有新增独立业务对象或流程时才扩展业务导航。
- 首页不将独立图像取证宣传为已实现的模板批次场景；图像取证从首页应用列表或应用目录进入。
