# 最终阶段构建与验收

本文件补充第二、三周构建说明。最终验收状态由《最终阶段验收矩阵》记录；命令成功只证明对应范围，不能代替其他机器或数据的实际测试。

## 构建顺序

1. 从已验证基础包制作新的构建目录，保留旧交付。按 `config/service-requirements.txt` 安装离线 wheels；service 新增 `psutil==7.2.2`，用于验收的进程内存监测。21 个完整闭包 wheel 的文件名与 SHA-256 见 `config/service-wheelhouse.json`，全部版本另锁定于 `config/runtime-locks/service.txt`。已实际从官方嵌入式 Python 空目录以 `--no-index` 重建并核对版本及原生依赖加载。
2. 前端执行 `npm ci`、`npm run test`、`npm run build`，把完整 dist 复制到包内 web。`scripts/sync_bundle.py` 同步源码、配置、说明和验收工具，但不构建前端或启动器。
3. 按原说明运行 `scripts/build_launcher.py`。本阶段启动器必须包含 `--verify-startup`，旧启动器不能证明自动启动自检。
4. 执行 `scripts/lock_bundle.py --bundle <包目录>` 生成完整文件清单与运行时锁；不能只生成 metadata 后立即启动，因为启动器要求完整 manifest。清单只排除根目录 cache/runs/results 和 Python 字节码缓存，不能排除依赖内部同名目录。
5. 使用 service 嵌入式 Python 跑全部 unittest，用 `audit_dependencies.py` 验证精确版本闭包，整理 licenses 索引。修改任何包内代码或文档后，都要重新生成与核验文件清单。
6. 最终归档使用 `package_bundle.py` 与 `verify_archive.py`；源码从已提交的 Git 树归档并逐 blob 核验。公开研究数据与用户项目留在包外，不装入分发 ZIP。

## 本机专项

以实际构建目录替换下列路径，证据目录须为空。全部 GPU 验收按顺序运行，避免竞争。

```powershell
& "E:\build\bundle\runtimes\service\python.exe" -B -X utf8 -I scripts/audit_application.py --bundle "E:\build\bundle" --output "E:\build\application"
& "E:\build\bundle\runtimes\service\python.exe" -B -X utf8 -I scripts/audit_load_cycles.py --bundle "E:\build\bundle" --output "E:\build\cycles"
& "E:\build\bundle\runtimes\service\python.exe" -B -X utf8 -I scripts/audit_batch_stress.py --bundle "E:\build\bundle" --output "E:\build\batch"
& "E:\build\bundle\runtimes\service\python.exe" -B -X utf8 -I scripts/audit_failure_recovery.py --bundle "E:\build\bundle" --output "E:\build\recovery"
& "E:\build\bundle\runtimes\service\python.exe" -B -X utf8 -I scripts/audit_fidelity.py --bundle "E:\build\bundle" --output "E:\build\fidelity"
& "E:\build\bundle\runtimes\service\python.exe" -B -X utf8 -I scripts/audit_table_scenarios.py --bundle "E:\build\bundle" --output "E:\build\table-scenarios" --real-case "E:\research\multi-table\case.json"
```

500 张压力样例是不同内容哈希的合成表格，用于吞吐与内存趋势；不是准确率数据。失败恢复工具只损坏隔离测试项目的一个处理版本，在确认后续任务成功后恢复完全一致的字节再重试，不改写任何识别输出。OOM 信息与取消回收的单元测试须和实际 GPU 测量分开说明。

浏览器审计使用 `run_ui_audit.py --build-root <构建根目录>`，随后以 `--features-only` 验证新增界面。后者使用前一轮创建的项目，并需要 `<构建根目录>/engine-packages/ppocr-validation-v1.zip`。Edge headless 加 `--disable-gpu --disable-gpu-compositing`，脚本结束关闭浏览器和自身启动器。生成截图之后先确认浏览器已退出，再做最终归档操作。

重复验收时可指定 `--data <新的隔离项目目录>` 和 `--output <新的证据目录>`，两次 GUI 流程使用同一 data，分别保存 core/features 输出，保留旧证据。`verify_ui_exports.py --evidence <core 输出>` 独立读回四格式；features 输出另加 `--features`，核对逐图 ZIP、汇总工作簿、字符串长编号和合并关系。正式 GUI 回执记录实际健康接口版本和包清单哈希。

`--diagnostic-service-only` 只用于已经停止工作台时的对话框缺陷诊断，必须同时指定 `--features-only` 并设置 `OCR_DIALOG_ONLY=1`、`OCR_ENGINE_ONLY=1`；其输出为单独的 `dialog-diagnostic.json`，不能作为启动器、全量自检、实际引擎激活或完整 GUI 的验收证据。正式验收清除这些环境变量，并按上一段命令执行。

## 完整离线引擎包

```powershell
python scripts/build_engine_package.py --bundle "E:\build\bundle" --engine ppocr --id ppocr-validation-v1 --version validation-1 --output "E:\build\engine-packages\ppocr-validation-v1.zip"
```

包内为 `engine-package.json`、app、runtimes、models、config、locks 和相关许可，不能只压缩权重。ID 不可复用以覆盖已安装版本。清单列出除自身外每个文件的相对路径、字节数和 SHA-256，协议为 `file-ipc-v1`。暂存不能执行包内代码；启用须复验清单、独立依赖加载和真实识别。更新与任务执行共用 GPU 排他控制，旧任务固定包 ID。

## 公开数据补充评测

`prepare_public_benchmark.py` 使用固定 OmniDocBench revision，按确定性规则从 200 个不同页面裁剪 200 个原始标注区域，保存原图哈希、裁剪坐标、标注及图片哈希。`research/public-benchmark-review.json` 记录手写类型的逐图检查；两张印刷内容从笔记类别中重新分类，原转录不修改。

```powershell
python scripts/prepare_public_benchmark.py --labels "E:\research\OmniDocBench.json" --output "E:\research\benchmark"
& "E:\build\bundle\runtimes\service\python.exe" -B -X utf8 -I scripts/evaluate_benchmark.py --bundle "E:\build\bundle" --benchmark "E:\research\benchmark\benchmark.json" --output "E:\research\evaluation"
python -X utf8 scripts/report_benchmark.py --evaluation "E:\research\evaluation\evaluation.json" --benchmark "E:\research\benchmark\benchmark.json" --table-review research/public-table-review.json --output "E:\research\report"
python -X utf8 scripts/prepare_multitable_case.py --labels "E:\research\OmniDocBench.json" --benchmark "E:\research\benchmark\benchmark.json" --output "E:\research\multi-table\case.json"
```

评测逐项落盘，可在相同清单哈希下继续未处理项目。CER 为 NFC 后去除空白的字符编辑距离除以标注字符数，同时保留含空白的严格指标。不修正大小写、标点或识别文字。文字数字字段预先定义为至少 4 位的数字 token，按保留空白的原文分词；表格数字字段按表号/行/列匹配完整单元格。结构指标是精确单元格跨度 F1 和完整结构一致率，不冒充 TEDS。PP-OCR 的结构能力标为不支持。

这套区域评测不代表整页、手机拍照或内网业务准确率；原标注框偶有邻行残片，须在失败样例分析中说明。数据集声明仅限研究、不可商业使用；研究图像与原标注保留在外部评测目录，源码只分发准备脚本与哈希审计记录。

报告工具需要构建 Python 中的 matplotlib，生成中文指标报告、静态 PNG、类别切片和本地错误图册；运行应用不依赖 matplotlib。真实多表专项按同一数据源和确定性页面顺序选取已经下载的完整页面，保留全部非忽略表格原标注；另有合成多表、已知透视投影和已知几何逆变换，明确不把这些称为真实手机照片。每个有表格的实际模型结果经文字修改、Excel 导出及独立读回，核对工作表数、字符串和合并关系。

`report_stability.py` 从 500 张批次与 20 次循环的原始记录生成内存/显存图和哈希回执。`collect_final_evidence.py` 只复制明确列出的工程与指标证据，排除项目数据库、会话令牌、诊断日志和公开研究图像/原转录。任何必需门槛没有通过时，收集结果的 `final_release_passed` 仍为 false；收集文件成功不代表发布验收成功。

## 外部机器硬门槛

在另一台无开发环境、禁止联网的 Windows 上解压运行，并测试两个不同盘符及中文/空格路径。机器仍需预装兼容 NVIDIA 驱动和浏览器。先以管理员运行包内 `tools/offline_guard.exe BUNDLE OUTPUT --application`；日常程序不需要管理员权限。WFP 动态规则只阻断被列出的 OCR 程序外网连接，退出自动清除。

`offline_guard --application` 使用应用审计的 `--quick` 路径，验证真实启动器与四引擎在系统禁网下工作，省略崩溃/交互专项；完整应用回归另运行不带 `--quick` 的 `audit_application.py`，两种证据不能互相冒充。

新禁网回执包含机器标识的 SHA-256 与应用 manifest 哈希。随后使用该机器的 service Python 运行包内 `tools/target_machine_acceptance.py`，指定 `--role clean-windows` 或 `--role a4000`、`--os-isolation-evidence <本次禁网证据目录>`、`--bundle` 和新的 `--output`。干净机器还须由实际操作者明确添加 `--confirm-no-development-environment`。命令扫描仅为辅助，不代替操作者核实系统没有开发依赖。

工具拒绝开发机指纹、不同机器/版本的禁网回执以及不符合 RTX A4000 / Xeon W5-2455X / 64 GB 的目标配置。A4000 角色继续运行真实应用、20 次加载卸载和 500 张队列。保留各次机器、盘符与路径记录，并在内网真实标注样本上另行复核。没有这些实测记录时，不宣称最终交付全部通过。

目标机工具还检查实际回执中的 20 次循环、500 张完成数与采样显存，剩余小于 2048 MiB 会保留为不通过。这只覆盖工程样例负载，内网大图负载仍需单独测量。

最终清单与冻结测试清单使用 `verify_tested_components.py --tested-manifest <应用实测清单> --final-manifest <最终清单> --output <对照回执>` 比较。可用 `--inference-manifest` 附加更早的独立适配器评测清单；该路径没有执行 HTTP service.py，唯一允许单独由后续应用测试覆盖的代码差别是此文件，所有差别仍显式列出。包完整性另外经过完整 ZIP 解压、CRC 和逐文件 SHA-256 校验。

`compare_evaluations.py --before <基线 evaluation.json> --after <新版 evaluation.json> --output <对照.json>` 核验相同数据哈希、逐图状态/指标与全部成功原始输出。保持失败项，忽略 Hunyuan 请求 ID/时间等非确定性元数据；不将研究转录写入分发用差异报告。
