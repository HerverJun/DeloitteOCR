# 第二、三周开发范围与验收契约

依据开发总纲，第 2 周完成应用基础；总纲未单独拆分第 3 周与第 4 周，因此本次覆盖其列出的交互功能，形成可实际使用的“导入照片 → 识别 → 校对 → Excel”闭环。

## 必须完成

1. React + TypeScript + Vite 三栏中文工作台；所有静态资源离线随包提供。
2. PySide6 托盘与 PyInstaller onedir 双击启动器；本机服务启动、状态、重新打开浏览器、退出与子进程清理；FastAPI 只绑定 loopback。
3. SQLite 项目、原始图片、处理版本、识别结果、人工校对及历史持久化；重开项目与程序重启后恢复。
4. 统一 EngineAdapter 能力声明、加载、识别、取消、卸载；四个真实引擎独立进程；单 GPU 串行，切换不残留进程。
5. 持久化任务队列：创建、暂停、继续、取消、失败重试；异常退出任务恢复为待用户继续状态，已完成项不重复。
6. 文件/文件夹/拖放导入与实际解码；缩放、旋转、裁剪、四点透视、局部框选、EXIF 归一化、可选对比度与去弯曲；保留原图和每次处理版本。
7. 照片文字、手写、表格、模型对比四入口；区域重识别、点击结果定位图片、四模型结果独立对比与选择，显示耗时与文字差异。
8. 文字编辑、复制、搜索；表格单元格编辑、增删行列、合并拆分、撤销重做、自动保存；原始识别与人工修改始终分开。
9. TXT/Markdown/JSON/XLSX 导出，多表独立工作表，可汇总选中结果；保留前导零、长编号、空单元格、合并与文本类型。
10. 针对状态转移、取消/恢复、编辑持久化、几何处理和导出做自动化测试；真实四引擎通过新服务运行；浏览器端实际走完整流程并保存截图/验收证据；新便携包与源码归档并核验。

## 仍属于后续阶段

500 张压力与稳定性、200 张标注准确率评测、另一台干净 Windows、A4000 性能与显存预算、引擎包导入/回退。此次不以这些未完成事项冒充已通过。

## 完成后的动作

用户已明确要求完成并确认无误后关机。只有上述交付及验证完成、源码和证据保存、服务与引擎退出后才执行 Windows 关机；不使用强制结束其他应用的 `/f` 参数。
