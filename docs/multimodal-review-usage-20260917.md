# 通用视觉审校使用与接口说明

2026-09-17。本轮增加“已有 OCR 结果 + 原图”的第二轮视觉审校：本地模型提出保留、修改或存疑建议，用户在原图旁逐条处理。处理记录、修订历史和输出来源关联保存。

本轮应用包目录为 `D:/OCR-multimodal-workbench-20260917/bundle`，通过包内 `启动工作台.cmd` 启动。默认审校配置为 `qwen35-4b-q4`，对应 **Qwen3.5-4B · Q4_K_M**。Qwen3.6 官方型号、稀疏激活参数与完整权重的区别、固定资源来源见[模型核验与离线配置](multimodal-models-20260917.md)。

当前仍有跨结果复核跳转、带来源结果复制为 ZIP 乱码等未修复缺陷，具体触发条件及其他已知问题见 [2026-09-17 最新功能审计](../audit/deep-review-20260917/REPORT.md)。

## 在工作台使用

1. 完成现有 OCR 识别，采用需要继续校对的结果，并切到该结果对应的图像版本。
2. 在文字编辑区选中一段文字，或在表格编辑区选中一个逻辑单元格，进入“视觉审校”。直接点击“视觉审校”标签也可打开本页记录。
3. 选择可用模型，点击“复核选中内容”或“复核本页”。提交会先保存当前编辑内容，再按当时的修订生成任务快照。
4. 在“审校任务”查看进度。完成后，对照“审校时的原文”“模型建议文字”和原图处理建议。
5. 需要核对记录时，选择 Excel、Markdown 或 JSON，点击“导出校验清单”。

视觉审校与已有 OCR 共用持久化 GPU 队列。开始审校前会释放当前 OCR 模型，审校会话结束后关闭模型进程。模型不会绕开队列在后台直接改写结果。

### 局部与本页范围

“复核选中内容”支持文字片段和已有逻辑单元格。合并单元格按其左上角逻辑坐标定位，修改作用于整个合并格的文字。

“复核本页”覆盖表格源码之外的现有文字段，以及已保存表格中的逻辑单元格。程序不会把 HTML／Markdown 表格源码再作为普通正文重复提交。表格标题 `caption`、缺失整表、跨页结构关系和版面完整性不属于当前目标集合；本页任务完成不表示这些内容已经检查。

有可靠定位时，模型获得页面上下文和带目标编号的局部图。现有证据可能表示文字范围、单元格或整表区域，界面保留其来源说明。没有可靠框、定位已过期或坐标不匹配时，使用全图；程序不会通过均分表格猜测单元格框。

每个任务最多 256 个目标、单目标最多 4000 字符、合计最多 40000 字符。超过范围会提示缩小目标，不会静默遗漏其余目标。页面含尚未绑定的表格源码时，可先整理表格或选择局部文字。实际模型批次、图片像素和输出预算由包内锁定配置控制。

## 处理建议、撤销与过期

| 模型意见 | 可执行操作 | 对已采用内容的影响 |
|---|---|---|
| 建议修改 | 采用这条修改、拒绝此建议、人工标记存疑 | 只有“采用这条修改”按完整字符串替换对应目标 |
| 建议保留 | 记录保留原文、拒绝此建议、人工标记存疑 | 保留内容，记录人工决定 |
| 模型存疑 | 拒绝此建议、人工标记存疑 | 不提供可直接采用的修改；可回普通编辑器校对 |

每条人工决定都写入修订历史，包括没有改变文字的保留、拒绝和存疑。可使用已有撤销／重做功能。任何决定均不会把页面自动标为“人工已确认”；原有整页确认流程继续独立工作。

同一任务内，程序会保留能够确定仍对应原目标的其他建议：文字修改后，互不重叠的文字位置按实际长度变化移动；单元格修改后，其他格仍需逐字匹配才能继续处理。原始目标、原值与模型响应保持不变，当前位置及变更记录另存。

以下情况会使旧建议失效：普通编辑器另行保存、撤销或重做、切换采用结果、切换图像版本，或图像版本内容变化。采用一轮建议也会使其他审校任务的旧快照失效。过期建议仍保留在记录中，但不能再采用；根据当前内容发起新任务即可。切回旧版本或旧采用结果不会使旧建议重新生效。

## 取消、重试与重启恢复

等待和运行中的任务可以取消。失败或已取消的任务，在其内容和图像快照仍有效时可以重试。应用重启后，未完成任务显示为暂停或中断，使用“恢复任务”继续。恢复沿用原任务及配置快照；已过期任务需要重新提交。

模型未返回全部目标、返回未知或重复目标、JSON 无效、输出截断或任务取消时，不会产生一组伪装成功的建议。推理期间发生内容修改，晚到的响应也不能覆盖当前结果。

“重试上次请求”用于核实没有收到完成响应的提交。客户端沿用原 `request_id`，服务端校验原请求内容并返回已保存的结果，不重复创建任务或重复采用修改。同一请求编号不能用于另一组内容。

仅校对模式允许查看已有建议、记录人工决定、撤销和导出；新审校与任务重试／恢复需要完整模式。已提交请求的只读重放仍可在仅校对模式或模型资源暂时不可用时返回原任务编号，不会唤醒或启动任务。

## 模型配置与离线运行

`config/multimodal-review.json` 将审校 profile 与四个原 OCR 引擎分开。配置包含基础模型和转换产物的固定 revision、量化、模型／视觉 projector／许可文件、运行时资源的字节数及 SHA256，以及固定提示词和资源预算。

模型列表先检查配置与资源是否存在、大小是否匹配。缺失、未部署或配置损坏的模型显示“不可用”及原因；备用 profile 出错不应隐藏有效的默认模型。开始实际会话时再核验完整资源哈希，文件存在不等同于已经完成完整校验。安装或修复资源后可点击“刷新模型”。

审校服务运行时只使用本机资源和受鉴权保护的本地回环连接，不联网获取模型、依赖或文档。资源准备脚本 `scripts/prepare_multimodal_models.py` 与运行服务分离；具体安装和离线校验命令见[模型配置说明](multimodal-models-20260917.md#资源准备与检查)。配置中存在某个 profile 不表示其权重已部署或已具备实际推理结论。

当前默认模型为 Qwen3.5-4B。本文不把其他参数档、Qwen3.6 混合计算档或另一台 GPU 的能力推断为已经验证的能力；实际部署状态以模型列表及本轮验证记录为准。

## 校验清单与正式输出

模型响应保存在独立的 `multimodal_requests`、`multimodal_proposals` 和 `multimodal_decisions` 中。原始 OCR 的 `results.original` 不被改写，审校模型也不增加原始 OCR 投票。只有明确采用的修改进入 `results.edited` 及编辑历史。

校验清单记录模型意见、人工状态、审校时原值、模型候选、最近关联的目标内容、图像版本、模型配置、任务编号和修订信息。过期条目的“最近关联内容”是当时可验证的快照，不宣称仍等于现在的文字。JSON 另含不可变输入快照、完整模型响应、原始目标／当前位置和逐条变更记录。Excel 将编号、金额及以 `=` 开头的字符串作为文字保存，并读回核对。

普通 TXT、Markdown、JSON、XLSX 导出使用已保存的编辑内容：“当前预览结果”范围使用当前预览，即使该结果尚未采用；“所选图片”或“整个项目”批量范围使用各图片的采用结果。结果存在审校记录时，输出以 ZIP 同时携带 `sources/multimodal-{result_id}.json`；未采用的审校建议只出现在来源记录，不混入正文或表格。PDF 导出的页面来源增加 `multimodal_sources`，沿用既有内容与定位预检，不因产生模型建议就将未采用文字写入 PDF。

导出内容及其审校来源在同一数据库快照中获取，避免并发编辑让正文与来源来自不同修订。成功生成清单或合法 JSON 只说明工程输出完成，不证明转录已经正确。

## 开发接口

接口与现有工作台共用本机访问及鉴权约束，路径前缀为 `/api`。

| 方法与路径 | 行为 |
|---|---|
| `GET /multimodal/models` | 返回 profile 列表、默认模型、可用性和原因 |
| `GET /results/{id}/multimodal` | 返回任务、提案、状态计数及当前修订 |
| `POST /results/{id}/multimodal` | 提交局部／本页审校；幂等返回 `task_id` |
| `POST /results/{id}/multimodal/{proposal_id}/decision` | 记录 `accept`、`reject` 或 `question`，返回编辑器结果形态 |
| `POST /results/{id}/multimodal/tasks/{task_id}/{action}` | `cancel`、`retry`、`resume`；校验任务归属与快照 |
| `GET /results/{id}/multimodal/report?format=xlsx` | 导出 `xlsx`、`md` 或 `json` 校验清单 |

提交示例：

```json
{
  "revision": 0,
  "version_id": "当前图像版本ID",
  "model_id": "qwen35-4b-q4",
  "scope": "target",
  "target": { "kind": "cell", "table": 0, "row": 1, "column": 2 },
  "request_id": "每次新提交生成并在重试时复用的UUID"
}
```

`model_id` 是本地 profile 编号。`scope: "page"` 时不传 `target`；文字目标为 `{"kind":"text","start":0,"end":8}`。所有表、行、列下标从 0 开始；文字区间为左闭右开，按 Unicode 字符计数，而非浏览器字符串的 UTF-16 单元数。包含 emoji 等补充字符时，调用方应转换偏移后提交。

人工决定请求包含 `action`、当前 `revision`、`version_id` 与新的 `request_id`。修改决定只能引用已存在的提案，不能通过该接口传入任意候选字符串。采用当前结果、图像版本、修订和目标值必须同时匹配；存疑提案没有可采用值。

队列复用 `tasks.kind='multimodal'`、`engine='reviewer'`，审校任务自身不生成 OCR `result_id`。项目任务视图以 `review_result_id` 指向被审校结果。输入绑定结果修订／编辑内容指纹、图像版本／SHA256、采用选择、目标集合及模型配置快照。

当前 `visual-review-v3` 的模型原始输出为 `items` 和 `summary`：每个已提交 `target_id` 必须恰好出现一次，条目包含 `target_id`、`reading` 和 `reason`。`reading` 为完整的视觉转录字符串，无法确定时为 `null`；模型不直接选择 `keep/replace` 标签。

运行层校验原始输出，并将 `reading` 与原值按字面比较，规范化为业务条目的 `target_id`、`decision`、完整字符串 `after` 和 `reason`：相同为 `keep`，不同为 `replace`，`null` 为 `uncertain`。`keep/uncertain` 的 `after` 保持原值。运行层保留模型身份、证据和原始响应，业务层再次校验规范化结果后才落库。扩展模型须满足上述原始输出及规范化契约，不依赖行业字段、文件名或已知答案，也不执行模型生成的代码。
