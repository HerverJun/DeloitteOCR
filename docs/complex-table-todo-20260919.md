# 复杂表格专项 TODO · Codex 自主执行版

制定／修订日期：2026-09-19，计划版本 2。起点：当前 0.12.0rc1 源码。状态：已改写为 Codex 可自主执行的计划，专项研发尚未启动。用户要求自主寻找验证数据、连续推进，不以等待用户提供样本或逐阶段批准作为工作方式。

目标：减少财务、审计材料中的错列、合并关系错误、空白格误判、重复金额错配及坐标对应错误，使导出的表格更容易核对和使用。执行顺序为 **专项基线 → 本地结构与对应改进 → API 结构仲裁及财务核对**。

## 给执行 Agent 的工作约定

1. 收到执行指令后直接行动。自行选择公开数据源、采集方式、标注工具、局部实现、实验参数和测试命令；无需用户逐项选择或确认。公开材料不足时继续寻找其他来源，不要求用户先提供业务文档。
2. 三阶段是研究依赖顺序，不是停下来汇报并等批准的关卡。A 阶段数据扩充期间可先做 B01/B02/B07 等不依赖完整新数据的工程工作；进入 C 阶段后，真实凭据缺失不阻挡契约、协议模拟、界面、财务规则和打包。
3. 将“工作能否继续”和“质量能否宣称达标”分开。样本规模不足、真实照片缺少参考标签、无人参与效率试验或没有真实 API Key，只影响对应证据结论；记录缺口，继续完成其余可执行任务。数据来源、测试独立性、凭据和几何／文字保全约束仍须如实遵守。
4. 主动搜索、阅读并下载公开可访问、可用于此研究的材料，在独立构建目录准备依赖与数据；使用现有已验证模型与运行时。默认单 Agent 即可完成，CPU 工具调用可批量并行，GPU 推理串行；不以创建子 Agent 作为前置条件。
5. 同一障碍使用下述重试与替代规则，禁止在一个失效链接、不可用模型或未取得的样本类别上无限等待。每次重试都要有新的依据或方法；已有成功产物经哈希校验可复用。
6. 正常情况下持续执行直到产生实现、验证结果和交付物。只有所有独立路径都已尝试且剩余工作确实需要用户独有信息时，才集中说明一个最小必要问题；不要先停下来询问数据、算法或常规工程选择。
7. 不扩大到购买数据、创建付费账号、未经授权的付费调用、向他人发送消息或上传用户私有材料。缺这类条件时使用公开样本、本地工具及模拟服务继续；已有任务授权范围内的操作无需再次确认。
8. 保留用户已有改动、原始样本、历史封存结果和现有交付包。模型建议的“人工采用”是产品行为，自动化验收可模拟点击，不意味着研发要等待用户回来操作。

## 持续执行、断点恢复与证据目录

机器可读入口：[31 项任务依赖与验收证据](complex-table-agent-tasks-20260919.json)。JSON 描述计划，初始状态均为 `pending`，不代表已经运行。执行时在独立 run 目录记录真实状态，勿把计划文件当运行回执。

默认目录为 `build/complex-tables-<run>/` 和 `audit/complex-tables-<run>/`。`<run>` 使用启动日期与递增编号，已有目录仅在身份和来源哈希一致时续跑，否则新建；不覆盖旧实验。

| 执行文件 | 必需内容 |
| --- | --- |
| `audit/.../progress.json` | 任务 ID、状态、已生成证据路径、依赖、尝试次数、最后错误、下一步命令、工程／质量／真实服务三个独立结论 |
| `audit/.../NEXT.md` | 当前任务、已完成步骤、下一条可执行操作、运行中会话／进程、禁止重跑或覆盖的产物；新会话可直接接续 |
| `audit/.../decisions.md` | 数据源选择、输入路由、参数、失败假设与替代方案及依据，避免恢复后重复探索 |
| `audit/.../gaps.json` | 尚缺证据、已尝试来源／方法、影响的结论、当前替代路径、重新尝试的触发条件；不得仅写“等待用户” |
| `build/.../sources.jsonl` | 成功与失败的数据来源、最终 URL、访问日期、许可／使用范围、哈希、类别、模板组和下载状态 |
| `build/.../dataset/` | 输入清单、参考标签、资格状态、开发／验证／封存分组与曝光记录，原始输入和派生图分别保存 |
| `build/.../runs/` | 每次实验的代码／模型／策略锁、命令、日志、逐项输出、耗时及失败；大文件不混入公开报告 |

执行循环：

1. 读取本计划、任务 JSON、`progress.json` 和 `NEXT.md`；首次执行就创建唯一 run 目录并初始化这两个状态文件，随后核对正在运行的作业，避免重复启动。D01 的状态记录从此贯穿运行，不必等最后阶段才开始。
2. 从依赖产物已满足的任务中选择优先级最高的一项。依赖指可验证的产物，不是全域质量达标；例：数据资格报告已指出照片标签不足，后续仍可在合格输入和工程样本上工作。
3. 每项任务按“复现当前行为 → 最小实现 → 针对性验证 → 保存证据”形成小闭环。长采集／推理按文档或批次落盘，设置超时并支持断点。
4. 主路径遇阻时写 `gaps.json`，立即执行备用路径或另一个可做任务；不用空转等待。异步作业运行期间推进不依赖其结果的工作。
5. 每完成一个任务或发生方向变化，更新进度和下一步。持续向用户提供简短进展，但不把阶段汇报作为结束执行的理由。
6. 每个任务标明 `engineering`、`quality`、`real_service` 结论。`done_with_gaps` 仅表示该任务已有完整的受限交付和缺口说明，不等于质量通过；不能用它掩盖尚未修复的工程错误。
7. 完成工程工作与可执行验收后生成交付和总报告；未满足的质量结论保持 `not_met`／`not_measured`。普通会话无法保证应用退出后继续运行，恢复时按 `NEXT.md` 接续，不重新开工。

状态使用 `pending`、`running`、`done`、`done_with_gaps`。暂时受阻的尝试记录在任务内部，整个计划不因一个证据缺口停止。工程硬约束失败时继续修复该部分，或隔离为未启用实验并验证其不影响可用功能，不把失败实现包装成完成。

## 数据自主探索与不阻塞规则

按以下路线自行探索；这些是来源线索，不是已取得或已核验的数据清单：

| 路线 | 优先探索来源 | 不适用时的下一步 |
| --- | --- | --- |
| 中文财务／审计原始文件 | 政府财政预算／决算、审计机关公开报告、发行人及交易所公开年报附表 | 切换机构、发行人或年份；检查模板近重复，避免只增加同模板样本 |
| 可独立评测的结构标签 | PubTables-1M、FinTabNet、PubTabNet、SciTSR 等项目官方数据与许可说明 | 选择有完整来源和所需标签的子集；缺中文或目标类别时仅作对应类别的补充 |
| 真实扫描／拍照复杂表格 | WTW 等官方数据集、公开文档图像资料及明确说明采集过程的研究项目 | 缺转录／跨度标签则用于检测与工程测试；另外寻找可核验标签，不推断成完整结构真值 |
| 仓库测试及旧实验样本 | 当前脚本、历史公开 PDF、已冻结候选、上游 regression fixtures | 用于启动、机制回归和失败复现，明确为已曝光材料 |
| 合成／变换案例 | 基于明确网格生成合并格、重复金额、空白、旋转和预算边缘案例 | 用于坐标、不变量与交互验证；单列结果，不充抵真实扫描／照片或新测试规模 |

Agent 可以自行增加候选来源和更有效的采集工具；无需用户挑网站。优先抽取小批次验证页面、标签和许可，再下载所需子集，不先整库搬运。用户业务样本只作为之后的补充，不是当前路线的前提。

参考标签按证据等级记录：`official_verified`（官方标签及适用性已核验）、`agent_audited`（由 Agent 对原图核对并通过结构检查）、`weak`（仅模型／启发式候选）、`unlabelled`。单独报告官方可核验轨与 Agent 标注探索轨；弱标签不进入独立准确率主指标。Agent 核图、规则一致性和第二工具交叉检查不能冒称人工签核或与模型无关的独立真值。不存在要求用户完成标注复核的前置步骤。

| 遇到的情况 | Agent 必须采取的动作 | 保留的结论边界 |
| --- | --- | --- |
| 链接失效、限流、需登录 | 每个来源最多 3 次有区别的尝试；尊重限流等待提示，转官方镜像／其他公开来源，同时继续别的任务 | 记录失败，不绕过访问限制 |
| 初轮数据搜索迟迟不完整 | 初次探索最多 90 分钟；以约 5 份新文档／10 张表为启动目标，达到部分可用就先跑；扩充另起批次，每批最多 30 分钟 | 启动目标也不是硬门槛；不足时先做现有样本回归与 B01/B02/B07，缺数据类别不宣称达标 |
| 缺独立标签或真实照片 | 自主核图建立 Agent 标注探索集，继续找官方参考；已有样本上实现与验证工程契约 | 不把弱标签、渲染图当真实独立验收；只限制对应质量结论 |
| 没有用户参加效率测试 | 完成真实交互流程、操作计数及自动化回归，记录可复现的界面证据 | 人工节省时间标为未测，不等待用户操作 |
| 某模型／依赖不可用 | 优先修复独立运行时，最多两条合理兼容路径；仍失败则用可用提供方和冻结原始候选推进适配／重放 | 该模型真实推理未验证，不能把重放算新推理 |
| GPU 被占用或显存不足 | 保持现有 GPU 锁，转 CPU 匹配、标注、协议与界面任务；不终止他人进程 | 在后续就绪检查时恢复 GPU 批次，不忙等 |
| 单次实验未提升或引入错位 | 每个机制先做一个基线及最多 3 个有明确假设的变体；无收益就保留负结果、隔离候选并推进下一机制 | 不降低验收门槛、不循环调测试集，也不因一项负结果停止全部开发 |
| 未达到 100 文档等正式规模 | 输出规模和类别缺口，继续开发／验证、工程回归和实验交付；新来源可用后再扩充 | 正式质量与默认启用资格未通过，规模目标不得悄悄下调 |
| 没有真实 API 连接／调用授权 | 完成两协议本地模拟、结构契约、队列、界面、财务规则和导出；有已授权可用连接时再执行对应真实测试 | 真实服务质量标为未测，不索要 Key 才继续其余工作 |
| 封存集被开发过程曝光 | 自动转入开发／回归记录，从未曝光组补充或建立下一封存批次 | 若已无法保持独立性，明确报告；不靠改名恢复“新测试”身份 |
| 一个自动检查持续失败 | 定位原因、修复并重跑受影响检查；外部条件相关则隔离条件并运行剩余检查 | 不跳过产品数据保全／几何校验失败后声称工程通过 |

90／30 分钟限制约束一次探索，不限制整个任务的持续推进；批次结束立即换成可产生成果的工作，之后只因出现新来源或新证据再开启探索批次。网络下载采用有界连接／读取超时和断点文件；生成式 API 请求仍不自动重发。

## 阶段一：建立复杂表格专项基线

执行完成标志：产生可追溯来源、标签资格、分组划分、可复现基线和失败分类。独立标签或正式规模不足时交付明确的受限基线与缺口记录，继续阶段二；完整新数据质量验收资格另行记录。

- [ ] **A01｜盘点现有实现和历史曝光数据。** 清点提供方、对应策略、模型／依赖版本、导出行为、人工绑定规则及历史数据清单；列出本轮复用接口和当前缺口。所有历史测试材料加入排除清单，可用于回归，不充当新留出验收。
- [ ] **A02｜自主建立真实材料目录。** 按上述探索路线自行搜索、下载和筛选中文财务报表、审计报告附表及同类公开材料，逐批覆盖原生 PDF、真实扫描、真实照片、单表／多表、有线／无线表、多层表头、跨行／跨列合并、空白、重复金额、长表及宽表。记录来源、页码、文件与图像哈希、输入类别、模板组和使用范围；来源不明标为未确认。第一批有可用目录或明确搜索回执即可推进，不等待用户供样。
- [ ] **A03｜按文档和模板分组划分。** 同一文档的页面、同模板不同年度、裁剪／旋转／渲染／拍照变体归入同组；检查文件、图像、文字及布局近重复，防止跨开发／验证／测试泄漏。从第一批可用材料建立分组，逐步扩充至约 30 份开发文档及后续验证／封存材料；数量不阻止建立数据管线。冻结分组规则后新材料按同一规则分配，优先保留本地与 API 两个未曝光验收组。
- [ ] **A04｜冻结标注契约。** 标注表区域、行列槽位、单元格 ID、跨行／跨列范围、原文字面值、表头关系、真实空白、文字范围与完整格范围；标记不可辨、边界争议和续表。保存页面到裁剪的坐标变换，不用文字紧框代替完整格，也不按待测模型预测反推参考身份。
- [ ] **A05｜由 Agent 完成标签核验。** 自主检查官方标签及原图，或使用本地标注工具和原图核对建立 Agent 标注探索集；检查网格覆盖、重叠、跨度和坐标一致性，重点核对合并格、空白、重复金额、符号及单位。按证据等级记录，官方参考主轨和 Agent 标注探索轨分别计分；无人工签核就明确写无人工签核。封存组只自动检查资格与一致性，不向开发上下文输出逐项标签；需要 Agent 查看原图／标签诊断的条目转入开发并登记曝光。争议项按冻结规则处理，不因模型失败删样本，不要求用户回来做标注才能继续。
- [ ] **A06｜自主锁定评测协议及正式规模目标。** 沿用至少 100 份独立文档、120 张表、6,000 个目标格的正式验收目标，记录模板组数量。新增分组目标见下表；Agent 在看到封存结果前自行选定明确的新增指标定义与阈值并记录依据，无需等待用户确定。区分工程回归、探索评测和正式质量验收资格；缺真实扫描／照片或数量不足只限制对应结论，不用渲染图充抵，也不停止研发。
- [ ] **A07｜建立同输入基线。** 在开发／验证集比较默认 Paddle＋local-v2、TableFormer raw＋local-v2／v3，以及适用输入上的 PDF 工具；留出集的基线与新策略到冻结验收时一起运行。主轨固定实际采用规则，不按样本选择最优 OCR；另设参考结构控制轨诊断对应器。分别报告表格裁剪和整页流程，未检出的表、未关联的格、超时与推理失败全部计入各自主轨分母。
- [ ] **A08｜完成失败归因与冻结回执。** 按表检测、文字遗漏、采用结构／跨度、token 归属、局部对应、几何边界、歧义和预算超时拆分主要失败原因；辅助原因另列，避免重复计数。保存模型、代码、参数、输入、采用规则和产物哈希，输出下一阶段按收益排序的开发任务。

新增分组规模是正式效果验收的设计目标，不是自主研发的启动或继续条件。分组可重叠，集中于少数模板的样本不能替代文档多样性；达不到时保留目标、如实报告缺口，不无限等待也不悄悄降低标准。

| 分组 | 建议的新测试最低覆盖 | 补充要求 |
| --- | --- | --- |
| 合并格 | 200 格，来自至少 20 份文档 | 跨行、跨列、多层表头分别统计 |
| 空白格 | 200 格，来自至少 20 份文档 | 区分真实空白、漏识别和不可辨 |
| 重复值／重复金额 | 500 格，来自至少 20 份文档 | 包含同排、同列及局部完全对称案例 |
| 原生 PDF／真实扫描／真实照片 | 每类至少 20 份文档 | 中文财务／审计类别与输入类别交叉统计 |
| 大表／宽表及整页多表 | 各至少 20 张表或页面 | 规模定义按格数、token 数等在推理前冻结 |

**阶段交付：** 数据来源清单、标注契约与复核记录、分组及排除清单、评测协议、基线报告、失败分类报告、冻结回执。

**自动推进规则：** A01/A04/A06 的盘点和契约产物就绪即可启动 B01/B02/B07；其余算法任务在小规模或明确限定范围的基线可复算后推进，不等正式数据全部齐备。若初轮新材料不足，A07/A08 先输出历史回归诊断和缺口，继续工程实现，并在后续新增合格数据上补跑。开发只查看开发／验证案例；候选冻结前不查看封存逐项错误。

## 阶段二：本地结构与对应改进

执行完成标志：在现有结构复核中生成可校验、可解释、可撤销的改进建议，完成工程回归、同输入对照及可执行的独立验收；正式验收缺口有明确记录，不阻挡下一阶段工程。

- [ ] **B01｜统一结构候选与证据语义。** 补齐现有候选中的原始格 ID、槽位、跨度、文字 ID、完整格几何和坐标来源。原生 PDF 使用原生文字／矢量线及现有工具；扫描／照片使用检测和结构模型。路由规则在开发集确定，保留全部来源，不逐样本凭参考答案挑选提供方。
- [ ] **B02｜先约束大表最坏成本。** 在现有 200ms 对应预算内，通过行列／空间索引、候选裁剪、锚点缓存和可靠区域分块减少搜索。保留已完成全部约束校验的独立局部结果；剩余区域超时则明确降级。测试候选输入顺序、不同表规模和预算边缘情况，不能把不完整的全局冲突检查当作通过。
- [ ] **B03｜增强合并／拆分候选。** 根据有来源的结构骨架、边线、跨度和邻居证据生成有限候选；优先修复合并表头和跨行标签。检查网格覆盖、矩形跨度、重叠、文字保全及人工修订冲突。允许多个完整文字片段归入一个合并格，不凭字符串长度拆出虚假文字框。
- [ ] **B04｜增强重复金额对应。** 使用独立文字 ID、空间位置、行列顺序、双侧邻居和表头关系进行受约束匹配。约束一个文字片段不能重复归属；同值金额必须有独立位置证据。无法消除的对称歧义继续保留，不用猜测填满覆盖。
- [ ] **B05｜区分空白、缺失和不可辨。** 基于网格、图像及文字证据判断槽位状态；空白不作为新增文字锚点。疑似漏字进入独立取证／局部 OCR 建议，仍复用现有识别引擎。新增文字与纯结构收益分开统计，不能把局部重识别悄悄混入固定文字对照。
- [ ] **B06｜改善缺锚点区域和坐标对应。** 结合可靠邻域与结构约束建立局部身份；文字范围、整格范围和组区域分别展示。多表不共享身份锚点，裁剪／旋转／透视后的证据须绑定正确图像版本；不把一个合并大框重复当成多个精确子格框。
- [ ] **B07｜增强现有结构复核界面。** 展示原图、当前结构、建议结构及局部差异，明确涉及的行列、合并关系、空白状态与未归属文字。复用人工采用／拒绝／撤销入口；对金额、整列移动和已有人工修改冲突给出清楚的影响范围。
- [ ] **B08｜补齐状态与导出一致性。** 结构采用后重算受影响定位，更新候选缓存和文字／几何关联；人工绑定优先，旧修订与迟到任务不能覆盖当前内容。验证重开项目、撤销／重做及 XLSX 的行列、合并范围、长编号和字面值；PDF 仍遵守定位预检与文字层约束。
- [ ] **B09｜做消融和失分审计。** 在同一 OCR／候选上分别启用合并格、重复值、空白及成本优化，记录新增正确、失去正确、新增错位和耗时。先判断候选是否足够：缺候选则改候选，候选足够则改对应；不同时改模型、提示词和阈值后笼统归因。
- [ ] **B10｜冻结并执行可用的独立验收。** Agent 根据验证结果自行选择候选，锁定代码、模型、参数和路由，再执行合格封存测试。输出分组、区间、工程回归和适用范围；数据资格或效果不足时记录 `not_measured`／`not_met`，保持实验状态并继续阶段三，不能等待用户批准才推进。任何已查看测试错误的材料转为后续开发／回归资料。

**阶段交付：** 本地改进代码及版本化策略、失败诊断、结构复核界面、缓存／导出兼容测试、消融报告、冻结测试报告与默认／实验范围说明。

**自动进入阶段三：** 本地方案形成可复现的工程验证及受限或完整的效果报告后，从开发／验证材料和冻结历史失败中确定 API 触发范围。正式测试规模未满足或某个局部算法无收益不阻止 C 阶段；未通过工程硬约束的实现先修复或隔离，未达生产质量指标的策略保持实验状态。

## 阶段三：API 结构仲裁和财务核对

执行完成标志：在用户发起的复核中，对本地仍无法确定的结构提供有限、可验证建议，完成模拟协议与产品工程验证。相对本地方案的真实净收益单独评测；缺真实连接时此结论保持未测，研发与交付继续。

- [ ] **C01｜冻结触发范围和预算。** 从开发／验证集的剩余问题确定触发规则，例如合并候选冲突、重复金额归属或未解决的表头关系。限制单表调用次数、图片像素、目标数量和耗时。仍使用现有单连接，不增加供应商管理或复杂配置；启动和读取项目不触发外部调用。
- [ ] **C02｜新增结构审校结果契约。** 第一版以候选排序／选择、有限合并／拆分建议或弃权为主，引用现有候选 ID 和文字 ID。结构结果与文字纠错结果分别校验；模型不自由重写整表，不生成没有原图依据的坐标或金额。
- [ ] **C03｜构建正确的结构证据输入。** 提供整表上下文、可靠的局部裁剪、候选编号、行列／跨度和固定文字池；无可靠框时提供带说明的行带或整表视图。核对发送图像、目标、裁剪坐标和哈希，不以待判定结构自身作为唯一取证依据。
- [ ] **C04｜接入已有外部网络队列。** 复用 OpenAI／Anthropic 传输、DPAPI 和配置版本；区分文字与结构任务类型，快照增加结构、文字池和候选哈希。延续取消、超时、无自动重发、配置变更要求重新提交、迟到响应丢弃及项目清理规则。
- [ ] **C05｜实现结构硬校验和人工采用。** 校验候选存在、引用完整、无重复归属、无不明文字丢失、跨度合法、网格不重叠、图像及修订未过期。建议进入现有结构复核；不合法、拒绝、截断或证据不足时保留当前结果，不发布可采用修改。
- [ ] **C06｜增加财务一致性疑点。** 先支持明确的合计／小计、年度列、金额单位、小数位、负数括号、百分比与编号等检查。金额计算用十进制定点语义，区分币种、单位、舍入、破折号和真实空白；关系、单位或范围不明确时标记不确定。输出疑点位置、原值、关系和差额，不为凑平算式改写原文。
- [ ] **C07｜完成协议与产品回归。** 模拟两种协议，验证正确图片送达、候选 ID、非法跨度、重复 token、无效 JSON、限流、超时及取消；验证 API 与本地 OCR 并行、人工采用／撤销／导出，检查凭据不会进入快照、日志和报告。
- [ ] **C08｜比较净收益和记录真实服务状态。** 有已授权可用连接时，在公开合格材料上比较“本地方案”与“本地＋API”，同时报告触发目标和全量目标，包含原本正确内容及预先固定的随机检查。记录纠正、改坏、漏检、弃权、调用用量／耗时和操作数量；不逐案例选择外部模型。无连接时完成计量管线及模拟端到端验收，写明真实净收益未测，继续 C09/D；不等待用户填写 Key。无人参加效率试验时只记录脚本操作数，不声称实际人工省时。
- [ ] **C09｜执行最终验收并界定缺口。** 使用阶段一预留的第二封存组或自主补充的新组；阶段二已经用于开发诊断的材料不复用为新测试。冻结模型标识、提示词、触发策略和参数，真实调用时保存脱敏服务身份及返回版本。真实连接或合格新样本不足时，输出已完成检查、未测指标、已尝试路线与可复现补验命令，不伪造证据，也不阻止其余工程交付。

**阶段交付：** 结构审校契约、API 仲裁实现、财务疑点检查、现有界面集成、调用与质量对照报告、真实服务验收记录或明确的未验收说明。

## 验收指标与推进规则

沿用现有 `geometry-evaluation-v3.json` 的定义作为起点。新增指标的分母、允许误差、统计方法和门槛须在阶段一冻结，不能看过封存测试结果后调整。

| 指标 | 口径与验收方向 |
| --- | --- |
| 完整格正确定位覆盖 | C/N；N 包含缺输出、失败与未关联目标。既有默认启用目标为 ≥90% |
| 错位率、提供框达标率 | W/A ≤1%、C/A ≥95%；同时列出含额外／重复输出的严格质量口径，不只统计成功框 |
| 合并关系正确率 | 匹配目标身份和跨行／跨列范围，分别报告漏合并、误合并、误拆分；与几何 IoU 指标分开 |
| 行列归属及文字保全 | 单列错行／错列、遗漏、额外输出和重复分配；不能以文字相同掩盖归属错误 |
| 空白与重复金额分组 | 单列覆盖、误判和错位，分组不能被总体均值掩盖；样本不足只报告探索结果 |
| 整表可用率 | 预先定义“一张表结构与关键值全部符合参考”的严格标准，与普通格平均分同时报告 |
| 人工修改量 | 在固定任务范围记录采用、修正、撤销次数及真实操作用时；脚本点击耗时不冒充人工效率 |
| 性能与资源 | 对应阶段 P95 ≤200ms，并报告超时格数、最坏成本、大表分组；另外记录端到端时延、显存和 API 调用成本／用量 |
| API 净收益 | 同输入比较纠正与改坏，按文档／模板组计算区间；不能仅报告触发区域中的成功案例 |

总体指标和合并格等高风险分组均需达到预先冻结的验收要求，才考虑在已验证输入类别中默认启用。历史 90% 目标是定位覆盖门槛，不是已实现效果，也不是所有新增结构指标的通用阈值。

实现完成、实验有效、效果达标分别记录。扩大自动采用范围不属于本计划；低于门槛的功能可作为明确标识的实验选项交付。
