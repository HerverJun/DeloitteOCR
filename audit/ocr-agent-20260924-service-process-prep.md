## 2026-09-24 receipt and lifecycle correction (static/fake-process only)

Review found that `Audit.save()` recreated the parent's `metrics` map on every call. The cleanup path saved child UI histograms before `shutdown`, then closed the bridge and saved again, erasing `mixed_two_ui:ui_progress` and `soak:ui_progress` from the final JSON. A missing histogram could therefore evade the p95 assessment. The parent now caches every child histogram and includes the cache in every save, including the post-shutdown and publishing-error saves. When a child key overlaps a parent key (such as `warmup_on:api`), the parent loopback histogram keeps its original key, the child gets a `service:` prefix, and the assessor excludes prefixed service histograms from its client API p95. The independent-process assessor requires positive sample counts at both `mixed_two_ui:ui_progress` and `soak:ui_progress`; absence makes functional qualification false and is listed in `missing_ui_progress_samples`. The original in-process path keeps its old sample criterion.

Bridge request bounds are now operation-specific: start 600 seconds for application/model setup, stop 120 seconds for queue/adapter closure, shutdown 60 seconds, other observations 15 seconds. Startup failure after `Popen` and cleanup failures in configure/state capture/stop/shutdown/wait mark the receipt failed and still reach a bounded terminate/kill/reap fallback for the spawned child and its descendants. The final JSON records `service_closed: false` if graceful cleanup did not complete. This is a harness correction only; the formal running output, frozen P0, and sealed questions were not accessed.
